# EdgeCtx — ИИ-агент для граничных устройств

ВКР ИТМО «Разработка ИИ-агента для приложений граничного искусственного интеллекта».

Лёгкий агент для одноплатного компьютера (Jetson Nano 4 ГБ) и всё, что нужно, чтобы честно измерить его работу
без железа: эмуляция слабой платы, симулятор датчиков, цифровой двойник робота в Gazebo.

```
 пользователь ──► EdgeCtx на плате (Go, 10–30 МиБ) ──► внешняя LLM (RouterAI; в разработке — заглушка, 0 ₽)
                    │ сам решает, когда будить модель: события, локальные правила, бюджет
                    │ MCP
                    ├── hw-mcp     датчики и приводы Linux (sysfs, GPIO) + шлюз безопасности
                    ├── cam-mcp    детектор движения на плате; кадр — только по запросу
                    └── robot-mcp  робот через ROS 2 / rosbridge
```

**Главная идея: LLM не стоит в контуре реального времени.** Реакция на событие — локально, за миллисекунды.
Модель вызывается редко и по делу. Ключевая метрика ВКР — работа во времени: вызовы LLM, токены, рубли, трафик,
задержки, память и CPU за рабочий день, в том числе при жёстких лимитах.

## Два сценария

**1. Датчики и исполнительные устройства.** Агент видит оборудование через MCP, держит контекст пользователя и
оборудования и будит модель только на значимое: перегрев, протечка, вопрос пользователя. Сравнение — с аналогами
PicoClaw и nanobot на одинаковом «рабочем дне».

**2. Робот лаборатории NeuroChip** — «помахал рукой — поехал». YOLO находит кисть, спайковая сеть распознаёт
нарисованный жест, робот едет. Сделано:
- разбор причин, почему у лаборатории «после 3–4 жестов надо перезагружать»;
- рефлекс «жест → движение» без LLM: конец жеста → команда мотору за 0,62–0,72 с, у лаборатории ≈2,5 с;
- узел безопасности — единственный писатель команд скорости: слепой сектор лидара, низкие препятствия и обрывы по камере глубины, IMU, аварийная защёлка;
- запуск через systemd с проверкой готовности и `neurobot doctor`;
- цифровой двойник робота в Gazebo.

## Быстрый старт

Нужны Go 1.27 и Python 3.12 (`uv`). Команды выполняются из корня, проверены на Mac. Linux и WSL2 —
`docs/WINDOWS.md`.

```bash
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -r requirements-dev.txt
export PYTHONDONTWRITEBYTECODE=1

# Go-модули
for m in agent hwmcp cammcp robotmcp sysmon bench/board/cpubench; do (cd "$m" && go test ./...) || break; done

# Python: стенд, монитор, статистика, аналоги
.venv/bin/python -m pytest -q -p no:cacheprovider bench/tests monitor/tests harness/tests
.venv/bin/python -m pytest -q -p no:cacheprovider bench/baselines/tests

# Смоук датчиков без платы и ключа (заглушка LLM), несколько секунд
.venv/bin/python -m bench.sensors --out /tmp/sensor-smoke
```

Эмуляция платы, датчики на `gpio-sim`, цифровой двойник робота — в README соответствующих каталогов. Нужен Linux
с ROS 2 Jazzy и Gazebo Harmonic: на Mac — ВМ Lima, на Windows — WSL2.

## Что проверено, а что нет

- **Проверено виртуально:**
  - тесты всех модулей;
  - сквозные тесты агента с MCP-серверами;
  - эмуляция слабой платы («задано против измерено»);
  - датчики через настоящий GPIO uAPI ядра (`gpio-sim`);
  - работа агента под 64 МиБ / 25 % CPU / сетью 3G;
  - цифровой двойник робота: датчики 10/10, 0 касаний в 18 сценариях безопасности из 21, бюджет Jetson 4 ГБ.
- **Не проверено на железе:** плата, датчики, камера, робот, реальная LLM. Все числа — **ориентир, не результат**.
  Результат ВКР — прогоны по протоколу на плате с реальной моделью.

## Правила

- Числа со стенда помечаются как ориентир; разделяется «реализовано / проверено (чем) / не проверено на железе».
- Готовое не выдаётся за своё: Linux (cgroup v2, netem, gpio-sim), systemd, ROS 2, Gazebo, MCP SDK, PicoClaw, YOLO,
  snnTorch, код лаборатории.
- Ключи API и токены не хранятся в репозитории. Деньги на LLM пока не тратятся.
