# Источник жестов и измерения стенда neurobot (этап Э1)

Срез: 15.10.2026. Основание — `docs/neurobot/PLAN.md` §3, §6 (источник (a)), §7 (Э1); `ANALYSIS.md` G1–G6, L1, L4,
R1, R2, S1, K6, K7, §5.2; `research/R1_demo.md` §3, §5–7; `research/R6_sim.md` §3, §4.1, §6–7;
`research/R7_robot_slides.md` §3.2–3.4, §4 (RS2, RS4–RS6). Где R7 расходится с PLAN, компонент следует R7 (§11).

Компонент даёт стенду пять вещей:
- **gesturegen** — детерминированный по seed поток боксов руки (таймлайн) и истину по сегментам;
- **FakeYolo** — подставной детектор руки с интерфейсом модели torch.hub YOLOv5, как её использует
  `predict_live.py` лаборатории; отдаёт бокс таймлайна в момент захвата кадра;
- **подставной `pyrealsense2`** — кадры с темпом детекции и инъекция отказов камеры;
- **наблюдатель** — узел ROS 2, который пишет события и разбирает каждый жест: t0 → t_rec → t_pub → t_cmd →
  t_motion, верная или неверная реакция, ложные действия, «едет без свежей команды», глухота, касание препятствия;
- **shapeclass** — таблица «форма → класс» настоящей сетью лаборатории на выходе gesturegen (R7b §4.6).

Чего здесь нет: распознавателя и писателя `/cmd_vel` (это perception v2 и страж — другие компоненты), Gazebo и
`stm32_sim` (стенд `neurobot/sim/stand/`). Готовые компоненты — ROS 2, Gazebo, YOLOv5, PyTorch, snnTorch,
librealsense — не наши; FakeYolo и подставной `pyrealsense2` только повторяют их интерфейс. SNN, её веса и
предобработка, которыми пользуется shapeclass, — код лаборатории.

**Честность чисел.** Формы классов — гипотезы (зондирование весов и слайд 12), а боксы — синтетика. Поэтому
точность распознавания на стенде ничего не доказывает. Задержки стенда — **ориентир**. **Результат** прогона —
структурные счётчики: ложные действия, эпизоды «едет без свежей команды», глухие интервалы, касания.

## 1. Схема

```
gesturegen ──► timeline.jsonl ──► FakeYolo ◄── кадр с меткой времени захвата ◄── подставной pyrealsense2
                                     │              (строка 0, переживает cv2.flip)      ▲ отказы: расписание
               truth.jsonl           │ .xyxy[0]                                          │ от якоря / control
                   │                 ▼                                                   │
                   │      perception v2 ─► /neurobot/gesture ─► исполнитель ─► /neurobot/cmd_vel_req ─► safety_gate
                   │      (демо как есть пишет /cmd_vel сам)                                                 │
                   │                         /diff_cont/cmd_vel_unstamped ◄─ twist_mux ◄─ /cmd_vel ◄─────────┘
                   ▼
               наблюдатель ◄── /cmd_vel, /odom, /ground_truth/pose, /neurobot/gesture, /neurobot/perception_health
                   │
                   ├─ events.jsonl (запись) ──► analyze ──► summary.json, gestures.jsonl
                   └─ anchor.json (t = 0 таймлайна; создаёт первый вызов FakeYolo)

gesturegen ──► shapeclass (ВМ sim: SNN лаборатории, torch) ──► table.json «форма → класс»
```

## 3. gesturegen

```sh
python -m neurobot.sim.gestures.gesturegen gen --seed 1 --gestures 200 --negatives 60 --out-dir DIR
python -m neurobot.sim.gestures.gesturegen info DIR        # сводка истины: классы, стороны, концы, боксы, обрезка
```

`--seed` (1) — зерно, `--gestures` (40) и `--negatives` (12) — число жестов и отрицательных сегментов, `--classes`
(0,1,2,3) — классы жестов (по очереди), `--out-dir` — каталог выхода. Без `--force` существующие файлы не
перезаписываются: код 2 и сообщение в stderr. Ошибка пути — тоже код 2 без трассировки: у `gen` каталог выхода не
создать (нет прав, на пути обычный файл), у `info` файла нет, он пуст или это не истина (например, `timeline.jsonl`).
Неверный параметр — тоже код 2 с именем параметра (например, `dur_s: нужен 0 < min ≤ max`,
`lead_in_s = -3.0: нужно 0 ≤ lead_in_s`). Проверяются все числа: диапазоны
(min, max) и одиночные — по границам (`--det-fps` 1–60, `--rotate-deg` 0–180, `--jitter` и `--size-jitter` 0–1,
`--margin-px` 0–240, `--hold-pre-s`, `--hold-post-s`, `--lead-in-s` ≥ 0; доли `--aspect`, `--p-miss`,
`--passer-p-miss` — в [0; 1): при `--aspect` ≥ 1 форма вырождается или зеркалится); NaN и бесконечность не проходят.

**Классы и формы** (`shapes.py`; источник: R1 — зондирование весов, слайд 12 и GIF — замысел лаборатории, R7b §4).
Класс у форм слайда 12 — замысел оператора, а не ответ сети. Последний столбец — что отвечает настоящая сеть на
полилинии (`shapeclass`, условие `fit_fps10`, §10) [замер, ориентир]:

| Класс | Манёвр демо | Форма | Источник | Сеть на полилинии |
|---|---|---|---|---|
| 0 round | turn180 («Полный оборот») | `circle`, `c_arc`, `oval` | R1 | 0 |
| | | `arc34` — ¾ круга, начало слева сверху, по часовой | слайд 12, GIF-1 | **1** (0,78) |
| 1 angular | come («Вперёд») | `v`, `n`, `two` | R1 | 1 |
| | | `two_m` («зеркальная 2»), `s` | GIF-4 (замысел неизвестен) | 1 (0,82–0,89) — поэтому класс 1 |
| | | `hook`, `hook_m` — вверх, через верх вправо и вниз, оба зеркала | слайд 12 | **0** (0,71–1,0), иногда 3 |
| 2 horizontal | go_left / go_right | `swipe`, `wave` | R1 | 2 |
| | | `swipe_rise` — мах с провалом и подъёмом в конце | слайд 12, GIF-3 | 2 (0,65), иначе 1 |
| 3 vertical | think (на слайде нет) | `down`, `slash`, `beckon` | R1 | 3 |

Для `two` и горизонтальных форм сторона и обращение хода задаются генератором. Координаты боксов даны в кадре так,
как его видит детектор в `predict_live.py`, то есть **после `cv2.flip(·, 1)`** («зеркало»). Сторона `left` означает,
что рука уходит в +x, и демо по первому и последнему боксу выбирает `go_left` (`predict_live.py:322–328`, проверено
тестом). Если perception v2 уберёт зеркалирование, стороны поменяются местами. В чьей системе нарисованы стрелки
слайда 12 (камеры или оператора), неизвестно (RS6): обе стороны генерируются поровну, а конвенция оператора в разборе —
таблица рефлекса с переставленными сторонами (`--maneuvers`: `"2:left": "go_right"`, `"2:right": "go_left"`).

**Геометрия** (R7b §3.4, §4.5):
- камера-обскура с фокусом `--f-px` 616 px [оценка RS4: 640×480 вырезан из 16:9, HFOV ≈ 55°] или 462 px (HFOV
  69,4° полного кадра 16:9 [ист. Intel]); ответ даст `rs-enumerate-devices -c` у лаборатории;
- бокс кисти `--hand-m 0.13,0.18` (ширина, высота; кадр слайда 8 — 185×244 px) [оценка], дистанция
  `--dist-m 0.5,2.5`, размах `--amp-m 0.3,0.6`; пиксели падают как 1/дистанция;
- **вертикаль из высот**: камера на `--cam-h-m 0.66` (мачта телескопическая — параметр), центр кисти на высоте из
  `--hand-h-m 0.8,1.4`, но в поле зрения на этой дистанции (оператор держит руку в кадре); траектория вокруг неё в
  кадр не вписывается и обрезается краями. Детектор видит руку, если в кадре не меньше половины бокса [оценка].
  Доля потерянных у края отсчётов — `cut` (любой край) и `cut_top` (центр выше кадра) в истине и в `info`;
- `--fit` — как до R7: размах уменьшается, пока жест не поместится, место в кадре случайное (`fit` < 1 в истине).

**Время жеста** (R7b §4.3, GIF): рука в кадре 3–7 с, жест кончается кулаком и уходом руки.
- длительность траектории `--dur-s 1,7` (короткие сохранены), рука до начала движения — до `--hold-pre-s 0.3`;
- конец `--end fist,leave` (на выбор поровну): `fist` — 1–3 сжимающихся бокса кулака и обрыв; `leave` — обрыв
  сразу; `hold` — рука стоит до `--hold-post-s 0.3` (как до R7);
- **темп детекции** `--det-fps 10` — шаг сетки таймлайна; подставная камера по умолчанию берёт тот же темп из
  заголовка. Значение 10 к/с — [оценка], диапазон 9–16 к/с, до замера на Jetson.

Остальные вариации: поворот `--rotate-deg 10`, растяжение `--aspect 0.15`, дрожание центра `--jitter 0.03` и размера
`--size-jitter 0.05` (доли бокса), пропуски `--p-miss 0.1`, уверенность `--conf 0.5,0.9`, паузы `--pause-s 12,18`
(дольше манёвра демо 11 с), разгон `--lead-in-s 5`, отступ от края `--margin-px 4`. Все флаги с единицами —
`gen --help`.

**Отрицательные сегменты** (`--neg-kinds`):
- `hand_still` — рука стоит `--still-s 1.5,10` с (GIF-2: неподвижная ладонь 1,5–5 с);
- `passerby` — кисть прохожего на `--passer-dist-m 2,3.5` м со скоростью `--passer-speed 0.8,1.5` м/с пересекает
  кадр, `--passer-p-miss 0.4` пропусков;
- `false_boxes` — ложные боксы в случайных местах, `--false-rate 0.5,3` в секунду, уверенность
  `--false-conf 0.25,0.6` (часть ниже порога 0,35), `--false-s 4,12` с;
- `empty` — пустой кадр `--empty-s 5,15` с.

У отрицательных сегментов `cls = −1`, `t0 = t_leave` — конец сегмента; из геометрии у них только поля их вида:
`dist_m` (hand_still, passerby), `direction` (passerby), `rate_hz` (false_boxes).

**Детерминизм.** Случайность берётся только из `random.Random.random()`: его последовательность по seed Python
гарантирует между версиями. Числа округляются перед записью (`timeline.rnd`, −0.0 → 0.0). Тест сверяет sha256 с
эталоном; эталонный таймлайн совпал побайтно под Python 3.8 и 3.12, на macOS и Linux (ВМ sim).

**Форматы.** Первая строка обоих файлов — `{"header": {version, seed, det_fps, frame, f_px, classes, shapes, note,
duration_s, n_segments, params}}`; у истины есть ещё `timeline_sha256`.
- Таймлайн: `{t, bbox: [x1,y1,x2,y2] | null, conf, seg}`. Это ступенчатая функция: запись действует до следующей,
  `t` — секунды от якоря.
- Истина: `{seg, kind: gesture|negative, cls, name, side, shape, reverse, end, t_start, t0, t_leave, dist_m, h_m,
  amp_px, fit, dur_s, cut, cut_top, n_boxes}`. Здесь `t0` — конец траектории (конец жеста), кулак и уход — после
  него, `t_leave` — последний бокс, `h_m` — высота кисти (null при `--fit`).

**Как до R7** (сравнение со старыми прогонами; байты будут другими — формы и порог видимости новые):
`--fit --f-px 462 --dur-s 0.8,2.0 --end hold --dist-m 0.6,2.5 --hand-m 0.10,0.18 --still-s 3,10` и `--shapes` из
форм R1.

## 4. FakeYolo

Повторяет то, что `predict_live.py` делает с моделью; тест сверяет это по AST их файла:
- `torch.hub.load(…).eval()`;
- атрибуты `max_det`, `conf`, `iou`;
- `.to(device)`, `.half()`;
- вызов `model(color_image, size=320)`;
- результат `.xyxy[0]` — строки `x1, y1, x2, y2, conf, cls`.

Как в YOLOv5, бокс с conf ≤ `model.conf` отбрасывается, `max_det` ограничивает число боксов, `classes` фильтрует
класс. `.xyxy[0]` — это `torch.Tensor`, если torch импортируется, иначе `numpy` N×6 (`NEUROBOT_FAKEYOLO_TENSOR`).

Какой бокс отдаётся:
- время берётся из **метки кадра** — момента захвата в подставной камере;
- замороженный кадр несёт старое время и даёт старый бокс;
- чёрный кадр детекций не даёт;
- в кадре без метки (чужой источник или изменённый размер) используется «сейчас», а счётчик `marker_miss` растёт.

| Переменная окружения | По умолчанию | Смысл |
|---|---|---|
| `NEUROBOT_GESTURES_TIMELINE` | — (обязательна) | `timeline.jsonl` |
| `NEUROBOT_GESTURES_ANCHOR` | — (обязательна) | файл якоря, **свой на каждый прогон** |
| `NEUROBOT_FAKEYOLO_LATENCY_MS` | 0 | имитация времени инференса |
| `NEUROBOT_FAKEYOLO_TENSOR` | auto | auto / numpy / torch |

**Якорь** (`clock.py`) — момент t = 0 таймлайна, файл `{t_wall, t_mono, timeline_sha256, pid, boot_id}`.
- Его атомарно создаёт первый вызов детектора. У perception v2 это прогревочный чёрный кадр.
- Перезапущенный процесс читает тот же якорь: мир с жестами идёт дальше, а жесты, пришедшиеся на простой, теряются.
- Ошибка (RuntimeError при первом вызове детектора): якорь другого таймлайна и якорь из другой загрузки ОС
  (`boot_id` ядра Linux; на macOS — смещение `t_wall − t_mono`, допуск 60 с).
- Якорь того же таймлайна, но старше его конца (файл от прошлого прогона) — предупреждение в stderr и событие
  `anchor_stale` в журнале probe: детектор ничего не увидит.
- Офлайн-разбор загрузку не сверяет (`read_anchor(live=False)`): его можно запускать после перезагрузки ВМ и на Mac.

Демо как есть (A0): обвязка подменяет `torch.hub.load` на `neurobot.sim.gestures.fakeyolo.hub_load`. У perception v2
есть флаг `--yolo fake --fake-yolo neurobot.sim.gestures.fakeyolo:FakeYolo.from_env`.

## 5. Подставной pyrealsense2

Чтобы заглушка заслонила настоящий модуль, нужен `PYTHONPATH=<корень>:<корень>/neurobot/sim/gestures/shim`.
Есть имена, которые использует `predict_live.py` (проверено по AST):
- `pipeline`, `config`, `stream`, `format`, `camera_info.name`, `option`;
- `enable_stream`, `start`, `stop`, `get_active_profile`, `get_device`, `sensors`, `get_info`, `set_option`,
  `wait_for_frames`, `get_color_frame`, `get_data`.

Для лесенки восстановления perception v2 есть ещё `try_wait_for_frames`, `context().query_devices()`,
`hardware_reset`; для тестов — `get_frame_number`, `get_timestamp`, `get_width/get_height`, `get_option`,
`configure(…)` (явная настройка). Сообщения об ошибках — как у librealsense: `Frame didn't arrive within N`,
`No device connected`, `start() cannot be called before stop()`, `wait_for_frames cannot be called before start()`.

Кадр: W×H по конфигу (в демо 640×480), bgr8 или rgb8, серый фон и метка времени захвата. Номер кадра и последний
кадр — у устройства: рестарт конвейера их не сбрасывает.

Темп — **темп детекции**, а не 30 к/с сенсора. Частота из `enable_stream` игнорируется. Порядок выбора:
`NEUROBOT_FAKE_RS_FPS`, иначе `det_fps` из заголовка таймлайна, иначе 10. Семантика «последний кадр»: медленный
потребитель получает свежий кадр, пропущенные теряются.

| Отказ | Параметры | Поведение |
|---|---|---|
| `delay` | `duration_s` | кадров нет; ожидание дольше таймаута → `RuntimeError("Frame didn't arrive within 5000")` (R1) |
| `stall` | [`duration_s`] | кадров нет до рестарта конвейера (stop + start) |
| `gone` | [`duration_s`] | «зависшее устройство»: рестарт конвейера не помогает, лечит только `hardware_reset()`; после него `NEUROBOT_FAKE_RS_RESET_S` (2,5 с) устройства нет (`No device connected`), затем нужен новый `start()` |
| `freeze` | `duration_s` | камера отдаёт один и тот же кадр (данные, timestamp, номер) **любому** конвейеру процесса, в том числе новому после рестарта |
| `black` | `duration_s` | чёрные кадры без метки |
| `slow` | `duration_s`, `fps` | темп падает до `fps` |

Поле `cure` — чем отказ снимается раньше `duration_s`: `none` (по умолчанию; тогда `duration_s` обязательна),
`restart` — рестарт конвейера после начала отказа, `reset` — `hardware_reset` после начала отказа. У `stall` это
всегда `restart`, у `gone` — `reset`. Например, `{"kind":"freeze","cure":"reset"}` — застывшая камера, которую
лечит только сброс устройства; лесенка perception v2 на ней проходит ступени до `hardware_reset`, а на `freeze`
длиннее лесенки — до `CameraFailed` (проверено тестом с `camera_guard.py`).

Как вносить отказы:
- **По расписанию.** `NEUROBOT_FAKE_RS_FAULTS=faults.json` — JSON-список `{at_s, kind, …}`, где `at_s` — секунды от
  якоря. Поэтому одно расписание ложится на A0 и A1 одинаково и переживает рестарт процесса: отказ, который
  ещё идёт, действует и на новый процесс. До появления якоря расписание не действует; без
  `NEUROBOT_GESTURES_ANCHOR` — ошибка (ValueError) при первом обращении к камере. Якорь другой загрузки ОС —
  ошибка в stderr и событие `anchor_error`, расписание не применяется. Расписание, целиком оставшееся в прошлом,
  ничего не сообщает: после законного рестарта perception это норма, а якорь от прошлого прогона ловит FakeYolo
  того же процесса (`anchor_stale`, §4).
- **По команде во время работы.** Дописать строку в `NEUROBOT_FAKE_RS_CONTROL`:
  `echo '{"kind":"delay","duration_s":7}' >> control.jsonl`. Команда действует с момента прочтения и **только на
  процесс, который её прочитал**. Файл проверяется при каждом ожидании кадра и не реже 10 раз в секунду, пока
  кадров нет. Неверная строка (не JSON, не объект, неизвестный вид или `cure`, не число) отклоняется: ошибка в
  stderr и событие `control_error` в журнале, а камера работает как работала. Файл, ставший короче (перезаписан
  `>` вместо `>>`), читается с начала с предупреждением.
- **Команды и рестарт процесса.** Строки, которые уже были в файле, когда процесс впервые обратился к камере,
  пропускаются: их прочитал прошлый процесс (рестарт после `kill -9`) или они от прошлого прогона. Сколько
  пропущено — событие `control_skipped {lines}` в журнале и строка в stderr. Так рестарт не повторяет старые
  отказы и не портит счётчики глухоты и TTR. Недописанная строка (её пишут в момент старта) будет прочитана.
  Следствие: команда, дописанная, пока процесса нет или он ещё не обратился к камере, не действует; безопасно писать
  после события `pipeline_start` с pid нового процесса. Отказ, который должен пережить рестарт процесса, задаётся
  расписанием.

Ошибки обвязки не выходят из `wait_for_frames`/`start` как отказ камеры: лесенка perception ловит `RuntimeError`, и
опечатка оператора выглядела бы ровно как R1. Исключение — конфигурационные ошибки при старте (`ValueError`).

POSIX-сигнал для команд не используется: он не несёт параметров, а обработчик в Python выполняется только в
главном потоке, который у демо занят `rclpy.spin`.

Состояние устройства живёт в процессе. После рестарта процесса отказ `gone` из расписания снова требует
`hardware_reset` — так воспроизводится «камера занята после аварийного выхода» (R2); `freeze` застывает на первом
кадре нового процесса (один «свежий» кадр после рестарта процесса неизбежен).

**Журнал подставных модулей** `NEUROBOT_FAKES_PROBE=probe.jsonl` (один файл на прогон).
- Раз в секунду пишется `{t, m, pid, frames, det_calls, timeouts, marker_miss, faults}`.
- Отдельно пишутся события: `fault_start/fault_end`, `hardware_reset`, `pipeline_start/stop`, `control`,
  `control_error`, `control_skipped`, `anchor_error` (камера) и `anchor_stale` (FakeYolo).
- Журнал нужен для A0, у которого нет темы здоровья. «Кадры/с = 0 при живом PID» (R1) — это строки журнала идут,
  а `det_calls` не растёт.
- Ошибка записи (нет каталога, кончилось место) — одно сообщение в stderr, журнал выключается; камера и детектор
  работают дальше.

## 6. Наблюдатель

```sh
# в ВМ sim (source scripts/sim/vm_env.sh; PYTHONPATH=<корень>:$PYTHONPATH)
python3 -m neurobot.sim.gestures.observer --out RUN/events.jsonl --truth truth.jsonl --anchor RUN/anchor.json \
    --summary RUN/summary.json --per-gesture RUN/gestures.jsonl --cmd-vel-type twist \
    --extra-cmd /neurobot/cmd_vel_req --extra-cmd /diff_cont/cmd_vel_unstamped \
    --world-sdf neurobot/sim/stand/worlds/lab_wall.sdf --wall-regex 'wall|post|box|neg_' [--probe RUN/probe.jsonl]
python3 -m neurobot.sim.gestures.analyze --events RUN/events.jsonl --truth truth.jsonl --anchor RUN/anchor.json \
    [--probe RUN/probe.jsonl] --out summary.json --per-gesture gestures.jsonl      # тот же разбор офлайн
```

**Цепочка движения** — как на роботе (контракт этапа 15.10, ANALYSIS §5.2): исполнитель → `/neurobot/cmd_vel_req` →
`safety_gate`, единственный писатель `/cmd_vel` → `twist_mux` → `/diff_cont/cmd_vel_unstamped` →
`diff_drive_controller`. Писатель для разбора — `--cmd-topic` (`/cmd_vel`): по нему считаются эпизоды, реакции и
K6. Заявка исполнителя и выход `twist_mux` — дополнительные темы: метки `lat_extra` и счёт сообщений `cmd.msgs`.
Демо как есть (A0) пишет `/cmd_vel` само.

`--probe` — только если у perception задан `NEUROBOT_FAKES_PROBE` (A0); если файла к концу нет, разбор строится
без него с предупреждением.

**Подписки:**

| Тема | Тип | QoS |

| `--truth`, `--anchor` | — | истина и якорь прогона: без них при остановке разбора нет, а `--summary`, `--per-gesture` и `--probe` без них — ошибка (код 2) |

**Коды выхода наблюдателя:** 0 — запись и разбор сделаны; 1 — якоря нет (детектор ни разу не вызван), разбор не
построен; 2 — ошибка параметров до записи (существующий `--out` без `--append`, нет каталога или прав на запись для
`--out`, `--summary` или `--per-gesture`, `--summary`, `--per-gesture` или `--probe` без `--truth` и `--anchor`,
неверный `--maneuvers`, класс истины без строки в рефлексе, нет файла `--truth`, `--walls` или `--world-sdf`, неверное
содержимое препятствий или `--wall-regex`, ни одного препятствия) или разбор после записи не построен или не записан
(истина и якорь от разных таймлайнов, файл прогона не прочитать, сводку не записать — запись при этом цела, разбор
строится офлайн `analyze`); 3 — тип издателей темы скоростей не совпал с подпиской. Сообщение об ошибке — в stderr,
без трассировки.

**Файл записи — один на прогон.** Существующий `--out` — ошибка (код 2); дописать можно только явно `--append`
(рестарт наблюдателя в том же прогоне). Каждый запуск пишет заголовок `{pid, t, m, boot_id, timeline_sha256 истины,
args, walls}` и начинает новую сессию записи; как разбор обходится с перерывом между сессиями — ниже, «Сессии
записи».

**Тип `/cmd_vel`.** Раз в 2 с и при остановке наблюдатель сверяет типы издателей каждой темы скоростей с подпиской
(`get_publishers_info_by_topic`, есть и в Foxy). DDS пару Twist/TwistStamped не соединяет, и без проверки в записи
просто не было бы команд, а всё движение ушло бы в «едет без свежей команды». При расхождении — ошибка в stderr,
событие `cmd_type_mismatch` в записи, `cmd.type_mismatch` в сводке и код выхода 3.

**Проверки при старте**: таблицы `--maneuvers`, покрытие классов истины таблицей рефлекса, препятствия, то, что
`--out`, `--summary` и `--per-gesture` можно записать (каталог есть, путь — не каталог, права на запись есть), и то,
что флаги разбора (`--summary`, `--per-gesture`, `--probe`) заданы вместе с `--truth` и `--anchor` (без них разбора
нет, и флаги молча пропали бы), — ошибка (код 2) до записи, а не после восьмичасового прогона.

**Препятствия и контур.** `--world-sdf` берёт коллизии `box` и вертикальные `cylinder` моделей с именем по
`--wall-regex` (по умолчанию `wall`; все препятствия миров стенда — `'wall|post|box|neg_'`), `--walls` — JSON
`{name, cx, cy, yaw, sx, sy}` или `{name, cx, cy, r}`. Контур робота — `--footprint` (прямоугольник, по умолчанию
TB3 waffle_pi) или `--footprint-radius` (круг; для `--base neurochip` стенда — 0,195). Касание — зазор ≤ `--touch-m`
0,02 м в проекции на пол: высоты не учитываются, поэтому полку и стол из `lab_low` оно считает касанием, когда
контур под ними.

**События** (`record.py`). Каждое несёт `t` (time.time) и `m` (CLOCK_MONOTONIC) момента приёма. Поток сжат:
- `cmd` — серия одинаковых команд; закрывается при смене значения или тишине > 0,25 с;
- `motion` — переходы «едет / стоит» по `odom` и `gt`: |v| > 0,05 м/с или |ω| > 0,1 рад/с;
- `pose` — 2 Гц, с расстоянием до препятствия;
- `wall` — переходы касания;
- `rtf` — окно 10 с;
- `gesture`, `health` — JSON как есть;
- `cmd_type_mismatch` — см. выше.

Журнал узла идёт в stderr; без `--summary` сводка печатается в stdout.

**Разбор** (`analyze.py`). Флаги — общие у `analyze` и наблюдателя; у `analyze` ещё `--events`, `--truth`,
`--anchor` (обязательны), `--probe`, `--out` (по умолчанию stdout) и `--per-gesture`; ошибка (неверные данные, нет
файла) — код 2 и сообщение в stderr без трассировки.

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--cmd-topic` | `/cmd_vel` | тема единственного писателя скоростей |
| `--maneuvers` | таблицы демо | JSON таблиц манёвров и рефлекса (ниже) |
| `--episode-gap-s` | 0,6 с | разрыв серий команд внутри одного эпизода движения |
| `--min-phase-s` | 0,25 с | фаза манёвра короче — переходный тик |
| `--match-window-s` | 10 с | реакция относится к сегменту, если началась не позже t0 + окно |
| `--sla-s` | 3 с | реакция позже t0 + sla — `late`, видимый сбой (PLAN §1) |
| `--stale-s` | 0,5 с | команда свежая столько после последней ненулевой (K6) |
| `--brake-allow-s` | 0,6 с | после явного нуля база встаёт не позже — торможение (K6) |
| `--connect-s` | 2 с | начало сессии записи, пока соединяются подписки: эпизод с первой команды темы мог начаться до сессии, K6 до первой команды писателя и «сообщений нет» не судятся |
| `--health-gap-s` | 3 с | тишина `perception_health` или probe дольше — сообщений нет |
| `--deaf-min-s` | 2 с | `fps = 0` короче — не глухота |
| `--rtf-min` | 0,95 | жесты в окне с RTF ниже не входят в задержки |
| `--dur-tol-abs`, `--dur-tol-rel` | 0,4 с, 0,15 | допуск длительности фазы манёвра: max(abs, rel × длительность) |

- **Свой прогон.** Истина и якорь должны быть от одного таймлайна (`timeline_sha256`), иначе ошибка (код 2). Сессии
  записи (заголовки) чужой загрузки ОС, чужого таймлайна и сессии, целиком закончившиеся до якоря (прошлый прогон в
  том же файле), отбрасываются с предупреждением; сколько — `input` в сводке. Строки probe вне сессий записи
  не учитываются.
- **Сессии записи** (рестарт наблюдателя с `--append`). Сессия — один запуск наблюдателя: от заголовка (его `m`;
  подписки соединяются уже после него) до события `stop`. Между сессиями наблюдения нет, и разбор их не склеивает:
  - трекеры записи начинают сессию с «стоит» и «не касается»; что не закрыто к концу сессии (едет, касание,
    `fps = 0`), закрывается её концом;
  - эпизод движения, который начался с первой команды темы в первые `--connect-s` 2 с сессии, мог начаться до неё
    (`cut: "start"` в разборе по сегментам); эпизод, после последней команды которого сессия длилась меньше
    `--episode-gap-s`, мог продолжиться после неё (`cut: "end"`);
  - эпизод без начала, пришедший не позже t0 сегмента (+0,1 с на порядок сообщений), — продолжение чужого манёвра,
    не новое действие: ни ложное, ни лишнее, ни самопроизвольное, и метки `cmd`, `motion`, `lat_extra` по нему не
    ставятся. Реакция сегмента — его первое действие: хвост чужого манёвра в окне жеста её не заслоняет. Сегмент,
    у которого есть только продолжение, — реакция `unobserved`. Продолжение считается начатым до жеста
    [допущение: реакция начинается после конца жеста, раньше (`early`) — только когда perception разрезал жест];
  - начало реакции видно, если первое действие сегмента — эпизод с началом, а его сессия началась не позже t0.
    Иначе начала не видно, и первое видимое действие может оказаться повтором:
    - t0 пришёлся на перерыв или сессия началась после t0 — реакция могла начаться (или пройти целиком) в
      перерыве, решающее сообщение тоже могло прийти в нём;
    - сессия началась до t0, но первое действие — эпизод без начала после t0: наблюдатель перезапущен меньше чем за
      `--connect-s` до реакции, и она могла начаться, пока подписки соединялись (или быть продолжением).

    Сегмент — `unobserved`: без меток `cmd`, `motion`, `rec`, `pub`, без поля `rec`, `late` и `moved_on_unknown`, в
    матрице ошибок — `unobserved`; видимые действия сегмента всё равно входят в `actions` и `extra_actions`. Метка
    дополнительной темы `lat_extra` — по тому же правилу для эпизодов этой темы в окне сегмента: если начала её
    первого действия не видно, метки нет (видимый эпизод мог быть повтором);
  - эпизод у конца сессии, совпавший с ожидаемым манёвром или его началом, — `unobserved`: чем он кончился, не
    видно; эпизод у конца сессии, уже не похожий на ожидаемый, судится как обычно;
  - сегмент без реакции, окно которого (от начала сегмента, а не от t0: реакция бывает и до конца жеста, — до
    t0 + `--match-window-s` или начала следующего сегмента) не уложилось в одну сессию, — `unobserved`, а не `none`;
    в матрице ошибок — столбец `unobserved`;
  - K6 в первые `--connect-s` сессии до первой команды писателя не судится: команд до сессии не видно, а подписка
    соединяется не сразу (первое событие — через 0,02–1,0 с после заголовка, [замер, ВМ sim, 15.10]). База, которая
    едет без команд писателя и дальше, — K6 `silent` с этого момента. «Не встала до конца записи» — до конца сессии;
  - «сообщений нет» (`health_missing`, `probe_missing`) в сессии судится с начала сессии + `--connect-s`, но не
    раньше первого сообщения темы в прогоне: тишина от этого момента до первого сообщения сессии входит, сессия без
    сообщений — целиком, так что рестарт наблюдателя глухоту perception не прячет. До первого сообщения темы
    perception ещё прогревается (якорь — первый вызов детектора при прогреве, здоровье — после READY: через
    1,1–4,5 с после якоря в 16 записях perception v2 [замер, 14–15.10]), и эта тишина — не глухота, в одной сессии
    и через рестарт наблюдателя. Долгий старт perception этим счётчиком не ловится — он виден по реакциям `none` на
    жесты до первого сообщения. Прогон, где темы нет вовсе (ни одного сообщения: здоровья нет у демо как есть),
    тишины не даёт — это видно по `health_msgs`. Тишина от последнего сообщения до конца сессии входит: если
    perception остановлен раньше наблюдателя, это хвост «сообщений нет» в конце записи — наблюдатель
    останавливают первым;
  - перерыв не входит ни в `health_missing`, `probe_missing`, глухоту и касания, ни во время записи: `duration_s` и
    `k7.hours` — сумма сессий, перерывы — `observer_gaps` {`n`, `total_s`, `max_s`};
  - `moving_without_cmd` — хотя бы в одной сессии база ехала после первых `--connect-s`, а команд писателя в ней
    не было ни одной.
- **Эпизод движения** — ненулевые серии `/cmd_vel` с разрывами ≤ 0,6 с. Он относится к последнему начавшемуся
  сегменту, если начался не позже `t0 + 10 с`. Иначе действие считается самопроизвольным.
- **Решающее сообщение perception** сегмента — последнее до начала эпизода движения (по нему робот поехал), а без
  движения — последнее в сегменте: perception может разрезать длинный жест на несколько сообщений. По нему —
  `rec` в разборе по сегментам, матрица ошибок `recognition.confusion` и метки `rec`, `pub`; число сообщений —
  `n_msgs`. Если начала реакции не видно (перерыв наблюдателя после t0 или реакция в первые `--connect-s` сессии),
  решающего сообщения тоже не видно (выше, «Сессии записи»).
- **Реакция** сверяется с таблицей манёвров демо `predict_live.py:398–454` по рисунку команд (F/B/L/R) и
  длительностям (допуск max(0,4 с; 15 %)):
  - `correct` (для класса без действия — движения не было);
  - `wrong` — другой манёвр, неизвестный рисунок (`unknown:…`), оборванное начало чужого манёвра (`partial:…`) или
    движение там, где надо стоять. Начало, подходящее к нескольким манёврам, называется манёвром, которого
    просило решающее сообщение (класс по таблице рефлекса), а без такого — всеми через «|»
    (`partial:go_right|think|turn180`);
  - `interrupted` — оборванное начало ожидаемого манёвра (видимый перезапуск, PLAN §1);
  - `none`;
  - `unobserved` — реакция видна не целиком из-за перерыва или рестарта наблюдателя (выше, «Сессии записи»); сбоем
    не считается.

  Таблицы манёвров и рефлекса заменяются файлом `--maneuvers` (`{maneuvers: {имя: [[буква, с|null], …]},
  reflex: {"класс[:сторона]": имя | "none"}}`), например под исполнитель v2. `"none"` (или null) — класс без
  действия: так задаётся «класс 3 → нет действия» под флаг perception v2 `--ignore-cls 3` (R7b RS5).
- **Метки по жесту** (отсчёт от t0):
  - `rec` — поле `t_rec` сообщения perception (time.time ВМ sim);
  - `pub` — приём `/neurobot/gesture` (оба — решающего сообщения);
  - `cmd` — первая ненулевая `/cmd_vel`;
  - `motion` — первое «едет» по `/odom` или `/ground_truth/pose`;
  - `lat_extra` — то же по дополнительным темам: первое действие темы в окне сегмента (эпизоды темы относятся к
    сегментам, как у писателя: окно — до t0 + `--match-window-s` или начала следующего сегмента); если начала
    первого действия не видно, метки нет (выше, «Сессии записи»).

  Повтор `boot + seq` отбрасывается.
- **Счётчики** (это результат прогона):
  - `reactions`, `late` (t_cmd − t0 > 3 с), `visible_failures` (не `correct` и не `unobserved` или поздно),
    `early` (робот поехал до конца жеста: распознаватель разрезал длинный жест — у perception v2 окно эпизода 3 с);
  - `false_actions` по видам отрицательных сегментов, `false_recognitions` (отрицательные сегменты, на которых
    perception хоть раз выдал класс), `spontaneous_actions`, `extra_actions` (действия сегментов сверх первого —
    реакции: повтор или второй манёвр в окне того же жеста; у сегмента — `actions`, число его действий);
  - `moved_on_unknown` — движение, перед которым последним сообщением perception сегмента было «не распознано»
    (`cls = −1`), на любом сегменте;
  - `k7` — K7 одной строкой: `moved_on_unknown`, `moved_when_ignored` (движение на классе без действия),
    `false_actions`, `spontaneous_actions`, `total` (разных нежелательных действий) и `per_hour` — на час записи
    (`hours` — сумма сессий);
  - `cmd` — сообщений по темам скоростей, `type_mismatch`, `moving_without_cmd` — хотя бы в одной сессии база ехала,
    а команд писателя в ней не было ни одной (выше, «Сессии записи»). Причины две: неверный тип или имя темы
    (`--cmd-topic`) либо писатель молчал всю сессию, а база держит прежнюю команду; движение после первых
    `--connect-s` сессии в обоих случаях входит и в K6 `silent`.
- **«Едет без свежей команды»** (K6, `unsafe_no_fresh_cmd`) — робот едет (по любому источнику), а последняя
  ненулевая команда писателя старше `--stale-s` 0,5 с. Интервал делится по явному нулю писателя:
  - `silent` — нуля не было: писатель замолчал (S1 у демо, отказ самого стража). Считается при любой длине.
    Для строки «отказ писателя → остановка» K6 такой интервал кончается одним из трёх способов:
    - база встала — `stop_after_last_cmd_s`, «последняя ненулевая → остановка базы»; при позднем нуле в него входит
      и торможение после нуля;
    - база ехала до конца записи (сессии) — `not_stopped_by_end` {`n`, `total_s`, `max_s`}: от устаревания команды
      до конца сессии, при позднем нуле тоже (остаток после нуля — ещё и `ignored_zero`). Так бывает, когда база
      держит последнюю команду: двойник `--hold` (`cmd_vel_timeout` 0) или `stm32_sim` hold. Конец сессии — не
      остановка: в `stop_after_last_cmd_s` такой интервал не входит, и остановка в следующей сессии с ним не
      связывается. Остановка базы, которая оказалась последним событием сессии (наблюдатель убит без `stop`),
      остаётся остановкой;
    - пришла свежая команда — не входит ни туда, ни туда;
  - `braking_after_zero` — ноль был, и база встала не позже `--brake-allow-s` 0,6 с после него: торможение, не
    нарушение. 0,6 с = 0,5 м/с ÷ 1 м/с² (разгон DiffDrive стенда) + 0,1 с на квант `/odom` [оценка];
  - `ignored_zero` — ноль был, а база едет дольше.

  `n`, `total_s`, `max_s` — нарушения (`silent` + `ignored_zero`); разбивка по источникам — `by_src` (скольжение
  колёс у стены видно только по `/odom`), в ней же `not_stopped_by_end` по каждому источнику. Считать ли торможение
  после нуля нарушением K6 — решение владельца PLAN (сейчас нет).
- **Глухота:**
  - `health` — `fps = 0` при идущих сообщениях дольше 2 с; состояния `paused` и `moving` (пауза детекции в движении)
    глухотой не считаются;
  - `health_missing`, `probe_missing` — сообщений здоровья (строк журнала probe) нет дольше `--health-gap-s` 3 с:
    между сообщениями, с начала суда в сессии до первого и от последнего до конца сессии, а в сессии без сообщений —
    целиком; прогрев до первого сообщения темы в прогоне — не в счёт (выше, «Сессии записи»);
  - `probe` и `probe_standing` (без интервалов движения) — `det_calls` не растёт при живом процессе (для A0).
- **Касание** — по истинной позе и контуру (см. выше).
- **Задержки** — p50/p95/p99 [ориентир], при n ≥ 20 — ДИ: среднее — кольцевой блочный бутстреп
  (`harness/stats.py`), квантили — ранговый ДИ по порядковым статистикам (Conover, 1999, §3.2; жесты разделены
  паузами и считаются независимыми). Для p95 нужно n ≥ 72, иначе ДИ нет (`null`). Жест, пришедшийся на окно с
  RTF < 0,95, в задержки не входит (`excluded_rtf`).

**Почему стенные часы, а не `use_sim_time`.**
- Источник жестов, perception, демо, страж и `stm32_sim` работают по стенному времени: `time.time`, `sleep`, таймеры,
  монотонные часы ВМ.
- Задержку «жест → движение» человек видит тоже в стенном времени.
- При RTF < 1 сим. время отстаёт от стенного, и метки на `use_sim_time` разошлись бы с t0 источника.

Поэтому все метки — это часы ВМ sim в момент приёма. Сопоставление идёт по CLOCK_MONOTONIC: оно не прыгает при
коррекции NTP. Метки из сообщений (time.time) переводятся по смещению `t − m` события приёма.

Сим. время из `header.stamp` используется только для скоростей по истинной позе и для RTF. RTF проверяет
допущение «стенное ≈ сим.», и по нему жесты исключаются из задержек.

Наблюдатель должен работать в той же ВМ, что и FakeYolo: CLOCK_MONOTONIC общий только в пределах одной загрузки ОС.

## 7. shapeclass — «форма → класс» настоящей сетью

```sh
# ВМ sim: torch и snntorch — из venv компонента perception, ROS — для импорта модуля лаборатории
source scripts/sim/vm_env.sh
~/nb/venv/bin/python -m neurobot.sim.gestures.shapeclass --gen DIR --out NEW_DIR [--votes 50] [--seed 0] \
    [--weights third_party/neurochip/demo/demo-ros2_feature/models/snn_emnist_small.pth]
```

`--gen` — каталог gesturegen, `--out` — новый каталог результата, `--votes` (50) — кодирований на сегмент, `--seed`
(0) — зерно кодирований, `--weights` — веса SNN (по умолчанию веса лаборатории).

Боксы каждого сегмента — как их собрало бы демо (уверенность > 0,35, по порядку, целые пиксели). Из них два холста:
`demo` — `write_map_number(scale=0.1)` лаборатории (путь демо как есть, G1) и `poly` — линия через центры рамок
(флаг `--polyline` perception v2). Каждый холст идёт в SNN лаборатории `--votes` раз (кодирования Бернулли одним
батчем, зерно — `seed + номер сегмента`). Класс сети, предобработка и кодирование импортируются из их
`predict_live.py` (без `main()`), веса — `torch.load(weights_only=True)` и строгая загрузка без `torch.compile`.
Выход: `per_segment.jsonl` и `table.json` (по формам и видам отрицательных сегментов: доли ответов, доля «немых» —
без выходных спайков, отрыв, сторона по правилу демо; итог по жестам: `mute`, `pred0`, `match_label`).
Сегменты меньше чем с 6 боксами демо не распознаёт — они считаются отдельно (`below_6`).

## 8. Совместимость

Весь код совместим с Python 3.8 (Foxy):
- нет `match`;
- нет `X | Y` и `list[…]` во время выполнения, `from __future__ import annotations`;
- нет `bisect(key=)`.

На стенде — Jazzy и Python 3.12. `rclpy` нужен только `observer.py`; torch, snntorch и ROS — только `shapeclass.py`.

`clock.mono()` берёт `clock_gettime(CLOCK_MONOTONIC)` явно. Причина: `time.monotonic()` в Python 3.8 на macOS
отсчитывается от старта процесса, и якорь между процессами там не работал бы ([замер]: 0,007 против 418 328 с у 3.12).
