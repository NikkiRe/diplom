# neurobot/lab — этап Э0 «Факты с робота»

Что передаётся лаборатории NeuroChip и чем собираются журналы с робота. План и разбор — `docs/neurobot/PLAN.md` (§7 Э0, §11), `docs/neurobot/ANALYSIS.md` (§3, §5, §5.2), нынешний стек робота — `docs/neurobot/research/R7_robotic_platform.md` и `R7_robot_slides.md`.

| Файл | Что это |
|---|---|
| `LAB_HANDOUT.md` | Документ для лаборатории: срочное, что нашли, что сделать сразу без кода, вопросы, как собрать журналы |
| `collect_diag.sh` | Сбор диагностики на роботе, только чтение; результат — каталог и `.tar.gz` |
| `redact.py` | Вырезание ключей и токенов; вызывается из `collect_diag.sh`, лежит рядом с ним |
| `scan_sectors.py` | Сводка одного сообщения `/scan` по секторам 10° без выгрузки массива (rclpy); вызывается из `collect_diag.sh` |
| `tests/` | Проверки: `redact.py` и `scan_sectors.py` (на Mac, Python 3.8 и 3.12), сбор на фикстуре (ВМ sbc), ROS-часть (ВМ sim) |

Лаборатории копируются три файла: `collect_diag.sh`, `redact.py`, `scan_sectors.py` (в один каталог).

## collect_diag.sh

```bash
bash collect_diag.sh                      # под пользователем, от которого работают демо и PicoClaw
bash collect_diag.sh --sudo               # полнее: dmesg, системный журнал, журналы юнитов пользователя, чужие процессы
```

В stdout печатается только путь к архиву, ход сбора — в stderr. Код выхода: 0 — сбор завершён (отдельные пункты могут быть «нет»); 2 — неверные аргументы, нет `python3`, `redact.py` или `timeout`, sudo не подтверждён. Без `scan_sectors.py` сбор идёт, сводка `/scan` отмечается «нет». `--help` печатает флаги со значениями по умолчанию.

| Флаг | По умолчанию | Что задаёт |
|---|---|---|
| `--sudo` | выкл. | команды, которым нужен root, идут через `sudo -n` (пароль спрашивается один раз в начале) |
| `--out DIR` | текущий каталог | где создать `neurobot_diag_<хост>_<время>/` и архив |
| `--tegrastats-sec N` | 60 | длительность записи tegrastats; 0 — не записывать |
| `--days N` | 7 | глубина журналов юнитов, журналов ROS 2 и логов рядом с кодом |
| `--max-log-mb N` | 5 | сколько последних МБ брать из каждого файла журнала |
| `--ros-setup FILE` | `/opt/ros/$ROS_DISTRO/setup.bash` или первый `/opt/ros/*/setup.bash` | setup-файлы ROS 2 (флаг повторяется: база, затем рабочее пространство) |
| `--search DIR` | `$HOME` | где искать код лаборатории, venv, скрипты запуска, PicoClaw, веса (флаг повторяется) |
| `--camera` | выкл. | `rs-enumerate-devices -c` — параметры камеры; не запускается, пока жив процесс, который может держать камеру |

### Что не собирается и не меняется

- Ничего не останавливается, не перезапускается и не пишется вне каталога результата. Исключения названы явно:
  - служебный `ros2 daemon`: если в домене его не было, он поднимается на время сбора (иначе `topic info` поднял бы его сам и оставил) и останавливается в конце, в том числе при прерывании; журналы ros2 CLI пишутся во временный каталог (`ROS_LOG_DIR`) и удаляются;
  - из программ лаборатории запускаются только две вещи. Первая — `picoclaw version`, и только у ELF-файла с именем ровно `picoclaw`: лаунчер (`picoclaw-launcher`) принимает `version` за путь к конфигу и запускает `picoclaw onboard`, который перезаписывает `~/.picoclaw/workspace` (AGENT.md, память, навыки), поэтому у остальных `picoclaw*` снимается только sha256. Вторая — найденные интерпретаторы Python (системный, venv, версии pyenv, интерпретаторы процессов): `-V` и список пакетов — `-m pip freeze --all` (это pip из окружения лаборатории; при старте Python обрабатывает `.pth` из site-packages), без pip — `importlib.metadata` под `-I`; у pyenv — `versions` и `global`. Остальное — системные утилиты на чтение (ps, ss, systemctl, journalctl, dpkg-query, git, `nvpmodel -q`, `jetson_clocks --show`, tegrastats, ros2 CLI);
  - адреса статуса воркеров и шлюза — только запрос GET на 127.0.0.1 без прокси, таймаут 3 с, первые 64 КБ ответа;
  - камера открывается только с `--camera` и только если нет процесса, который может её держать (демо, `realsense2_camera`, воркеры YOLO и robot_vision).
- Окружение процессов читается только по списку имён выше и `PICOCLAW_HOME`, `PICOCLAW_CONFIG`, `PICOCLAW_LOG_FILE`, `HOME`, `VIRTUAL_ENV`; остальное (там бывают ключи) не читается.
- `~/.picoclaw/.security.yml` не копируется (в отчёте — «есть»); содержимое сессий PicoClaw, кадры, видео, rosbag не собираются. Веса моделей только хешируются: `torch.load`/pickle не вызываются.
- `git` вызывается с `--no-optional-locks` (индекс не обновляется).
- У каждой внешней команды, которая может зависнуть (ps, чтение `/proc`, journalctl, ros2, find, pip, git, tmux, sha256sum, GET), — таймаут 2–90 с; tegrastats пишется в фоне параллельно с остальным сбором.

### Вырезание секретов (redact.py)

Вывод команд и копии файлов проходят через `redact.py` до записи; служебные строки (`$ команда`), `thermal.txt`, `tegrastats.txt`, `files.txt` и весь каталог — повторным проходом в конце (`redact.py --check`). Если повторный проход что-то вырезал, в отчёте — строка «ошибка». Вырезаются:
- значения узнаваемого вида где угодно: `sk-…`, `Bearer …`, `Basic …`, `user:pass@` и длинный токен перед `@` в URL, JWT, токены VK (`vk1.a.…`, 85 hex), GitHub, GitLab, Slack, Telegram (и в пути `…/bot<токен>/`), AWS, Google, блоки `PRIVATE KEY`; пароль в `curl -u user:пароль`, `sshpass -p`, `echo пароль | sudo -S`, `sudo -S <<< пароль`, `echo user:пароль | chpasswd`; пароль Wi-Fi в `nmcli … password V`, `nmcli … wifi-sec.psk V` и `wpa_passphrase SSID пароль`;
- значение, присвоенное секретному имени. Имя секретное, если в нём есть `api_key`, `token`, `secret`, `password`/`passwd`, `passphrase`, `authorization`, `credential`, `cookie`, `sshpass` или целым словом `key`, `pass`, `auth`, `psk`, `pwd`, `psw`, `pswd` (`VK_GROUP_KEY`, `SUDO_PASS`, `MYSQL_PWD`, `authKey`; но не `monkey`, `bypass`, `KeyError`, `PassEnvironment`). Присваивание узнаётся по форме, а не по языку файла:

| Форма | Примеры |
|---|---|
| имя, разделитель, значение | `NAME=v`, `NAME: v`, `NAME := v`, `NAME ?= v` (Makefile), `NAME => v`, `"api_key": "v"`, `\"api_key\":\"v\"` (JSON внутри строки JSON), `environ["NAME"] = v`, `cfg.token = v`, несколько целей (`TOKEN, CHAT_ID = v, 1`), аннотация типа (`def f(token: str = v)`), за словом объявления (`const token = v`, `local token=v`), поле структуры Go (`APIKey: v,`), `?access_token=v&` в URL, `api_key%3Dv` (URL-кодировка). Значение — строка (и склейка строк: `"a" "v"`, `"a" f"{v}"`), число, скобки, лямбда с телом (`key=lambda: os.getenv("T") or "v"`) или выражение целиком: `token = os.getenv("X", "v") or "w"`; у оператора присваивания — и через запятую: `API_KEYS=a,b`, `TOKEN = "a", "b"`. В присваивании до конца строки (INI, код, YAML) ` #` внутри кавычек — часть значения, а не комментарий: `key = s.split(" #")[0]` прячется целиком |
| имя в кавычках в списке аргументов | `setdefault("NAME", v)`, `("NAME", v)`, `["--token", v]` — остаток списка. Перенесённый по аргументу на строке (black, argparse, click): первая строка за именем — значение, дальше — значения именованных аргументов, литералы остаются (`add_argument(` ↵ `"--token",` ↵ `type=str,` ↵ `default="v",` ↵ `required=False,` ↵ `)`); в списке строк (`__all__ = [` ↵ `"SecretStr",` ↵ …) прячется только элемент за именем, как и на одной строке |
| запасное значение | `os.environ.get("NAME") or v`, `token or "v"`, `token if token else "v"`; у имени в кавычках — и `or v` строкой ниже (`get("NAME")` ↵ `or "v"`, `get("NAME") or` ↵ `"v"`) |
| сравнение с литералом | `if password == "v"`; сравнение с переменной (`== x`) не трогается |
| пара «имя — значение» | `<param name="api_key" value="v"/>`, `SetEnvironmentVariable(name="NAME", value="v")`, `{"name": "NAME", "value": "v"}`, `- name: NAME` и `value: v` строкой ниже, `<token>v</token>`, `<property name="password">v</property>` |
| флаг | `--api-key v`, `--token=v`, `--key "a b"`, `--api-keys a,b` |
| значение на следующих строках | после `\` (и за значением: `TOKEN = "a" \`, если следующая строка — не новая пара или флаг; перенос до или после оператора: `os.getenv("T") \` ↵ `or "v"`, `"a" + \` ↵ `"v"`; в YAML `\` — знак значения, а не перенос); перенос у оператора без `\` — как переносит black внутри скобок вызова и словаря: оператор в конце строки (`token="a" +` ↵ `"v")`) или в начале следующей (`api_key=os.getenv("K")` ↵ `or "v",`, `"Authorization": "Bearer %s"` ↵ `% ("v",)`, `api_key=a` ↵ `if prod` ↵ `else "v",`), если выражение за оператором кончается разделителем, скобкой или концом строки; оператор остаётся виден; строка в кавычках под значением, которое кончилось строкой, — склейка (`api_key="a"` ↵ `"v",`); пустая строка и строка-комментарий между значением и продолжением не мешают; имя в кавычках одно на строке внутри вызова или индекса — значение за скобкой ниже (`os.environ[` ↵ `"VK_TOKEN"` ↵ `] = "v"`, `get(` ↵ `"VK_TOKEN"` ↵ `)` ↵ `or "v"`); после ключа JSON без значения, после имени в списке аргументов и после `=` в скобках (`f(token=` ↵ `v)`); блок YAML под ключом; незакрытая скобка — до закрытия, в том числе за первым операндом (`api_keys: [` ↵ `a` ↵ `]`, `credentials = {` ↵ `'password': 'v'` ↵ `}`, `key = ''.join([` ↵ `'v'` ↵ `])`), а за `]` и `=` — значение после `=` (так black переносит аннотацию типа: `api_key: Optional[` ↵ `str` ↵ `] = "v"`); строка в тройных кавычках или с `\` в конце — до закрывающей кавычки. От такого значения остаются скобки, знаки препинания, операторы `+`, `-`, `*`, `/`, `%`, `or`, `in` … и литералы (`true`, `None`); ключи словаря и комментарии внутри тоже прячутся |
| заголовок | `Authorization: token v`, `Cookie: a=v; b=w` — значение целиком, со схемой; в коде и JSON (`{"Authorization": "Bearer " + KEY}`) — выражение, как у других имён |

Числа под секретными именами тоже вырезаются: пароль бывает из одних цифр. Присваивания ищутся от опорных подстрок секретных слов, а не с каждой позиции, а проверки от каждого найденного имени ограничены по длине (несколько целей — до 9 имён по 64 знака), поэтому длинная строка без разделителей (base64 картинки в журнале) и строка из многих имён без присваивания (`token, token, …`) обрабатываются за линейное время [код; тест `LongLineTest`].

Остаются `true/false/null` и пустые значения, пределы `max_*` и числа у счётчиков токенов (`summarize_token_percent`, `default_token_budget`): `"max_tokens": 32768` видно. «:» после заголовка блока Python (`if token: connect()`, `for key in keys: …`) — не присваивание: код остаётся читаемым. Повторный проход по уже вырезанному ничего не меняет — в том числе там, где за маской вызов, не закрытый на строке (`"<redacted>" + <redacted>(`), — это проверяется у каждого образца в тестах и на корпусах [замер, 15.10]: 11 707 файлов (пакет 1 `neurobot/` вместе с `lab`, `agent`, `bench` с исходниками PicoClaw, `docs`, `third_party`, стандартная библиотека Python 3.12 и 3.8 с её `site-packages`, пакеты `.venv`), корпус проверяющего с журналами из `experiments` (5 425 файлов), Homebrew (9 493) и ВМ sim (`/opt/ros/jazzy`, `/etc`, `~/.ros/log` — 35 420); иначе повторная проверка давала бы ложную «ошибку». Лишнее вырезание допустимо: `tokenizer: o200k`, `sort_key: name`, лямбда целиком (`key=lambda e: e["m"]` → `key=<redacted>`), `key, value = …`, содержимое словаря `result[key] = {` … `}` целиком, именованные аргументы за именем в кавычках (`help="…"`), строка в кавычках под значением-строкой и тогда, когда это не склейка (`TOKEN = "v"` ↵ `"""Строка документации."""`), следующее слово в кавычках в shell (`export TOKEN="v" "$X"`, `--token "v" "file"`), значение YAML с кавычкой посреди — вместе с комментарием за ним; скобка или строка в тройных кавычках под секретным именем, которая не закрывается, прячет всё до конца файла.

Ограничения [код]:
- секрет без имени и без узнаваемого вида не распознаётся: позиционный аргумент (`python3 bot.py abc123`), свободный текст (`invalid token abc123`), поле с нейтральным именем вне пары (`"value": "abc"`, `"id": "abc"`);
- не распознаются значение в другой кодировке (base64, `\u0022`), пара XML, у которой `name` и `value` на разных строках, и разделитель вне перечисленных (`token -> v`, `setenv NAME v`, `read NAME <<< v`, `echo v > ~/.token`);
- пароль в коротком флаге конкретной программы (`mysql -pV`, `ssh-keygen -N V`, `openssl -k V`, `mosquitto_pub -P V`) и сравнение в shell (`[ "$TOKEN" = "v" ]`) не распознаются;
- строка, которая начинается с оператора, продолжает значение строкой выше, только если выражение за оператором кончается разделителем, скобкой или концом строки: `or token == "v"):` и текст (`not None and the …`) — не продолжение, такая строка разбирается сама по себе (литерал в сравнении прячется). Не связываются со значением ниже: ветка `else` за условием тернарного выражения, которое само перенесено (`if os.path.exists(` ↵ `path` ↵ `)` ↵ `else "v"`; у black — при ширине строки 20–30); перенос посреди аннотации типа вручную (`def f(token:` ↵ `str = "v")`, `def f(token: str` ↵ `= "v")`; перенос black внутри скобок аннотации разбирается); имя без кавычек перед `or` в конце строки (`(token or` ↵ `"v")`); в списке аргументов по строке — аргументы за значением, которое само переносится (`default=os.getenv(` ↵ … ↵ `),` или `default=a` ↵ `or b,`): дальше список не прячется;
- выражение продолжается только через `+`, `%`, `or`, `and`, `if`/`else`, `in`, `is`, `not`, вызовы, индексы и склейку строк; через `-`, `*`, `/`, `||`, `??` — только в присваивании в начале строки, где значение берётся до конца строки: `x = 1; token = a - "v"` и `{ token: a || "v" }` (JavaScript) утекают. `&&` и `||` не продолжают значение нарочно: в shell это разделители команд (`export TOKEN=v && ./run.sh` остаётся читаемым);
- присваивание списку целей в скобках (`[TOKEN, ID] = ["v", 1]`, `(token, chat) = ('v', 42)`) не распознаётся;
- строка в обычных кавычках на несколько строк без `\` в конце (YAML `password: "a` ↵ `b"`) вырезается только на первой строке, и незакрытая обычная кавычка внутри скобки тоже кончает значение на этой строке: такая кавычка чаще значит вложенные кавычки (`'k="v"'` в коде тестов и журналах), и перенос сдвинул бы разбор следующих строк. По той же причине `\n` внутри строки журнала (JSON, repr) — не перенос: `"token":\n "v"` в одной строке не связываются;
- текст переписки — не секрет по форме: при `log_level: "info"` PicoClaw 0.2.8 пишет в `gateway.log` начала ответов агента.

Поэтому лаборатории предлагается просмотреть архив перед отправкой и пересобрать его после ручной чистки (`LAB_HANDOUT.md` §5).
