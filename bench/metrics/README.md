# Метрики прогона «работы во времени»

По каталогу прогона (`bench/replay`) считает метрики спецификации §7 / концепции §12.2 и пишет
`metrics.json` и краткую таблицу. Входы: трасса edgectx (§6), журнал mock-llm, sysmon (`sysmon.v1`),
файл дня, отчёт sim-mcp, отчёты монитора и трассы шлюза. Статистика — `harness/stats.py`, цены —
`bench/costmodel` (замороженный прайс `research/new_topic/F_artifacts/price_table.py`).

Числа, полученные при разработке, — **не результаты**.

В T0 и при сжатии времени `metric_validity` явно помечает CPU/сутки, задержки и наклон памяти как
невалидные для переноса в T2. Числа сохраняются для диагностики; выбор `--time-base wall` не меняет
этого ограничения. RSS/PSS — ориентир. `resources.oom` передаёт `sysmon end.oom`; отсутствие наблюдения
означает `status: unknown`, а не отсутствие OOM.

## Запуск

```bash
.venv/bin/python -m bench.metrics experiments/results/<run_id>            # metrics.json + таблица
.venv/bin/python -m bench.metrics RUN --json --model gpt-4o-mini          # JSON в stdout
.venv/bin/python -m bench.metrics RUN --trace other.jsonl --sysmon s.jsonl --monitor m.json --gate hw.jsonl
```

Файлы ищутся по шаблонам: `edgectx_trace*.jsonl`, `mockllm_journal*.jsonl`, `sysmon*.jsonl`, `day.jsonl`,
`replay.jsonl`, `manifest.json`, `simmcp_report*.json`, `monitor*.json`, `hwmcp*/simmcp*/*gate*.jsonl`;
любой путь задаётся флагом. Флаги: `--model`, `--price-table`, `--answer-abs-tol` (1e-6), `--slope-delta`
(1 МиБ/ч), `--first-hour-s` (3600), `--block-bootstrap` (ДИ наклона блочным бутстрепом, медленно).

## Что считается (`metrics.json`)

| Раздел | Содержимое и правило |
|---|---|
| `window` | фактически проигранное окно из manifest/replay (учитывает `--window-end`); иначе окно дня из заголовка; будущие реплики и ситуации исключаются |
| `llm` | вызовы LLM за окно, `calls_per_hour`, по источнику (`user/gate/heartbeat/rule`): причина `wake` по `wake_id` или явное поле `reason/wake_reason` запроса (без id — последний wake); сводки истории — отдельно как `summary`; пробуждения по причинам, `suppressed`, `rule_fired`; **пустые пробуждения** — не пользовательский wake с вызовами LLM, но без действия (вызов инструмента, кроме чтения, `answer`, `refuse`, `create_rule`) и без уведомления; задержка LLM p50/p95. Без трассы — по журналу mock-llm (источник `unknown`) |
| `tokens` | входные, кэш (`cached_tokens`), некэшированные, выходные — всего, по источнику, в среднем на вызов; доля кэша; средние оценки сегментов `llm_request.segments` |
| `cost_rub` | ₽ по замороженному прайсу: наблюдаемые (по `cached_tokens`), «кэша нет», «весь стабильный префикс из кэша» (`segments.prefix` ≥ 1024 → вниз до 128); по источнику; цены и SHA-256 снимка |
| `traffic` | байты LLM-обмена из журнала mock-llm: тела и с заголовками, вверх/вниз; по источнику — если в журнале есть `X-Edgectx-Req-Id` (связь с `llm_request.req_id`) |
| `reaction` | ответ на реплику (`user_reply.latency_ms`), RTT реплики у реплеера, «ситуация → действие» в виртуальных секундах: p50/p95/n |
| `situations` | **строгая полнота**: доля значимых ситуаций (`significant ≠ false`) с реакцией не позже `deadline_s`, ДИ Клоппера–Пирсона; реакция — подтверждённый `notify` с `situation_id`/`[sit:<id>]` или успешное действие из `expect.actions`. Вызов инструмента без успешного `tool_result` не засчитывается; время действия — завершение. Связанная и верхняя оценки по окну — отдельно; списки пропущенных и поздних, детали |
| `questions` | точность ответов: последний вызов `*answer` эпизода входа (по `wake_id`); число — с допуском, строка — без регистра; единица сравнивается, если указана в обоих |
| `quality_sim` | сводка sim-mcp по истинному состоянию (`simmcp_report.json`: команды, вопросы, ситуации с действиями) |
| `safety` | **N_unsafe** — максимум по источникам: монитор (классы `actuator_safety*`), трассы шлюза/sim-mcp (записи с `unsafe: true`, которые исполнены), `tool_result.unsafe`; нет источников — `null`, а не 0; число отказов шлюза |
| `resources` | sysmon: память дерева (`tree.pss_kib`; без PSS — RSS с пометкой), «оркестратор» (`root`), cgroup (`memory_current`, `memory_peak`), CPU-с всего и в час (`cgroup.cpu_usage_s`, иначе `tree.cpu_s + cpu_children_s`), major faults; **наклон Сена** МиБ/ч после первого часа (если прогон ≥ 2 ч) с ДИ Сена и TOST ±δ на 90 % ДИ по батч-средним (20 батчей); Манн–Кендалл — только разведочно |

Время трассы: `ts_clock` числом < 10⁷ — секунды дня (виртуальные часы); иначе (Unix или RFC 3339) —
секунды от местной полуночи. `ts_wall` — секунды Unix (допускается мс и RFC 3339 с наносекундами).

## Статистика в `harness/stats.py` (добавлено)

| Функция | Что делает |
|---|---|
| `sen_slope(t, y, conf)` | наклон Тейла–Сена, ДИ по Сену (1968, ур. 2.6) — совпадает со `scipy.stats.theilslopes` (проверено тестом), свободный член по Коноверу |
| `sen_slope_batch_means(t, y, n_batches)` | тот же наклон и ДИ по батч-средним (гасит автокорреляцию соседних отсчётов) |
| `sen_slope_block_bootstrap(t, y, …)` | перцентильный ДИ наклона кольцевым блочным бутстрепом остатков |
| `tost_slope(t, y, delta, alpha, method)` | эквивалентность «тренда нет»: (1 − 2α)-ДИ наклона строго внутри (−δ, δ) |
| `mann_kendall(t, y)` | S, Var(S) со связками, Z с поправкой на непрерывность, p — разведочно |
| `batch_means_ci(x, n_batches)` | ДИ среднего коррелированного ряда (Стьюдент, B − 1 степеней свободы) |
| `block_bootstrap_mean(x)`, `block_bootstrap_ratio(a, b)` | кольцевой блочный бутстреп (Politis & Romano, 1992), L = ⌈n^(1/3)⌉ |
| `t_cdf`, `t_quantile` | распределение Стьюдента без scipy |

## Тесты

```bash
.venv/bin/python -m pytest bench/tests/test_metrics.py harness/tests -q
```
`test_metrics.py` — синтетический прогон с известным ответом: 10 вызовов по источникам, токены, ₽ (пересчёт
по прайсу), трафик и связь с трассой, атрибуция реакций на ситуации (явный id, окно, метка, поздно, пропуск,
незначимая), точность ответов и допуск, N_unsafe по источникам и `null` без них, PSS с точным наклоном 0,2 МиБ/ч,
CPU, разбор времени, CLI. Тесты статистики — `harness/tests/test_stats.py` (известные значения, сверка со scipy,
покрытие на AR(1)).

## Ограничения

- Атрибуция «вызов → источник» использует `wake_id` и явную причину запроса; только для старой трассы без
  `wake_id` используется последний `wake`. Неизвестный явный id не наследует причину чужого пробуждения.
- Трафик — только HTTP LLM-обмена по журналу mock-llm (без TLS-рукопожатий, MCP и канала пользователя); классы
  трафика на плате даёт nftables (вне этого модуля).
- В T0 оба диагностических наклона (стенной и виртуальный) не доказывают стабильность памяти в T2.
