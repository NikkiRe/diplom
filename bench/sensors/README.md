# Проверка датчиков без платы и ключа

Из корня проекта:

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m bench.sensors
```

Нужны уже установленные зависимости `.venv` и Go. Команда собирает свежий `agent/`, запускает
локальные sim-mcp и mockllm, затем последовательно проверяет `gate`, `heartbeat`, `hybrid`.
Реальные API, VM, робот, камера и исполнительные устройства не используются.

Два условных датчика — числовой `sensor_numeric.value` и логический `sensor_binary.active`.
Сценарий содержит обычные изменения, пересечение порога, логический переход и два вопроса о текущем
показании. Имена, порог и частота — тестовый пример, а не согласованная периферия.

Каждый запуск создаёт уникальный каталог `bench/sensors/smoke/<дата-время-случайный id>/`.
Там остаются свежий бинарник, файл сценария, конфиги, журналы сервисов, SQLite, трассы,
`manifest.json`, `monitor.json`, `metrics.json`, `check.json` и SHA-256 артефактов.
Существующие прогоны не перезаписываются; останавливаются только созданные командой процессы.
При сбое сохраняются журналы и `failure.json`, команда возвращает ненулевой код.

```bash
# Один режим / другое место для артефактов
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m bench.sensors --mode gate --out /tmp/sensor-smoke

# Отдельный сквозной тест настоящего hw-mcp на файлах sysfs
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest bench/tests/test_hwmcp_edgectx.py -q
```

Здесь виртуальные 30 минут проходят ускоренно. Все числа — **ориентир, не результат**.
Оракул проверяет протокол и учёт вызовов; качество выбранной LLM он не проверяет.
Деньги не потрачены; для `mock-oracle` нет тарифа. CPU/память/энергия платы и реальная задержка
этой командой не измеряются. Монитор проверяет структуру трассы; проверка приводов пропущена,
поскольку приводов в сценарии нет.
