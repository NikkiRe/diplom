# daygen — генератор «рабочего дня»

Генерирует детерминированный по seed файл дня (JSONL) для стенда EdgeCtx: трассу датчиков дома CASAS,
реплики пользователя по профилям нагрузки, вопросы о прошлом с правильными ответами, значимые ситуации
с дедлайнами. Один файл дня проигрывается для всех конфигураций (парный дизайн, THESIS_CONCEPT §12.1).
Контракт формата — IMPLEMENTATION_SPEC §2; здесь — подробности и всё, что добавлено сверх него.

## Как запускать

Все команды — из корня проекта (`/Users/chosenundead/Projects/diploma-edge-ai`), Python — `.venv/bin/python`.

```bash
PY=.venv/bin/python
# один день: дом и сутки — по расписанию части tune (seed 1 → hh106 2011-07-21)
$PY -m bench.daygen gen --seed 1 --profile M+ --split tune --out day.jsonl
$PY -m bench.daygen timeline day.jsonl [--sensors]                     # прочитать глазами
# серии для настройки и для отложенной проверки (seed могут совпадать: нагрузка всё равно разная)
$PY -m bench.daygen batch --seed0 1 --n 30 --profile M+ --split tune    --outdir days/tune_Mplus
$PY -m bench.daygen batch --seed0 1 --n 30 --profile M+ --split holdout --outdir days/holdout_Mplus
$PY -m bench.daygen stats 'days/tune_Mplus/*.jsonl'                     # частоты на сутки, 95 % ДИ
$PY -m bench.simmcp.selfcheck days/tune_Mplus/*.jsonl [--catalog explicit]   # согласованность с sim-mcp
# конкретные сутки (split выводится из дома) и короткое окно с пропорциональной нагрузкой
$PY -m bench.daygen gen --seed 1 --profile S200 --home hh121 --date 2012-03-03 --out heavy.jsonl
$PY -m bench.daygen gen --seed 1 --profile H --split tune --window 07:00-09:00 --rate-scale 0.125 --out day2h.jsonl
$PY -m bench.daygen gen --seed 1 --source synthetic --out day.jsonl     # без данных CASAS
```

`--split` для дней CASAS обязателен (без `--home`): `tune`, `holdout` или `any` — явное разрешение брать дома
обеих частей (раньше умолчание молча подмешивало отложенные дома к настройке). Синтетическому дому split нужен
только как соль ГСЧ (по умолчанию `tune`).

Параметры `gen`/`batch`: `--profile L|M|M+|H|S69|S200`, `--source casas|synthetic`, `--home hh101`,
`--split tune|holdout|any`, `--date YYYY-MM-DD`, `--lang ru|en|mix`, `--window 07:00-23:00`, `--rate-scale 1.0`,
`--question-share 0.25`, `--trap-share 0.10`, `--synthetic-situations 2`, `--deadline 300`,
`--door-open-min 10`, `--night-start 22:00`, `--no-motion-h 2`, `--absence-h 4`, `--awake 07:00-21:00`,
`--no-manual-switch`. Все параметры записываются в заголовок (`params`), по ним день восстанавливается байт в байт.
`batch` предупреждает, если серия длиннее расписания части и пары (дом, сутки) начали повторяться.

### Выбор дома и суток, tune/holdout

Без `--home` пара (дом, сутки) берётся из **расписания части** (`schedule_pair`): seed разбивается на круг
`r = seed // H` и позицию `seed % H` (H — число домов части); каждый круг обходит все дома части в своём
перемешанном порядке, дом на r-м круге берёт r-е сутки из своего перемешанного списка пригодных суток.
Подряд идущие seed дают разные дни без повторов (выбор без возвращения), дома представлены поровну:
без повторов для 175 подряд идущих seed в tune (7 × 25 суток), 63 в holdout (7 × 9: у hh121 9 суток),
126 в any. Расписание не зависит от профиля и долей — все профили одного seed идут по одним суткам.

Все потоки ГСЧ солятся частью дома (см. «Детерминизм»), поэтому **при одинаковых seed дни tune и holdout
различаются и по пользовательской нагрузке** (число реплик, k, порядок вопросов/команд), а не только домом.
Проверено: на seed 1–30 (M+) совпадений числа реплик 2/30, последовательности k 1/30 — уровень случайных
совпадений; до соли было 30/30 (ревью).

Данные (уже собраны, пересборка воспроизводит файлы байт в байт):

```bash
$PY -m bench.daygen casas-check      # архив data/casas/labeled_data.zip цел (аналог unzip -t)
$PY -m bench.daygen casas-extract    # -> data/casas/subset/ (14 домов, index.json, PROVENANCE.txt)
$PY -m bench.daygen massive-build    # -> data/massive/ (шаблоны команд, PROVENANCE.txt)
```

## Формат дня

Первая строка — заголовок, далее события по возрастанию `t`. Сериализация каноническая: ключи
отсортированы, без пробелов, UTF-8 без `\u`.

**Время.** `t` — секунды **от полуночи** суток (виртуальные часы). Окно дня — `window` (`["07:00","23:00"]`)
и `window_s` (`[25200, 82800]`); все события лежат в `[window_s[0]; window_s[1])`, реплики — не позже чем за
60 с до конца окна (в окне ≤ 2 мин — за 1 с). Если сессия длиннее окна (короткое окно с большим профилем без
`--rate-scale`), её хвост отбрасывается, число отброшенных реплик — `counts.utterances_truncated` (для окна
07–23 — 0). Реплеер ставит часы edgectx и sim-mcp в начало окна и продвигает их до `t` событий.

### Заголовок (`kind: "header"`)

| поле | смысл |
|---|---|
| `format`, `generator` | `daygen/1`, версия генератора |
| `seed`, `profile`, `profile_params` | seed, профиль и его параметры (команд/сут, команд/сессию) |
| `source`, `home`, `split`, `date` | `casas`/`synthetic`, дом CASAS, `tune`/`holdout`, сутки CASAS |
| `window`, `window_s`, `t_origin` | окно и его границы в секундах; `t_origin: "midnight"` |
| `lang` | `ru`, `en` или `mix` |
| `devices` | инвентарь помещения (см. ниже) — из него sim-mcp строит каталоги generic/explicit |
| `rooms` | комнаты дома и словоформы (`ru`, `ru_loc`, `en`) |
| `initial_state` | состояние всех свойств в начале окна (трасса CASAS до 07:00 свёрнута сюда) |
| `initial_user_room` | где житель в начале окна (последнее движение) |
| `situation_rules` | параметры предикатов значимых ситуаций (фиксируются в предрегистрации) |
| `counts`, `counts_by_class` | число событий по видам (и `utterances_truncated`) и классам |
| `params` | все параметры генерации |
| `casas` | DOI, SHA-256 архива и файла дома в подмножестве |

**Устройство:** `{"id", "type", "location", "title": {"ru","en"}, "properties": {имя: схема}, "actions": {…}}`;
схема свойства — `type` (boolean | integer | number | string), `rw`, необязательные `unit` (Cel, %RH, Pa, %),
`min`/`max`, `enum`, `resolution`. Действие — `description`, `params` (схемы параметров) и `effect` (что
меняется, на сколько секунд, что становится потом; исполняет sim-mcp).

| устройства | откуда | свойства |
|---|---|---|
| `pir_<локация>` | CASAS ON/OFF (Bathroom, Bedroom, Kitchen, LivingRoom, DiningRoom, WorkArea, Office, LoungeChair, OutsideDoor→`entrance`) | `motion` 0/1 |
| `door_front` | CASAS OPEN/CLOSE у OutsideDoor (нет у hh122, hh126) | `open` 0/1 |
| `contact_<локация>` | CASAS OPEN/CLOSE в других локациях (дверцы шкафов) | `open` 0/1 |
| `light_<комната>` | по одной лампе на комнату дома | `on`, `brightness` 1–100 %, `color` (10 цветов) |
| `thermo_<комната>` | синтетика, BME280 | `temperature` 0,1 °C, `humidity` 1 %, `pressure` 100 Па |
| `boiler` | синтетика, DS18B20 + реле | `temperature`, `heating` (rw) |
| `leak_<комната>`, `valve_water` | синтетика | `wet` 0/1; `open` (rw) |
| `plug_<комната>` | «умная розетка» MASSIVE | `on` (rw) |
| `coffee_<комната>` | кофемашина | `brewing`; действие `brew` (300 с) |
| `vacuum` | робот-пылесос | `cleaning`, `zone`; действия `start {room?}` (1800 с), `dock` |

### События

```json
{"t":25412.3,"kind":"sensor","device":"pir_kitchen","property":"motion","value":1,"source":"casas:hh101"}
{"t":30001.2,"kind":"user_cmd","id":"u3","text":"выключи свет на кухне","lang":"ru","class":"control",
 "action":"light_off","template":"massive:2230","room":"kitchen","resolve":"slot","session":2,"turn":1,"k":3,
 "expect":{"type":"action",
   "calls":[{"name":"write_property","args":{"device":"light_kitchen","property":"on","value":false}}],
   "calls_explicit":[{"name":"set_light_kitchen_on","args":{"value":false}}],
   "goal":[{"device":"light_kitchen","property":"on","op":"eq","value":false}]}}
{"t":30120.0,"kind":"user_cmd","id":"u4","class":"invalid","text":"выключи свет в гараже","target":"light_garage",
 "expect":{"type":"refuse","reason":"no_such_device","calls":[{"name":"refuse","args":{"reason":"no_such_device"}}]}, …}
{"t":41000.5,"kind":"question","id":"q2","text":"когда последний раз открывали входную дверь?","class":"past",
 "qtype":"last_door_open","answer":{"value":40211.9,"unit":"t","tol":60},
 "expect":{"type":"answer","calls":[{"name":"answer","args":{"value":40211.9,"unit":"t"}}]}, …}
{"t":50097.3,"kind":"situation","id":"s3","name":"door_left_open","significant":true,"deadline_s":300.0,
 "expect":{"type":"notify_or_action"},"evidence":{"device":"door_front","open_since":49497.3,"min_open_s":600.0},
 "source":"casas"}
```

* `sensor` — изменение свойства (повторы одного значения отброшены). `source`: `casas:<дом>`, `synthetic`,
  `manual` (житель сам переключил свет).
* `user_cmd` — `class`: `control` | `multi` | `invalid`; `action` — нормализованное намерение; `resolve` — откуда
  комната (`slot` — из текста, `context` — где житель сейчас, `fixed`, `none`); `k` — вызовов LLM на реплику по
  модели VisionClaw; `session`/`turn` — номер сессии и реплики в ней. `expect.calls` — минимальная эталонная реакция
  (для mock-llm oracle), `expect.goal` — что должно стать истинным (проверяет sim-mcp); засчитывается любая реакция,
  после которой цель выполнена. Для `invalid` ожидается `refuse`.
* `question` — `class`: `past` (о прошлом по датчикам), `state` (текущее состояние, в `answer.ref` — свойство,
  sim-mcp сверяет с истинным состоянием в момент ответа), `history` (о прошлых репликах пользователя).
  Единицы `answer.unit`: `t` (секунды от полуночи; sim-mcp принимает и «ЧЧ:ММ»), `count`, `Cel`, `%RH`, `room`,
  `color`, `bool`; `tol` — допуск, `accept` — допустимые написания строки.
* `situation` — агенту не подаётся (он должен заметить её по датчикам); `deadline_s` — для метрики полноты;
  `expect.actions` — действие, которое тоже считается реакцией (перегрев → выключить нагрев, протечка → перекрыть кран).

## Модель дня

**Реплики пользователя** (как `compression_bias.py:gen_day` из GAP1): число сессий ~ Пуассон(команд/сут ÷
команд/сессию), реплик в сессии — геометрическое со средним «команд/сессию», паузы внутри сессии — логнормаль,
медиана 90 с, обрезка [5; 600] с [допущение]; час начала сессии — по часовому профилю начал активностей
выбранного дома CASAS в окне. Сессия, не помещающаяся в окно, сдвигается назад (а не обрезается), поэтому
среднее число реплик равно профилю (проверено тестом на 1000 seed). Профиль задаёт число реплик **на окно**
(«активный день»); для окна-доли суток (T2 14–22, интеграционный день на 2 ч) нагрузку можно пропорционально
уменьшить `--rate-scale`. Синтетические ситуации в коротком окне размещаются с пропорционально меньшими полями.

| профиль | команд/сут | команд/сессию | источник |
|---|---|---|---|
| L / M / H | 2,61 / 5,55 / 30,44 | 2,42 / 2,74 / 5,40 | Bentley et al. 2018, табл. 6 |
| M+ (основной) | 10,1 | 4,7 | VisionClaw §6.2 (555/118) |
| S69 / S200 | 69 / 200 | 5,40 | стресс, только T0 |

Вызовов LLM на реплику `k` ∈ {1, 2, 3, 5} с вероятностями 0,21 / 0,27 / 0,23 / 0,29 (VisionClaw, E[k] ≈ 2,9).
Реплика — вопрос с вероятностью `question_share` (0,25 [допущение]), иначе команда; команда — ловушка
«невалидная» с вероятностью `trap_share` (0,10 [допущение]).

**Команды.** 171 шаблон из 220 пар MASSIVE iot ru/en (data/massive/iot_templates.json, разметка и причины
исключения — в `massive.py`). Команда выбирается с учётом «идеального» состояния дома: выключают горящий свет,
приглушают включённый, варят кофе, когда кофемашина свободна. «Выключи свет» без комнаты относится к комнате,
где последним было движение. Ловушки: шаблон с комнатой, которой нет в доме («на балконе», «в столовой» в доме
без столовой), или устройство, которого нет («телевизор», «вай фай»).

**Вопросы** (11 типов): когда последний раз открывали дверь, сколько раз открывали, когда было движение в
комнате, где было последнее движение, максимальная температура с утра; текущие температура, влажность,
дверь, свет в комнате; какой цвет просил, сколько раз просил кофе. Ответ вычисляется только по тому, что агент
мог видеть с начала окна.

**Значимые ситуации** (`situations.py`): из данных CASAS — `door_left_open` (дверь открыта ≥ 10 мин),
`door_open_late` (открыта после 22:00), `no_motion_home` (нет движения ≥ 2 ч, тишина началась не у двери и
целиком лежит в «часах бодрствования» `awake`, по умолчанию 07:00–21:00), `long_absence` (нет движения ≥ 4 ч
после активности у двери); синтетические — `overheat` (котёл > 85 °C) и `leak`, ровно `synthetic_situations`
в сутки (0 / 2 / 5). Часы бодрствования исключают сон: тишина, начавшаяся до 07:00 (утренний сон — раньше
41 из 171 срабатывания), или вечерняя, не заканчивающаяся до 21:00 (отход ко сну — 42 из 171), ситуацией не
считается; дневной сон в спальне остаётся (оговорка).

Частота ситуаций из данных — свойство данных, а не профиля (перепись всех пригодных суток, генератор 1.1):

| часть | суток | всего в сутки (дома поровну / все сутки) | door_left_open | door_open_late | no_motion_home | long_absence | разброс по домам |
|---|---|---|---|---|---|---|---|
| tune | 255 | 0,64 / 0,58 | 0,24 | 0,07 | 0,22 | 0,11 | 0,29–1,93 |
| holdout | 238 | 0,61 / 0,50 | 0,40 | 0,05 | 0,11 | 0,06 | 0,11–1,64 |

(«дома поровну» — так их взвешивает расписание; до исключения сна было 0,81 и 0,61 по всем суткам; прежняя
цифра README «≈ 1,1» неверна.) Плюс ровно `synthetic_situations` синтетических (по умолчанию 2).

**Синтетика** [допущения, `synth.py`]: климат — суточная синусоида + AR(1)-шум, опрос раз в 5 мин; котёл —
циклы нагрева около 60 °C, эпизод перегрева — рост до ≈ 92 °C за 10 мин, плато 20 мин, спад 15 мин; протечка
держится 30 мин. Трасса не реагирует на действия агента (котёл не остывает от выключения нагрева).
**Ручные переключения света** [допущение]: при смене комнаты житель включает свет в новой (p = 0,3 в «тёмные
часы» — первый час окна и после 19:30, иначе 0,02) и выключает в прежней (0,5 / 0,2), не чаще раза в 30 мин на
лампу; ≈ 20 событий в сутки (21 в среднем на seed 1–20 tune).

**Детерминизм.** Каждый случайный выбор берёт свой поток `random.Random(f"daygen/{split}/{seed}/<имя>")`, где
`split` — часть дома (tune | holdout). Внутри части одинаковые seed дают общие случайные числа для разных
профилей (парный дизайн), между частями — независимые. Часть трассы `casas` + `synthetic` не зависит от профиля
и долей вопросов/ловушек (одинакова для L и S200 при одном seed — проверено на 20 seed); **ручные переключения
света (`source: manual`) — зависят**: житель переключает свет по «идеальному» состоянию, которое меняют команды
(на 20 seed tune из ≈ 21 события manual в сутки у L и S200 различаются в среднем 16 — симметричная разность).
Гейт edgectx свет не отслеживает (`edgectx_simday.yaml`), поэтому на вызовы LLM это не влияет.
Версия генератора 1.1 (соль split, расписание, обрезка по окну, часы бодрствования) — дни 1.0 не воспроизводятся.

## Ограничения

* Проверка ответов о прошлом предполагает, что агент начинает день в начале окна (история с 07:00).
* Классы «условные», «временные», «опасные в текущем состоянии», «устаревшее состояние», «дубли» из §12.8
  пока не генерируются: из ловушек есть только невалидные команды (нет устройства/комнаты).
* Числовые сообщения CASAS (0–100 у части домов, смысл не описан) в день не попадают.
* Одна кофемашина, одна розетка, один пылесос на дом; цвет «голубой» MASSIVE отождествлён с blue.
* Жители CASAS — пожилые люди, логи колонок Bentley — 2015–2019 гг.: это прокси нагрузки (оговаривается в ПЗ).
