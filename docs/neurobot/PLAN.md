# План: робот NeuroChip «помахал — поехал» + агент сверху

Срез: 14.10.2026; §13 — 15.10, статус шага W3 и решения студента по повторной приёмке — 19.10 (§13.5, §13.6).
Основание — `ANALYSIS.md` и `research/R1–R7`.

За основу взят вариант B: рефлекс на борту в графе ROS 2, событийный агент над ним. Прививки:
- **из A:** быстрый ремонт кода лаборатории — первым; страж с явным нулём; сторож PicoClaw по журналу; RUNBOOK;
- **из C:** место замыкания контура как переменная ВКР; odom_stall; «no data» для заднего сектора; сброс свойства gesture после события; совместимые имена инструментов; разбиение на фазы;
- **от скептика:** сначала журналы с робота; жесты принимаются только на стоящем роботе; задний ход ограничен; эпизод жеста определяется по движению руки; правки распознавания под флагами; проба живости PicoClaw — не ходом LLM.

Фатальные изъяны вариантов сняты: twist_mux не используется как средство остановки, рефлекс не идёт через rosbridge.

## 0. Коротко

- **Три опоры:**
  1. рефлекс «жест → движение» замыкается на роботе, без LLM, MCP и rosbridge;
  2. у `/cmd_vel` один писатель с явным нулём;
  3. каждый компонент — отдельный процесс под systemd, живость определяется по прогрессу.
- Агент (PicoClaw лаборатории или наш EdgeCtx) работает сверху через MCP по HTTP: получает события, отдаёт команды уровня задачи. На жест — 0 вызовов LLM.
- **Порядок:** факты с робота → стенд и базовая линия → быстрый ремонт (пакет 1 через ≈8,5 рабочего дня) → целевая архитектура (пакет 2 через ≈19,5 д) → эксперименты ВКР, только после согласования с руководителем. Всего ≈29 рабочих дней, опции — ещё 2–3.
- Ключ RouterAI не тратим, везде `bench/mockllm`. Задержки на стенде — ориентир, итоговые цифры даёт только HIL на роботе.

## 1. Цель и критерии готовности

**Цель лаборатории:**
- помахали — робот поехал без заметной задержки;
- работает часами без ручных перезапусков;
- безопасно останавливается;
- агент понимает команды и отвечает о состоянии, но не стоит в контуре жеста.

| # | Критерий | Сейчас | Цель | Как проверяем | Статус числа |
|---|---|---|---|---|---|
| K1 | t0 (конец жеста) → первая ненулевая `/cmd_vel`, p95 | ≈1,6–1,8 с [оценка] | стенд ≤ 0,5 с при темпе детекции, как на Jetson; робот ≤ 0,6 с — предварительно, фиксируем в PROTOCOL после замера цикла на Jetson | наблюдатель, ≥ 200 жестов на условие | стенд — ориентир, HIL — результат |
| K2 | t0 → начало движения (\|v\| > 0,05 м/с) | неизв. | K1 + ≤ 0,3 с | /odom, ground_truth | то же |
| K3 | Непрерывная работа | «после пары использований» | стенд: 8 ч с расписанием отказов, 0 видимых перезапусков; робот: 1–2 ч HIL без вмешательства человека | журнал супервизора + наблюдатель | — |
| K4 | Вызовы LLM | 0 у демо, 2 на жест через PicoClaw | 0 на жест; «проехать 0,5 м» ≤ 2 вызова | счётчики mockllm/llmtap | результат (структурный счётчик) |
| K5 | Время восстановления (TTR) компонентов | ручной перезапуск | таблица §5.2 | инжектор отказов | стенд — ориентир |
| K6 | Безопасная остановка | молчание вместо нуля | 0 эпизодов «едет без свежей команды > 0,5 с» при отказе любого компонента, кроме самого писателя; stop через MCP → ноль ≤ 100 мс (p95); препятствие → ноль ≤ 150 мс после скана; отказ самого писателя → остановка ≤ 0,5 с только при таймауте в мосте или STM32 (вопрос №1) | stm32_sim с таймаутом 0 и 300 мс | — |
| K7 | Ложные действия | turn180 на «немую» SNN | 0 движений по «не распознано»; порог ложных манёвров в час на отрицательных сценариях — после записей лаборатории | gesturegen | — |
| K8 | Ресурсы | — | наклон PSS ≤ 1 МиБ/ч на наш процесс за 8 ч; дрейф p95 ≈ 0 | sysmon, harness/stats.py | только T2 |
| K9 | Запуск | «есть проблемы с запуском» (со слов лаборатории) | холодный старт: 100 из 100 успешных подъёмов всего стека в заданном порядке, время до готовности ≤ T (T фиксируем после замера на стенде, на роботе — HIL); при неудаче `neurobot doctor` называет компонент и причину | `start_test` на стенде: 100 циклов «старт → doctor → жест → стоп»; плюс старт с заранее «сломанным» компонентом | стенд — ориентир, HIL — результат |

**Видимый перезапуск** (определение из R6, предрегистрировать). Перезапуск видим, если случилось хотя бы одно:
- валидный жест не получил верной реакции за 3 с от t0;
- движение оборвалось на середине команды;
- система была недоступна дольше интервала между жестами;
- понадобился человек.

Остальные перезапуски невидимы. Непрерывность — **ограничение, а не цель ВКР**.

## 2. Целевая архитектура

### 2.1. Принципы

1. **Два контура.** Быстрый — на роботе: ROS 2 по DDS, только localhost. Медленный — агент через MCP.
2. **Один писатель `/cmd_vel`** — `motion_executor`. Явный ноль при старте, выходе, препятствии, отмене и по deadman. twist_mux не используем: ноль он не публикует (ANALYSIS §4).
3. **Жесты распознаются, только когда робот стоит.** Камера стоит на роботе: при повороте 1 рад/с сцена проходит поле зрения D435i (≈70°) примерно за 1,2 с [оценка], и траектория бокса превращается в мусор. Движение прерывают stop от любого источника, лидар и агент.
4. **Эпизод жеста определяется по движению руки:**
   - начало — рука движется (k из n кадров);
   - конец — рука ушла или остановилась (END_GAP 0,3–0,6 с);
   - окно ≤ 3 с, нужна минимальная длина пути.

   Неподвижная рука эпизода не начинает.
5. **«Не распознано» вместо класса 0.** Нормировка и полилиния — под флагами; по умолчанию остаётся путь лаборатории (torch-SNN, их предобработка).
6. **Каждый компонент — отдельный процесс под systemd.** Живость — по прогрессу. Дешёвое восстановление внутри процесса идёт раньше рестарта.
7. **Агент не публикует скорости.** Пределы проверяются дважды: в robot-mcp и в исполнителе (защита от «уговорённой» LLM, RoboPAIR).

### 2.2. Схема

```

┌────────────────────────────────────────────────────────────────────────────────────────────┐
│ D435i ─USB─► [perception] predict_live v2 = код лаборатории + наш патч, --mode gesture      │

│              pub /neurobot/gesture, /neurobot/perception_health; sub /neurobot/motion_state  │
│                      ▼                                                                      │
│ [motion_executor] (наш, rclpy, Python 3.8) — ЕДИНСТВЕННЫЙ писатель /cmd_vel                  │
│   входы: /neurobot/gesture (рефлекс по таблице), /neurobot/task (задачи агента), /scan, /odom │
│   автомат 20 Гц: drive / turn / stop / манёвры; stop > препятствие > текущая задача         │
│   deadman; ноль при старте, выходе, препятствии, отмене; задний ход ограничен               │
│   pub /cmd_vel, /neurobot/motion_state, /neurobot/events                                    │
│                      ▼ /cmd_vel (Twist; на стенде — параметр)                                │
│ [мост /cmd_vel→UART лаборатории] → STM32 + L298N   (просьба: таймаут 300–500 мс в мосте)      │

└────────────────────────────────────────────▲───────────────────────────────────────────────┘
                                             │ одно постоянное WS (JSON/CBOR)
 [robot-mcp -profile base -compat neurochip] (наш, Go, статический) — MCP streamable HTTP :18110
   инструменты status / drive / turn / maneuver / stop / reflex / look
   + robot_get_status / robot_stop / robot_nudge; события gesture / task_end / alert
      ▲ tools/call + resources/updated            ▲ tools/call (событий не принимает)
 [EdgeCtx] (наш; гейт + правила)          [PicoClaw v0.3.1] ◄─ MQTT ◄─ мост тревог (pushfilter)
      └──────── HTTPS ───────► LLM: стенд — bench/mockllm (0 ₽); прод — RouterAI после разрешения
```

### 2.3. Темы и протоколы

Тип `std_msgs/String` с JSON и полем `seq` выбран сознательно: в rosbridge 1.3.1 нет actions, а свои msg-пакеты пришлось бы собирать под два дистрибутива.

| Тема | Тип | Пишет | Читает | Частота |
|---|---|---|---|---|
| `/cmd_vel` | Twist (Foxy) или TwistStamped (параметр) | только executor | мост STM32 / gz | 20 Гц в движении, нули 10 Гц в покое |
| `/neurobot/gesture` | String JSON {boot, seq, cls, name, conf, spikes, margin, side, n_boxes, t_end, t_rec} | perception | executor, robot-mcp, наблюдатель | на жест |
| `/neurobot/perception_health` | String JSON {fps, frame_age_s, recoveries, state} | perception | executor, robot-mcp | 1 Гц |
| `/neurobot/task` | String JSON {seq, op: drive\|turn\|maneuver\|stop\|reflex, args, by: llm\|rule\|user, preempt} | robot-mcp | executor | по команде |
| `/neurobot/motion_state` | String JSON {boot, moving, task, by, reflex, blocked_front, last_gesture} | executor | perception, robot-mcp | 2 Гц + при изменении |
| `/neurobot/events` | String JSON {seq, type: task_end\|alert, …} | executor | robot-mcp | на событие |
| `/scan`, `/odom` (если есть) | LaserScan, Odometry | драйверы | executor; robot-mcp (сводка 1 Гц, CBOR) | 10 Гц / — |

| Звено | Протокол |
|---|---|
| perception ↔ executor ↔ драйверы | ROS 2 DDS, localhost |
| robot-mcp ↔ граф | rosbridge v2, одно WS, JSON/CBOR, 127.0.0.1:9090 |
| агенты ↔ robot-mcp | MCP streamable HTTP 127.0.0.1:18110 |
| тревоги → PicoClaw | MQTT `/picoclaw/<agent>/robot/request` через фильтр |
| агент ↔ LLM | HTTPS, OpenAI-совместимый API |

### 2.4. motion_executor (наш)

- **v1 (этап 2) — страж.** Входы `/cmd_vel_gesture` (ремап демо) и `/cmd_vel_agent` (имя темы задаётся конфигом MCP лаборатории).
  - Нулевой Twist от жестов не считается заявкой: демо в покое шлёт нули 10 Гц.
  - Свежая ненулевая команда агента главнее команды жеста.
  - Вход старше 0,4 с → явный ноль.
  - Вперёд запрещено, если в секторе ±30° (по `angle_min`/`increment`) ближе d_stop или `/scan` старше 0,5 с; повороты разрешены.
- **v2 (этап 3) — исполнитель задач.** Около 500 строк, Python 3.8, Foxy и Jazzy.
  - Примитивы drive, turn, stop — по `/odom`, если он есть, иначе по времени с калиброванной скоростью.
  - Программы лаборатории (turn180, come, go_left/right, think, back) — таблица в конфиге.
  - Одна задача за раз. Stop от любого источника отменяет её за ≤ 1 тик (50 мс). Задача агента во время манёвра жеста получает `busy`, если не задан `preempt`.
  - Препятствие → ноль сразу, `task_end{blocked}`.
  - Задний ход: ≤ 0,2 м и ≤ 0,05 м/с (параметр, можно запретить).
  - Жесты старше 0,5 с и с повторным `boot+seq` отбрасываются.
  - `odom_stall`: команда ≠ 0, а |v| ≈ 0 в течение 1 с (только при наличии `/odom`).
  - Конфиг `/var/lib/neurobot/config.json` пишется атомарно. READY — после первого нуля, WATCHDOG — от тика.

### 2.5. perception = predict_live v2 (код лаборатории + наш патч)

- Поставляется как `.patch` к ветке ros2_feature и копия в `neurobot/perception_v2/`; `third_party/` не трогаем. Совместим с Python 3.8. Каждое изменение привязано к id из ANALYSIS.
- **Режимы:**
  - `--mode legacy` (этап 2): свой DriveController пишет в `/cmd_vel_gesture` (ремап `--ros-args -r`, проверить на стенде);
  - `--mode gesture` (этап 3): только `/neurobot/gesture`, DriveController выключен.
- **Включено по умолчанию:**
  - R1: `try_wait_for_frames`, лесенка восстановления;
  - R2: `hardware_reset` при старте, порядок завершения;
  - R3: локальный yolov5@725b922e без сети, конечные попытки;
  - R4: загрузка до compile, `weights_only`, падение при ошибке;
  - R5/R6: `--headless`, logging в stderr;
  - R7, R8: сектор лидара по углам;
  - L1/G3/G4: END_GAP (по умолчанию 0,5 с) + окно 3 с + мин. длина пути + ограниченный буфер + очистка всегда;
  - G1: «не распознано»; G2: зерно / K=5;
  - L2, L3, S1–S3: в режиме legacy;
  - sd_notify по приросту кадров; `/neurobot/perception_health`; пауза детекции в движении.
- **Под флагами, по умолчанию выключено:** нормировка холста, полилиния, G5, сегментатор «рука остановилась».
- SNN по умолчанию работает на torch, как у лаборатории. Numpy-порт — только инструмент сверки с дампами `spikes_out`.

### 2.6. robot-mcp, профиль base (наш Go-модуль)

**Общее.**
- Статический linux/arm64 ≈9,5 МБ, Python на роботе не нужен.
- Транспорт streamable HTTP 127.0.0.1:18110; stdio — только для тестов; логи в stderr.
- Одно WS к rosbridge (готовый клиент), CBOR.
- `Actions` пустой: отмены Nav2 нет.
- `cmd_vel_type` — параметр (сейчас TwistStamped зашит в `robot.go:79, 240, 866`).
- Если при `stop()` состояние исполнителя старше 0,5 с, robot-mcp сам публикует **только ноль** в `/cmd_vel`.

**Инструменты.** Каталог ≈250–320 токенов [оценка].

| Инструмент | Что делает |
|---|---|
| `status()` | ≈50–60 токенов: motion, task, by, reflex, free_m{front, left, right, back:"no data"}, last_gesture{name, age_s}, camera{state, fps}, alert |
| `drive(distance_m ∈ [−0,2; 1], speed?, wait?)` | → {accepted, task, eta_s}; итог `task_end{moved_m, stopped_by}`; `wait=true` — для PicoClaw |
| `turn(angle_deg ∈ [−180; 180], wait?)` | то же для поворота |
| `maneuver(name ∈ таблица, wait?)` | программа лаборатории как задача |
| `stop(reason?)` | сразу, вне очереди |
| `reflex(enabled?, map?{class → maneuver\|none}, min_conf?)` | так «по запросу связываются камера и мотор» |
| `look(image=false)` | сводка детектора; JPEG — опция |
| `robot_get_status`, `robot_stop`, `robot_nudge` | псевдонимы лаборатории: nudge ≤ 500 мс, ≤ 0,08 м/с через исполнитель |

**Ресурсы:**
- `robot://inventory` — пределы, классы, манёвры;
- `robot://state/robot` — подписка, `_meta.state` ≈44–60 токенов;
- `robot://diag` — счётчики, не для LLM.

**События** (`notifications/resources/updated`):
- `gesture{seq, name, conf, action, by: reflex}` — после события свойство сбрасывается в none, поэтому два одинаковых жеста подряд дают два события;
- `task_end{task, by, status}`;
- `alert{obstacle, camera_lost, camera_back, slow_detector, odom_stall, executor_offline, rosbridge_down}`.

**Пределы** 0,15 м/с, 0,8 рад/с, 1 м за вызов — заглушки до ответа лаборатории.

**Тесты:** fakebridge с кинематикой Twist→/odom; дымовой тест против rosbridge 1.3.1 (контейнер Foxy, загрузка — с разрешения).

## 3. Путь «жест → движение» и бюджет задержки

| Шаг | Демо сейчас | Цель | Основание |
|---|---|---|---|
| 1. Определён конец жеста (Δ_end) | 1,5 с + до 1 цикла | 0,3–0,5 с (END_GAP подбирается в 0,3–0,6 по доле разорванных жестов) | [оценка]; параметр конструкции — главное узкое место |
| 2. YOLO кадра, подтверждающего конец | 60–110 мс | так же; TensorRT FP16 ≈47–70 мс — опция | [оценка]; форум NVIDIA, Seeed [ист.] |
| 3. Предобработка + SNN | 10–30 мс (torch на Nano) | так же; K=5 добавляет ≤ 30 мс | [оценка] |
| 4. `/neurobot/gesture` → колбэк исполнителя | ≈0 (очередь в процессе) | ≈1 мс (DDS localhost) | [оценка], мерится наблюдателем |
| 5. Первый Twist | 0–100 мс (таймер 10 Гц) | < 1 мс, сразу в колбэке | [код] |
| 6. Мост → UART → STM32 | неизв. | неизв., 5–30 мс | вопрос лаборатории |
| 7. Разгон до \|v\| > 0,05 м/с | неизв. | 50–300 мс; в Gazebo ≈50 мс + квант /odom 20 мс | [оценка] |
| **Итого t0 → /cmd_vel** | **≈1,6–1,8 с** | **≈0,37–0,67 с** | цель робота p95 ≤ 0,6 с достижима при END_GAP ≤ 0,4 с или с TensorRT; окончательно — после замера цикла на Jetson |

Остановки:
- stop → ноль за ≤ 1 тик (50 мс);
- препятствие → ноль ≤ 150 мс после скана [оценка].

Путь агента — не рефлекс:
- реплика → LLM (TTFT 0,68–0,82 с [ист.]) → drive → движение ≈1,2–2,5 с с живой моделью [оценка; ROSClaw 1,3–2,3 с/ход]; на mockllm ≈0,1 с;
- «0,5 м» — 2 вызова и ≈415 токенов против 13–17 вызовов и 15,9–26,2 тыс. токенов у nudge [оракул].

Метки на одних часах ВМ sim: t0 (истина gesturegen), t_rec, t_pub, t_exec, t_cmd (`/cmd_vel` у наблюдателя), t_motion (`/odom`, `/ground_truth/pose`).

## 4. Роль агента

**Агент делает:**
- команды уровня задачи («проедь 0,5 м», «развернись», «стоп»);
- настройку рефлекса (`reflex`: включить или выключить, переназначить жесты);
- ответы о состоянии («что впереди?», «камера в порядке?»);
- объяснение тревог и сводки по запросу.

**Агент не делает:**
- не стоит в контуре жеста;
- не получает каждый жест в LLM;
- не публикует скорости;
- не видит кадров по умолчанию;
- не перезапускает компоненты.

**PicoClaw** — интерфейс лаборатории, меняется только конфиг.
- MCP `type: http`; `max_tokens` 1024; `request_timeout` 20; `max_llm_retries` 1; `max_tool_iterations` 6–8; `max_parallel_turns` 2.
- Лишние встроенные инструменты выключены (15 → ≈7 [оценка]); `hot_reload` выключен, `/reload` не используем.
- **Как узнаёт о событиях:**
  - drive и turn с `wait=true` — итог приходит в ответе инструмента;
  - тревоги — MQTT-мост, не чаще 1 раза в 30 с на тип, по умолчанию выключен;
  - жесты не отправляются.

**EdgeCtx** — наш агент для ВКР.
- Подписка `robot://state/robot`. Гейт: `gesture by=reflex` — без пробуждения LLM (только контекст и счётчики); `alert` — пробуждение safety с cooldown; `task_end` задач LLM — пробуждение. Правила без LLM (например, `camera_lost` дольше 30 с → notify).
- Нужна правка `_meta edgectx/by` в CallTool, ≈10 строк в `host.go:569–587`.
- Вариант L2 для эксперимента: рефлекс исполнителя выключен, правило `gesture eq X → maneuver(X)` с `debounce_s: 0`.
- Опция: компилировать такое правило в `reflex(map)`.

## 5. Непрерывность

### 5.1. Супервизия (systemd)

| Юнит | Type | WatchdogSec | Restart / RestartSec | Готовность |
|---|---|---|---|---|
| rosbridge | simple | — | always / 1 | ExecStartPost: ждать порт 9090 |
| executor | notify | 3 с (от тика 20 Гц) | always / 0,5 | READY после первого нуля |
| perception | notify | 5 с (только при новом обработанном кадре) | always / 1 | READY после прогрева YOLO+SNN |
| robot-mcp | simple | — | always / 1 | ExecStartPost: проба status |
| edgectx / picoclaw | simple | — | always / 2 | After=/Requires= robot-mcp |
| watchdog.timer | — | — | каждые 10 с | — |

`After=`/`Requires=` задают только порядок, готовность обеспечивают READY и ExecStartPost. На Ubuntu 20.04 нет `RestartSteps` (появился в systemd v254) — проверить `systemctl --version`.

### 5.2. Обнаружение и восстановление (TTR — [оценка], мерим)

| Компонент | Как обнаруживаем | Действие | TTR | Рефлекс |
|---|---|---|---|---|
| Камера: нет кадра или замороженный кадр | `try_wait_for_frames(1000)` ×3, хеш/возраст кадра | рестарт конвейера → `hardware_reset` + 3 с → сброс USB-порта (unbind/bind или uhubctl) → `exit(1)` | 1–8 с без рестарта процесса | пауза; робот стоит |
| perception завис или упал | нет WATCHDOG 5 с / выход | SIGABRT → рестарт | 5–40 с (инициализация CUDA ≈1 ГиБ; мерить на HIL) | видим, если пришёлся на жест — считаем |
| executor | WatchdogSec 3 с | рестарт, ноль при старте | ≈1–2 с | стоит; если STM32 держит команду — едет до рестарта (вопрос №1) |
| rosbridge | robot-mcp видит обрыв | Restart=always, переподключение | ≈2–5 с | не затронут |
| robot-mcp | проба status с таймаутом 3 с раз в 10 с | рестарт; PicoClaw переподключается сам (≤ 1 ошибка), EdgeCtx — сам | ≈1–2 с | не затронут |
| EdgeCtx | systemd | рестарт; правила в SQLite | секунды | не затронут |
| PicoClaw | журнал (`All MCP servers failed`, `connection closed`, `invalid trailing data`, вызов без завершения > 60 с) + процесс | рестарт; сессии на диске | секунды паузы диалога | не затронут |
| Сеть к LLM | таймаут 20 с, 1 повтор | — | — | не затронут |
| `/scan` пропал > 0,5 с | возраст скана | вперёд запрещено, alert | — | частично |
| База / мост | odom_stall | alert, стоп | — | — |

Проба живости PicoClaw — не ход LLM. Пробная реплика допустима не чаще раза в 30 мин, только на mockllm, и в метрики не входит.

### 5.3. Состояние и ресурсы

- **Состояние:**
  - `config.json` исполнителя (таблица рефлекса, пределы), правила EdgeCtx в SQLite, сессии PicoClaw на диске;
  - после рестарта манёвр не возобновляется, робот стоит;
  - устаревшие жесты отбрасываются.
- **Ресурсы:**
  - очереди и буферы ограничены;
  - лимиты journald;
  - кадры в `/tmp` не пишем;
  - сервисы rosbridge в цикле не вызываем (#774 на Foxy);
  - вентилятор, nvpmodel, журнал tegrastats; alert `slow_detector`.

### 5.4. Запуск (со слов лаборатории — есть проблемы с запуском)

Присланная версия ros_mcp_server может быть устаревшей (со слов лаборатории), поэтому на её детали не завязываемся: наш robot-mcp работает напрямую с темами ROS, имена берутся из конфига. Актуальную версию и рабочий конфиг запрашиваем (ANALYSIS §5, п. 3).

- **Одна точка входа:** `neurobot.target` (systemd) поднимает всё. Ручные `python3 …` в нескольких терминалах не используем.
- **Порядок по готовности, а не по `sleep`:**
  1. драйверы (`urg_node`, мост STM32);
  2. executor — READY после первого нуля в `/cmd_vel`;
  3. perception — READY после прогрева YOLO+SNN и первого кадра;
  4. rosbridge — ждём порт;
  5. robot-mcp — проба `status`;
  6. агент.

  Каждый следующий стартует только после READY предыдущего (`Type=notify`, `ExecStartPost`-проба). Если зависимость не поднялась за таймаут, юнит падает с понятной причиной, а не висит.
- **Проверки перед стартом** (`ExecStartPre`, быстрые):
  - камера видна на USB;
  - веса на месте, хеши сходятся;
  - нет второго экземпляра, свободны порты;
  - `/cmd_vel` никто больше не пишет;
  - конфиги проходят проверку схемы.
- **`neurobot doctor`** — одна команда «всё ли поднялось». По каждому компоненту: состояние юнита, READY, прогресс (кадры/с, тики executor, возраст скана), соединения (rosbridge ↔ robot-mcp ↔ агент), последние ошибки из журнала. Печатает «ОК» или конкретную причину и что сделать (ссылка на RUNBOOK).
- **Проверка на стенде:** `start_test` — 100 циклов «холодный старт → doctor → один жест → stop → остановка всего» на чистом состоянии. Отдельно — старт с заранее сломанным компонентом (нет камеры, нет весов, занят порт, rosbridge не поднялся): doctor должен назвать именно его. Время до готовности и доля успешных стартов — в отчёт (K9).

## 6. Стенд (Gazebo и ВМ)

**Размещение.**
- **ВМ sim («робот»), профиль `--profile neurobot`:**
  - копия TB3 waffle_pi с лидаром как у URG-04LX: 240°, ≈683 луча, 0,02–4 м, 10 Гц;
  - мост `cmd_vel` = Twist;
  - камера Gazebo выключена (RTF ≈0,99 против 0,68 с камерой);
  - исправлен `odom_publish_frequency` (сейчас `--odom-hz` не работает);
  - `/ground_truth/pose` 50–100 Гц;
  - мир `lab_wall`: стена в 1,5 м и препятствия;
  - `stm32_sim` с таймаутом 0 мс (держит последнюю команду — худший случай) или 300 мс.

  Здесь же, на одном DDS, как на роботе, работают rosbridge, executor, perception (под подставными модулями, torch CPU) и наблюдатель. cgroup-квота задаётся под Nano и калибруется после HIL.
- **ВМ sbc («плата агента»):** robot-mcp, EdgeCtx, PicoClaw, mosquitto, sysmon.
- **Mac:** mockllm (оракул + логнормальная модель задержки по TTFT — помечать «модель»), gesturegen, toxiproxy.

**Источники жестов:**
- **(a) основной:** gesturegen → FakeYolo (bbox-JSONL с seed). Формы классов взяты по зондированию R1 до ответа лаборатории. Есть отрицательные сегменты: рука стоит, проход человека, ложные боксы. Темп детекции как у Jetson: 9–16 к/с [оценка] до замера;
- **(c) опция:** видео или rosbag лаборатории → YOLO в ONNX CPU (конвертация один раз, в изолированной ВМ офлайн, с разрешения);
- **(b)** веб-камера Mac — только для демонстрации;
- **(d)** актёр Gazebo — не используем.

**Базовая линия A0** — «демо как есть»: подставные pyrealsense2 (темп, режимы отказа) и FakeYolo, скрытый `torch.compile`, `weights_only`, Xvfb, симлинк `/home/jetson`. Все отклонения пишутся в `manifest.deviations`.

**Инъекция отказов:**
- камера: задержка > 5 с, RuntimeError, замороженный или чёрный кадр;
- kill -9 и SIGSTOP каждого процесса;
- рестарт и задержка rosbridge (toxiproxy, netem);
- ошибки и задержка mockllm;
- `/reload` PicoClaw;
- пропадание `/scan`;
- стена на пути `come`.

Для каждого отказа фиксируем TTD, TTR, потерянные жесты, видимость перезапуска и «опасное движение».

**Валидность:**
- задержки, CPU и наклоны памяти — только в реальном времени (T2) и при RTF ≥ 0,95;
- счётчики валидны в любом режиме;
- часы — наблюдатель в ВМ sim; между ВМ — через `/rosapi/get_time`;
- ≥ 200 жестов на условие, p50/p95/p99, блочный бутстреп.

**Что стенд НЕ доказывает:**
- времена на Jetson, тепло;
- реальные сбои USB/RealSense: лесенка проверяется только на подставном модуле;
- STM32.

Минимальный HIL у лаборатории:
- 200 жестов с разбивкой по стадиям;
- тишина `/cmd_vel` → реакция STM32;
- 1–2 ч непрерывной работы с журналами;
- rosbag: 5–10 жестов каждого класса.

## 8. Что НЕ делаем и почему

- **LLM в контуре жеста.** Это ≥ 2 вызова и секунды на событие по построению, деньги, риск джейлбрейка (RoboPAIR).
- **Не патчим PicoClaw.** По правилам ВКР это аналог; апстрим закрывает исправления надёжности без слияния.
- **Не чиним ros_mcp_server глубоко** (кроме ≤ 20 строк Э2). Беда архитектурная: LLM внутри цикла движения. Заменяем его robot-mcp base с совместимыми именами — лаборатория допускает MCP по нашему образцу (со слов студента).
- **twist_mux как средство остановки** — ноль не публикует.
- **Nav2, AMCL, карты** — у робота их нет; в rosbridge 1.3.1 нет actions.
- **Не переобучаем YOLO и SNN.** Нормировку и полилинию не включаем по умолчанию до A/B на записях. Numpy-SNN не ставим в рабочий путь до сверки с torch.
- **Не исполняем `yolo_hand.pt`** вне изолированной офлайн-ВМ.
- **Не распознаём жесты в движении** и не возобновляем манёвр после рестарта.
- **Без горячего резерва распознавателя** — на Nano 4 ГБ не поместится [оценка].
- **Без актёра Gazebo и без рендера камеры.**
- **Не тратим ключ RouterAI.** Не переводим робота на новый стек сами — это предложение лаборатории.
- **Не выдаём задержки стенда за результат.** Не делаем надёжность целью ВКР.

## 11. Что дать лаборатории

**Сразу, без кода:**

## 12. Что пойдёт в ВКР

**Эксперименты.**
- **E1 «до».** A0 (демо как есть + MCP лаборатории по stdio + PicoClaw), 2 ч с отказами. В ПЗ подаётся как «воспроизведённый механизм отказа», а не «частота сбоев у лаборатории»: отказы вносим мы.
- **E2 — место замыкания контура.**
  - Варианты на одном потоке жестов:
    - L0 — демо;
    - L1 — рефлекс исполнителя;
    - L2 — правило EdgeCtx;
    - L3 — LLM на жест (PicoClaw через MQTT или пробуждение EdgeCtx).
  - Мерим: задержку по стадиям, вызовы и токены LLM на жест, CPU и PSS.
  - Задержка L3 — модель mockllm, это не замер RouterAI.
- **E3 — рабочий день 8 ч** (T2, ночью): S+EdgeCtx против S+PicoClaw в лучшем конфиге.
  - Нагрузка: жесты 1–4 в минуту, запрос пользователя раз в 10 мин, отказы по расписанию.
  - Мерим: вызовы, токены, ₽ (costmodel, без трат) в час; наклоны PSS; дрейф p95; трафик; соединения и RSS rosbridge; рестарты и TTR.
- **E4 — агентские задачи** («0,5 м», «развернись», «что впереди?»): nudge лаборатории против drive. Мерим вызовы, токены, время, WS-соединения.
- **E5 (опция) — лестница ограничений** для perception: FPS, задержка, точность (H7).
- **E6 — HIL.**

**Гипотезы.**
- **Новая H8** — место замыкания контура. Предрегистрируем: L1 и L2 — 0 вызовов LLM на жест (структурный счётчик); L2 − L1 ≤ 20 мс на стенде [оценка]; L3 ≥ 2 вызовов на жест. Пороги задержки для робота — после замера на Jetson.
- **Расширения:** H1 (события вместо опроса — гейт EdgeCtx против MQTT-пуша PicoClaw), H4 (память во времени), H6 (задачи и сводки вместо толчков и сырых тем).
- Гипотезы «доступность ≥ 99 %» **нет**: непрерывность — условие допуска, а матрица отказов — приёмочный тест для лаборатории и в ПЗ даётся кратко.

**Новизна** формулируется осторожно: «в проверенных источниках не найдено» MCP-серверов для ROS с замерами реального времени и непрерывной работы. Двухуровневая схема (Helix, GR00T N1, SayCan) — известная, своей её не называем.

Предлагаемое решение для DECISIONS (записать после согласия студента и руководителя): сценарий «мобильный робот» в ВКР — это робот NeuroChip на стенде neurobot и HIL. Профиль Nav2 в robot-mcp становится второстепенным.

### 13.3. Безопасность v2 («чтобы ничего не пострадало»)

Слои защиты, от железа к агенту:
- **L0 — железо** (рекомендации лаборатории): кнопка аварийной остановки; предохранитель есть; проверить `cmd_vel_timeout` в `diff_drive_controller` на роботе.
- **L1 — контроллер:** пределы скорости, ускорения и рывка в `diff_drive_controller`. Мачта высокая, рывок опасен опрокидыванием.
- **L2 — наш `safety_gate`:** отдельный процесс, Python 3.8, единственный писатель `/cmd_vel`. Исполнитель выдаёт желаемую скорость, `safety_gate` пропускает, урезает или обнуляет. Проверки:
  - тормозной путь от края корпуса, а не от оси лидара: d = v·t_задержки + v²/(2·a_торм) + запас;
  - NaN и «нет данных» лидара в секторе остановки — запрет движения вперёд. Статическую маску слепых лучей (корпус камеры) узнаём при старте;
    **отступление (решение студента 19.10, §13.6 п. 2а):** «нет данных» на участке, который камера глубины не видит
    (у корпуса слева-спереди, дальше ≈25° от курса), — не запрет, а «не быстрее 0,15 м/с» (`nodata_unseen=slow`), как
    слепой сектор корпуса камеры справа; полный отказ лидара («весь скан неизвестен») — стоп `lidar_fault`. Цена
    записана: предмет, не отражающий лазер (стекло, чёрный бархат), слева-спереди вне поля камеры — робот едет к нему
    0,15 м/с. Строгое правило буквы — `nodata_unseen:=block`;
  - камера глубины: препятствия на пути ниже плоскости лидара (низкие предметы, ножки, нависания) и «пропал пол» (обрыв) по уменьшенной карте глубины в системе базы;
  - IMU: наклон больше порога или удар (всплеск ускорения) — стоп с защёлкой;
  - пробуксовка или упор: команда есть, а движения по одометрии нет больше 1 с — стоп с защёлкой (бережём моторы и драйвер);
  - пределы скорости и ускорения, максимальное время непрерывного движения, «геозабор» вокруг точки старта;
  - блокировка старта: пока все датчики не свежие и исправные — не ехать. Если есть издатели `/cmd_vel_joy` и `/cmd_vel_tracker`, они выше нас по приоритету в `twist_mux` — предупреждение или отказ;
  - аварийная защёлка `/neurobot/estop`: ставят все, снимает только человек (CLI/doctor), не агент;
  - устаревшие входы — ноль; после рестарта движение не возобновляется.
- **L3 — агент:** инструменты MCP ограничены (≤1 м, ≤0,15 м/с); сырые скорости агенту не доступны; снять аварийную защёлку агент не может; единицы длительности проверяются, ошибка N1 «мс → с» закрыта ограничением сверху.

### 13.6. Решения студента по повторной приёмке 18.10 (приняты 19.10)

Проект текста и данные — `experiments/results/neurobot_20261018_acceptfix2/notes.md` §3; реализация и замер
решения 1а — `experiments/results/neurobot_20261019_decisions/` (`manifest.json`; артефакты — локально). Оба решения
студент принял 19.10 окончательно. Все числа — [замер на двойнике], ориентир стенда, не результат робота.

1. **K6, stop через MCP — принят вариант (а): `robot_stop` агента — стоп по безопасности, мгновенный.** Ноль в
   `/cmd_vel` ≤ 100 мс (p95), без S-кривой. Аварийная защёлка не ставится: это разовый стоп текущего движения, после
   него робот принимает новые команды как обычно. Критерий K6 в §1 не меняется — 1а его выполняет.
   - **Как сделано.** Инструмент `robot_stop` патча `ros_mcp_server` вместе с нулями в `/cmd_vel_agent` шлёт через
     rosbridge в `/neurobot/stop_now` (`std_msgs/String`, JSON `{id, by, reason, t}`, один `id` на вызов);
     safety_gate по нему сразу ставит ноль и снимает взвод: прежний манёвр сам не продолжается, даже если ноль
     агента не дошёл до исполнителя, а следующий нулевой запрос взводит снова. Исполнитель не менялся: ноль агента
     и так гасит манёвр жеста и отъезд. Автостоп в конце толчка агента и конец манёвра жеста остаются штатными,
     плавными. Тема — в `topics_glob` rosbridge; это единственный вход safety_gate, открытый агенту, и он умеет только
     остановить: пределы не трогает, защёлку не ставит и не снимает, а взвод только снимает (взводит снова лишь нулевой запрос). Отдельная тема, а не флаг в существующем входе: у Twist нет
     поля под флаг (а своё сообщение — сборка пакета на Foxy), стоп идёт в safety_gate одним переходом и не зависит
     от живости исполнителя, порядок с нулями агента не важен.
   - **Замер 19.10** (`verify/k6.py`, n = 30, мир hall, курс 90° — как серия 18.10): ноль в `/cmd_vel` через 1,9 /
     2,7 мс (p50 / p95; наибольшее 53 мс — первый вызов после старта сервера, новое соединение), 30 из 30 ≤ 100 мс
     (18.10 при плавном стопе — 514 / 545 мс, 0 из 30); после стопа робот не поехал ни разу, хотя сценарий ещё 1,5 с
     просил ехать. Скан не ухудшился: ноль через 0,3 / 0,7 мс после скана со столбом, 30 из 30, касаний 0 (18.10 —
     0,4 / 0,7 мс).
   - **Удар по мачте** (`stop_shock`, мир lab, стоп с 0,15 м/с, отклонение `/camera/imu` от медленного среднего, как
     у safety_gate): стоп агента n = 10 — 3,17 / 3,72 м/с² (p50 / p95), наибольший 4,14 при пороге `shock` 6, ложных
     защёлок 0 из 10, выбег 0,7–1,8 см; в той же сессии резкая остановка (n = 4) — 3,18, плавная (n = 4) — 2,19 м/с²,
     защёлок 0. Цена: удар по мачте на каждом стопе агента; однажды (прогон `long` 16.10) резкая остановка дала
     6,1 м/с² и ложную защёлку `shock` — 18.10 и 19.10 этого не воспроизвели; на роботе порог — по записи
     `/camera/imu` (`neurobot/lab/LAB_HANDOUT.md`).
   - Вариант (б) — критерий «торможение ≤ 100 мс, ноль ≤ 0,6 с (p95)» — не принят (предложение исполнителя доводки
     18.10 было (б)).
2. **`nodata_unseen=slow` — принят вариант (а): осознанное отступление от буквы §13.3** (записано там же). Лидар «нет
   данных» вне поля камеры глубины (у корпуса слева-спереди, дальше ≈25° от курса) — не запрет, а «не быстрее
   0,15 м/с», как слепой сектор корпуса камеры справа; полный отказ лидара — стоп `lidar_fault`. Цена записана:
   предмет, не отражающий лазер (стекло, чёрный бархат), слева-спереди вне поля камеры — робот едет к нему 0,15 м/с;
   частичный отказ лидара в этом секторе. Цена строгого правила: в зале A1 16.10 — `blocked` 73–80 % времени, верных
   реакций 19 из 80; с правилом 18.10 — `blocked` 2–13 %, верных 37–44 из 80; участок вне поля глубины держал `slow`
   в комнате 5 × 5 м 4–7 % времени, в зале 9 × 9 м — 34–35 %. Строгое правило остаётся параметром
   (`nodata_unseen:=block`), по умолчанию — `slow`.
