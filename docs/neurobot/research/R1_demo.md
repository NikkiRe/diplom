## 0. Коротко (главное)

1. Вся логика — один процесс Python и три потока: главный (`rclpy.spin`: таймер 10 Гц публикует `/cmd_vel`,
   колбэк `/scan`), поток-демон «зрение» (камера → YOLO → карта траектории → SNN) и поток-демон «контроллер»
   (манёвры на `time.sleep`). Ни у одного потока нет `try/except` и контроля живости **[код]**.
2. **Главная причина «после пары раз надо перезапускать»:** любое исключение в потоке «зрения» (таймаут кадра
   RealSense `RuntimeError: Frame didn't arrive within 5000`, ошибка OpenCV/GUI, CUDA, `queue.Full`) молча
   убивает поток: процесс жив, окно застывает, робот больше не реагирует **[код `:595–668`]**. Таймауты кадров
   D435i на Jetson Nano — известная проблема **[источник S1–S3]**. После аварийного выхода RealSense может
   остаться «занятой» — нужен `hardware_reset()` или переподключение **[источник S4, S5]**.
3. **Вторая (по моим замерам на синтетике — вероятно, массовая) причина «ведёт себя странно»:** предобработка
   рисует боксы руки уменьшенными в 10 раз (`scale=0.1`, `:640`) и не нормирует яркость, картинка 28×28
   получается в 3–25 раз «бледнее» MNIST (средняя яркость 0,005–0,05 против ≈0,13); SNN часто не выдаёт ни одного выходного спайка, а `argmax` от
   нулей = класс 0 = «разворот на 180° на 7 с». На синтетических жестах доля «немых» выходов 7–88 % в
   зависимости от дистанции и FPS; исправленная предобработка (линия через центры боксов + нормировка) даёт
   0,87–1,00 верных классов **[замер, numpy-порт, §6.3]**. Плюс входные спайки случайные (`torch.bernoulli`) —
   один и тот же жест может дать разные команды **[код `:212`]**.
4. **Задержка «конец жеста → движение» ≈ 1,6–1,8 с** **[оценка]**, из них 1,5 с — жёсткий таймаут «рука пропала
   из кадра» (`:610`); пока рука в кадре, распознавания нет вообще. После команды робот «глух» 3–11 с
   (манёвры на `sleep`, отменить нельзя, `:398–454`).
5. **Безопасность:** при препятствии код **перестаёт публиковать** `/cmd_vel`, а не шлёт ноль (`:475`). В нашем
   Gazebo DiffDrive держит последнюю скорость (замер в `docs/robot_sim.md:373,407`) — робот поедет дальше.
   Остановится ли STM32 сам — неизвестно (вопрос лаборатории). При падении/выходе ноль тоже не шлётся.
6. **В нашем симуляторе (Jazzy + TurtleBot3) демо как есть не заработает:** `/cmd_vel` там `TwistStamped`, а не
   `Twist`; `/scan` — 360 лучей, а код читает индексы 166–515 → `IndexError` в колбэке → падение всего процесса
   (`:460`); жёсткие пути `/home/jetson/...`; `pyrealsense2` импортируется безусловно.
7. **Модели:** `yolo_hand.pt` — это **YOLOv5s** (а не yolov5n из yaml в репозитории), 1 класс `hand`,
   ≈7,0 млн параметров в FP16, обучен 03.10.2025 на Windows под Python 3.13 (ссылка на `pathlib._local.WindowsPath`),
   yolov5 commit `725b922e`, imgsz 256. `snn_emnist_small.pth` — чистый state_dict (только тензоры и словари):
   784→128 (bias) → 4 (без bias), Leaky beta=0,5, threshold=1, subtract; метаданные: `emnist`, split `balanced`,
   `fix_orientation=True`, `num_steps=25`. SNN перенесена в numpy: 0,33 мс на SNN + 0,22 мс на предобработку на M4 Pro
   **[замер]**; детерминированный режим возможен. YOLO → ONNX требует torch + исходники yolov5 на коммите `725b922e`
   (безопаснее — через статическое извлечение весов, §5.4).
8. **Классы жестов (поведенческое зондирование весов, не истина от авторов):** 0 — круглые формы (O, C, 0),
   1 — «угловатые» (V, N, M, 2), 2 — горизонтальный штрих (только «-»), 3 — вертикальный штрих (1, I, |, /)
   **[замер]**. Отсюда: «помахали рукой» по горизонтали → класс 2 → `go_left/right`, сторона — по первому и
   последнему боксу (для махания туда-обратно фактически случайна). Обучающего скрипта для этой сети в архиве нет.

## 2. Архитектура и поток данных

```
                      ПРОЦЕСС python3 predict_live.py (один узел ROS 2 "velocity_publisher")
 ┌──────────────────────────────────────────────────────────────────────────────────────────────┐
 │ ГЛАВНЫЙ поток: rclpy.spin(node)  (:699)                                                      │
 │   ├─ таймер 0,1 с → DriveController.send_twist_msg()  (:371–372, :456–486)                    │
 │   │      если НЕ is_obstructed: publish Twist(x·speed, th·turn) в /cmd_vel; иначе — НИЧЕГО     │
 │   └─ подписка /scan (LaserScan, глубина 1000) → process_lidar (:373, :459–467)                │
 │          for i in 166..515: если 0 < r ≤ 0,25 м → is_obstructed.set(), иначе .clear()         │
 │                                                                                              │
 │ Поток-демон «ЗРЕНИЕ»: VelocityPublisher.main_loop (:595–597, :602–668)                       │
 │   pipe.wait_for_frames() [RealSense 640×480 BGR 30 к/с, таймаут 5 с] (:615)                   │
 │   → cv2.flip (зеркало) (:619)                                                                │
 │   → YOLOv5s (torch.hub AutoShape, size=320, conf 0,35, iou 0,45, max_det 1, FP16 на CUDA)     │
 │   → write_bbox → список боксов этого кадра (0 или 1)                                          │
 │   → если робот стоит (is_standing): black_white_map += боксы; last_collected = now            │
 │   → если прошло >1,5 с без боксов И в карте ≥ 6 боксов:                                       │
 │        write_map_number: прямоугольники боксов (×0,1 от размера) на 256×256 (640×480 → 256×256)│
 │        → to_mnist_canvas: порог 20 %, обрезка, масштаб до 20 px, центр масс → 28×28 [0..1]     │
 │        → rate_encoding: torch.bernoulli, 25 шагов → SNN 784–128–4 (LIF) → mean → softmax → argmax│
 │        → pred 0..3 → put_cmd("turn180"|"come"|"go_left"/"go_right"|"think") в Queue(3)        │
 │   → cv2.imshow("bbox") полноэкранно + waitKey(1); 'q' → break (конец потока)                   │
 │                                                                                              │
 │ Поток-демон «КОНТРОЛЛЕР»: DriveController.main_loop (:494–512)                               │
 │   cmd = queue.get() → манёвр: выставляет self.x/self.th, is_standing.clear(), time.sleep(...), │
 │   stop(), is_standing.set()                                                                   │
 └──────────────────────────────────────────────────────────────────────────────────────────────┘
       /cmd_vel (geometry_msgs/Twist) ──► мост ROS→UART (не в этом репо) ──► STM32F103 + L298N
       /scan ◄── драйвер Hokuyo URG-04LX (не в этом репо)
```

Синхронизация **[код]**: `Event is_standing` (робот стоит/едет), `Event is_obstructed`, `Queue(3)` команд;
`self.x/self.th` пишет поток контроллера, читает таймер в главном потоке (без блокировки — возможна «рваная» пара
x/th на один тик 100 мс, например при `turn_right()` сначала ставится th, потом x).

Таблица манёвров **[код `:398–454`]** (скорости: `speed=0.5`, `turn=1.0`, т. е. `linear.x=±0,5`, `angular.z=±1,0`):

| Класс | Команда | Последовательность | Длительность «глухоты» |
|---|---|---|---|
| 0 | turn180 | вправо 7 с | 7 с (при 1 рад/с это ≈7 рад ≈ 401°, а не 180°, если единицы — рад/с) |
| 1 | come | вперёд 3 с | 3 с |
| 2, direction=0 | go_left | влево 3 с → вперёд 2 с → вправо 3 с | 8 с |
| 2, direction=1 | go_right | вправо 3 с → вперёд 2 с → влево 3 с | 8 с |
| 3 | think | вправо 2 → вперёд 2 → влево 5 → вперёд 2 | 11 с |
| — | back | назад 3 с | недостижима: ни один класс не ведёт к `back` |

`direction = 1`, если x1 первого бокса ≥ x1 последнего (`:327–328`), т. е. по крайним точкам, а не по
траектории.

## 3. Бюджет задержки «конец жеста → начало движения»

| Этап | Код | Время |
|---|---|---|
| Рука должна исчезнуть из кадра (или детектор перестать её видеть) | `:630–633` | зависит от пользователя; **если рука остаётся в кадре, распознавания нет никогда** |
| Таймаут «нет детекций» | `:610` | **1,5 с** (константа) |
| Таймер проверяется только в начале итерации → выравнивание фазы | `:609–613` | 0…1 × T_loop |
| Эта итерация ещё ждёт кадр и прогоняет YOLO, и только потом распознаёт | `:615–644` | 1 × T_loop |
| Предобработка + окно «before/after» + SNN 25 шагов | `:640–644`, `:217–228` | torch на Nano: ≈10–30 мс **[оценка]**; numpy-порт: 0,55 мс на M4 Pro **[замер]** |
| Очередь → поток контроллера | `:489`, `:497` | ≈0 |
| Квант таймера публикации `/cmd_vel` | `:371` | 0…100 мс (в среднем 50) |
| Мост ROS→UART→STM32→мотор | вне кода | неизвестно |
| **Итого после последней детекции** | | **≈1,5 + 1,5·T_loop + 0,05 с ≈ 1,6–1,8 с** **[оценка]** при T_loop ≈ 60–110 мс |

T_loop (кадр + flip + YOLOv5s FP16 на 320 + отрисовка + полноэкранный imshow) на Nano не измерен. Ориентиры:
YOLOv5s ≈16,5 GFLOPs при 640 **[источник S9]** → ≈3,3 GFLOPs при 320×256 **[оценка]**; Nano — 472 GFLOPS FP16
пиково **[источник S10]**; на форуме NVIDIA для YOLOv5s в PyTorch на Nano при 640 — ≈120 мс/кадр **[источник S8]**.
Отсюда T_loop 60–110 мс (9–16 к/с) — **оценка**, замерить на роботе (в коде есть закомментированные замеры `:623–626`,
`:643–645`).

Дополнительно воспринимается как «задержка» **[код]**:
- `MIN_FRAMES_TO_DETECT = 6` (`:41`): нужно ≥6 кадров с детекцией (≈0,4–0,7 с жеста при 9–16 к/с).
- После команды 3–11 с новые жесты не собираются (`:630`, `:657–658`), отмены нет.
- Первый жест после старта: прогрев CUDA/cuDNN; при torch ≥ 2.0 ещё и `torch.compile(mode="reduce-overhead")`
  (`:570–571`) компилирует SNN при первом вызове — секунды **[оценка]**.
- `namedWindow` + `setWindowProperty(FULLSCREEN)` на каждом кадре (`:662–663`) — лишняя работа GUI в цикле.
- Пауза руки >1,5 с посреди жеста (детектор потерял руку) режет жест на два — две ошибочные команды.
- Старт процесса: `torch.hub.load` каждый раз ходит на github.com (определяет ветку по умолчанию) **без таймаута**;
  без сети откатывается на кэш, но при «молчащей» сети ждёт системный TCP-таймаут **[источник S6; оценка ~2 мин
  для Linux по умолчанию]**. Видимый пользователю «перезапуск» — десятки секунд **[оценка]**.

## 4. Почему «после пары использований надо перезагружать»: все найденные причины

Ниже — кандидаты, отсортированные по моей оценке вклада. Что именно происходит на роботе, без логов не узнать;
см. вопросы §9.

| № | Причина | Доказательство | Как проявляется | Исправление |
|---|---|---|---|---|
| P1 | Поток «зрения» умирает от **любого** исключения, молча | `:595–597` демон без контроля; `:602–668` нет `try/except`; `:615` `wait_for_frames()` бросает `RuntimeError` по таймауту 5 с [S1–S3] | окно застыло, команды больше не идут, процесс «жив» (spin крутится), нужен ручной перезапуск | `try/except` вокруг итерации; при N таймаутах — `pipe.stop()/start()`, затем `hardware_reset()`; heartbeat-тема + сторожевой поток/процесс; лог исключения |
| P2 | Камера остаётся «занятой» после аварийного выхода/убийства процесса | сценарии в [S4, S5]; в коде нет `hardware_reset`, выход по Ctrl+C зовёт `pipe.stop()` во время `wait_for_frames` другого потока (`:673–677`) | следующий старт: «No device connected»/висит — помогает только переподключение или перезагрузка платы | при старте `hardware_reset()` + ожидание 2–5 с [S5]; корректное завершение потоков (сначала остановить цикл, потом `pipe.stop()`) |
| P3 | Предобработка слишком «бледная» → SNN без выходных спайков → класс 0 (`turn180`, 7 с) | `:640` `scale=0.1`; `:135–190` нет нормировки яркости; `:275–276` `argmax` от равных значений берёт первый индекс [S13]; мой замер §6.3: «немых» выходов 7–88 % | робот «крутится» вместо нужной команды; кажется, что «сломался» | рисовать полилинию через центры боксов толщиной ~MNIST, нормировать на max=1; отказ «не распознано», если нет спайков или мал отрыв — никогда не «по умолчанию 0» |
| P4 | Случайные входные спайки | `:212` `torch.bernoulli` без зерна | один и тот же жест → разные команды на пограничных формах (у меня L, Z: 0,51/0,49) | фиксированное зерно, голосование K=5 (≈1,6 мс в numpy) или детерминированный rate-режим (§5.3) |
| P5 | «Застрявшие» боксы: карта чистится только при распознавании | `:636–641` при <6 боксах `black_white_map` не очищается | случайная ложная детекция (1–5 боксов) прилипает к следующему жесту → обрезка `to_mnist_canvas` захватывает лишнюю точку, холст сжимается и бледнеет → неверный класс (мой замер §6.3: «2 ложных бокса в углу + жест», крупные боксы — вертикаль 0,97→0,73 верных, круг 1,00→0,93; эффект умеренный, зависит от положения ложной точки) | очищать карту по таймауту всегда; окно по времени (боксы с метками времени, ≤3 с); отбрасывать выбросы по расстоянию |
| P6 | Рука/ложный объект постоянно в кадре → распознавание не срабатывает никогда, список растёт без предела | `:632` сброс таймера на каждый бокс; `:633` `extend` без ограничения; `max_det=1` (`:553`) — ложный объект с большей уверенностью «перебивает» руку | робот «не реагирует»; память растёт ≈4–7 МБ/ч при 10 к/с **[оценка: ~120–200 Б на кортеж]** | ограничение длины, сегментация жеста по времени/по остановке руки, а не только по исчезновению |
| P7 | Колбэк лидара падает на коротком скане → падает весь процесс | `:460–461` жёсткие индексы 166–515; у TurtleBot3 в нашем стенде 360 лучей (`docs/robot_sim.md:138`) → `IndexError`; исключение из колбэка выходит из `rclpy.spin` (`:698–704`) | в симуляции — падение при первом скане без препятствия в 166..359; на реальном Hokuyo (≈683 луча [S11]) не проявляется | индексы считать из `angle_min/angle_increment` по сектору углов; `try/except` в колбэке; параметр порога |
| P8 | `q` завершает только поток «зрения» | `:666–667` `break`; главный поток продолжает `spin` | окно «не отвечает», процесс висит, README обещает выход | `q` → `rclpy.shutdown()`/событие завершения для всех |
| P9 | GUI из не-главного потока, создание окна на каждом кадре | `:662–665`, `:225–228`; GTK не потокобезопасен, на macOS не работает вовсе [S14] | возможные зависания окна; без `DISPLAY` — `cv2.error` → P1 | GUI в главном потоке или отдельный узел-просмотрщик (публиковать размеченный кадр), режим `--headless` |

### 5.3 Перенос SNN в numpy

Семантика `snntorch.Leaky` (по исходникам [S17, S18]): `reset = H(mem − thr)` по **предыдущему** mem;
`mem = beta·mem + I − reset·thr` (subtract, `reset_delay=True` по умолчанию); `spk = H(mem − thr)·graded_spikes_factor`;
H — строгая ступенька (`>0`). Перенос (ядро):

```python
for t in range(25):
    xt = (rng.random(784) < x).astype(np.float32)        # как torch.bernoulli; или xt = x (детерминированно)
    cur1 = W1 @ xt + b1
    r1 = (mem1 > 1.0); mem1 = 0.5*mem1 + cur1 - r1;  spk1 = (mem1 > 1.0)
    cur2 = W2 @ spk1
    r2 = (mem2 > 1.0); mem2 = 0.5*mem2 + cur2 - r2;  spk2 = (mem2 > 1.0)
    counts += spk2
pred = argmax(softmax(counts/25))                         # np.argmax, как torch.argmax, берёт первый максимум
```

Замер **[замер, Mac M4 Pro, numpy 2.5.3, 1 поток]**: предобработка (PIL-отрисовка + `to_mnist_canvas`) 0,22 мс,
SNN 25 шагов 0,33 мс. На Cortex-A57 Nano — единицы мс **[оценка]**. **Ограничение:** эквивалентность torch-версии
не проверена (torch не установлен); проверить у лаборатории по выгрузке спайков: в коде есть `export_spiking_input`
(`:43–70`, сейчас закомментирован вызов `:278–280`) — на одинаковом входе счётчики спайков должны совпасть (возможны
редкие расхождения из-за порядка суммирования float32 на пороге).

## 6. Жесты: классы, данные, синтез для тестов

### 6.1 Как обучалась SNN жестов

Скрипта обучения `snn_emnist_small` в архиве нет. Из метаданных: EMNIST balanced, `fix_orientation=True`, 4 выхода,
25 шагов, beta 0,5. Генераторы в `src/nettools/` относятся к другим задачам:
- `snn_prod/generate_dataset.py` — видео с «шаром», движущимся по прямой поверх фонов Kaggle scene-classification
  (нужен `file/ball.png`, его нет), для предсказания траектории;
- `snn_tools/generate_dataset.py` — координаты боксов YOLO из видео YouTube;
- `generate_dataset.py`, `ann_dataset/*`, `coco_people/*` — данные «человек» (Kaggle hillsworld, COCO).
Для синтеза жестов классов 0..3 этим кодом воспользоваться нельзя; можно взять только идею «вклеить объект в кадр
по траектории» для видеотестов YOLO (нужен спрайт кисти).

### 6.2 Какие формы соответствуют классам (поведенческое зондирование)

Подавал на numpy-SNN MNIST-подобные изображения (сплошной штрих и глифы 4 шрифтов DejaVu, 50 прогонов Бернулли)
**[замер]**:

| Класс | Команда | Что сеть относит к классу (доля ≥0,7) |
|---|---|---|
| 0 | turn180 | круглые: O, C, D, Q, G, 0, а также a, b, d, e, h, n; круг, нарисованный траекторией |
| 1 | come | угловатые/многоштриховые: V, M, N, K, H, U, Y, 2, 9, P |
| 2 | go_left / go_right | **только горизонтальный штрих** «-» (и махание рукой влево-вправо) |
| 3 | think | вертикальные: 1, I, \|, /, L, J, F, f, r |

Вывод (**оценка**): словарь жестов — «круг / галочка-зигзаг / горизонтальный мах / вертикальный мах». В EMNIST нет
символа «-», значит обучающие данные для класса 2 были не чистым EMNIST — уточнить у авторов. Перестановки
(транспонирование, отражение) этой картины не объясняют: транспонированная «1» уходит в класс 2, горизонталь — в 3.

### 6.3 Проверка демо-предобработки на синтетических траекториях

Синтез: траектория формы (сплайн по опорным точкам, равномерно по длине) → N боксов кисти с шумом 2 % → ровно та же
`write_map_number(scale=0.1)` (PIL, как в демо) → `to_mnist_canvas` (точные аналоги `F.interpolate` area/bilinear) → SNN.
Геометрия: HFOV RGB D435i ≈69,4° → f ≈ 462 px **[источник S19, розничный листинг]**; кисть 0,10×0,18 м; размах жеста
0,5 м; жест 2 с; N = 2·FPS. 4 прототипа × 15 попыток **[замер]**:

| Дистанция | FPS | Бокс, px | Демо: верно | Демо: «немой» выход (→ класс 0) | Исправленная предобработка: верно |
|---|---|---|---|---|---|
| 0,6 м | 7 / 15 / 30 | 77×139 | 0,37 / 0,50 / 0,62 | 0,88 / 0,75 / 0,60 | 0,87 / 1,00 / 1,00 |
| 1,0 м | 7 / 15 / 30 | 46×83 | 0,45 / 0,50 / 0,67 | 0,80 / 0,75 / 0,33 | 1,00 / 0,98 / 1,00 |
| 1,5 м | 7 / 15 / 30 | 31×55 | 0,47 / 0,53 / 0,82 | 0,78 / 0,62 / 0,17 | 1,00 / 0,98 / 1,00 |
| 2,0 м | 7 / 15 / 30 | 23×42 | 0,50 / 0,57 / 0,90 | 0,75 / 0,42 / 0,07 | 1,00 / 1,00 / 1,00 |

(«Верно» в демо включает случайные попадания класса 0 для круга — немой выход как раз даёт 0.) Средняя яркость
холста 28×28 в демо 0,005–0,05 против ≈0,13 у MNIST **[оценка для MNIST]**. «Исправленная» = полилиния через центры
боксов толщиной 10 px на 256×256 + нормировка max=1. Другие наблюдения: пустой вход → класс 0; шум 5 % → почти
случайный класс; «2 ложных бокса в углу кадра + жест» при крупных боксах 240×280 (где без них всё верно): круг 1,00→0,93,
V и горизонталь без изменений, вертикаль 0,97→0,73 (P5; при мелких боксах опыт неинформативен — там и без ложных
боксов выход «немой»).

**Ограничения:** идеализированная синтетика, мой порт без сверки с torch; реальные треки YOLO (дрожание, пропуски)
хуже. Это аргумент проверить на записях с робота, а не готовый результат.

### 6.4 Синтез жестов для симуляции

Предлагаю источник жестов как абстракцию с 4 реализациями: RealSense | веб-камера (Mac) | видеофайл | **синтетический
поток боксов** (JSONL: `t, x1, y1, x2, y2`). Последний делается генератором как в §6.3 (формы классов из §6.2,

## 8. Рекомендации (по приоритету)

1. **Разделить на процессы/узлы ROS 2 с супервизором** (systemd `Restart=always` или `respawn=True` в launch):
   `gesture_perception` (камера → YOLO → боксы → траектория → SNN → событие `/gesture` с уверенностью и метками
   времени), `motion_executor` (команда → отменяемый манёвр с обратной связью по одометрии/IMU D435i; heartbeat 10–20 Гц;
   ноль при стопе/препятствии/выходе), `safety_stop` (сектор лидара по углам; гейт `cmd_vel`, например twist_mux).
   Падение «зрения» тогда не останавливает моторную часть, а рестарт одного узла занимает секунды и не виден, если
   держать прогретый запасной экземпляр **[оценка]**.
2. **Живучесть цикла камеры:** `try/except` на итерацию, счётчик таймаутов → перезапуск конвейера → `hardware_reset()`;
   тема здоровья; лог всех исключений; корректное завершение.
3. **Безопасность движения:** нулевой Twist при препятствии/окончании/выходе; таймаут `cmd_vel` в мосте или прошивке
   (0,3–0,5 с); сектор лидара из `angle_min/angle_increment`; порог параметром (свести README 0,35 и код 0,25).
4. **Распознавание:** полилиния через центры боксов + нормировка + сохранение пропорций (паддинг до квадрата вместо
   растяжения 640×480→256×256); детерминированность (зерно/голосование/rate-режим); отказ «не распознано» вместо класса 0;
   очистка карты по таймауту; окно по времени; таймаут конца жеста 0,5–0,7 с или детектор «рука остановилась» вместо
   «рука исчезла»; явная обратная связь пользователю (звук/цвет) «принял жест N».
5. **SNN в numpy** (детерминированно, <1 мс на M4, без torch/snntorch/compile) — или torch с `weights_only=True` и
   падением при ошибке загрузки, без `torch.compile`.
6. **YOLO:** локальная копия yolov5 на `725b922e`, без сети при старте, прогрев; экспорт в ONNX → TensorRT FP16 на Nano;
   пауза/понижение частоты детекции во время манёвров (меньше нагрев и задержка).
7. **Инструментирование (это же метрики ВКР «работа во времени»):** метки времени кадра, детекции, конца жеста,
   распознавания, команды, первой ненулевой публикации, начала движения (в симуляции — по `/odom`); счётчики жестов,
   отказов, команд, остановок по лидару, таймаутов камеры, рестартов; RSS/CPU/GPU — для многочасовых прогонов.
8. **Стенд в симуляции:** источник жестов (§6.4) → тот же конвейер → TurtleBot3 в Gazebo (ретранслятор
   Twist→TwistStamped, 360 лучей, скорости в пределах 0,26 м/с и 1,82 рад/с) → многочасовой «прогон с сбоями».
9. **Окружение:** зафиксировать версии на роботе (`pip freeze`), свести README и requirements, не ставить torch 2.x из PyPI
   на Nano; проверить `torch.cuda.is_available()`.
