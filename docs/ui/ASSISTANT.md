# Модель, диалог и контекст EdgeCtx

Экран `#/assistant` работает с реальным Go-агентом EdgeCtx. Собственной генерации ответов в UI нет.
Можно запустить управляемый процесс или подключить уже работающий EdgeCtx по loopback URL/SSH-туннелю.
Обращение к внешнему OpenAI-совместимому провайдеру требует HTTPS; локальные Ollama/LM Studio и тестовые
серверы могут использовать HTTP на loopback. Укажите API base URL, обычно с `/v1`, точный ID модели и ключ,
если провайдер его требует. Совместимость протокола и tools зависит от конкретной модели.

## Рабочий путь

1. В «Подключениях» соберите паспорт компьютера или импортируйте JSON, созданный `edge_probe.py` на плате.
2. Укажите MCP URL. Диагностика читает только initialize и каталоги возможностей. Подключите источник к атласу.
3. В «Ассистенте» сохраните провайдера и модель. Проверка использует только `GET /models`; некоторые провайдеры
   не поддерживают этот метод, поэтому ошибка списка сама по себе не доказывает невозможность чата.
4. Запустите EdgeCtx. Первый запуск без `--agent-binary` собирает Go-агент в приватном каталоге состояния.
   Он не запускает heartbeat и не отправляет модельных запросов от обновления датчиков.
5. Создайте диалог и отправьте сообщение. Ответ, статус, usage и доступный записанный контекст связаны
   с `input_id`/wake в настоящей трассе. Трасса также появляется в лаборатории.

Для подключения внешнего EdgeCtx укажите корень его HTTP API, например `http://127.0.0.1:18080`.
У него могут быть собственные модели, инструменты и политики; настройки провайдера UI применяются только
к управляемому процессу. Отключение такого соединения не завершает внешний процесс.

## Память

`agent-context.sqlite3` — источник истины для фактов, полной истории и summary. `chat.sqlite3` — журнал UI,
сессии и статусы заданий. Это разные роли: удаление диалога не удаляет память агента; явная очистка истории
удаляет ходы и summary, сохраняя факты. Факты можно добавить, изменить и удалить. Изменение сразу пересобирает
профиль для следующего запроса модели. Во время активного хода изменения возвращают `409`, чтобы запрос
использовал целостную память. Политики `full`, `window`, `mask` выбирают видимую часть истории, а не удаляют архив.

Все диалоги управляемого агента используют общую память. Они не обещают изолированные системные промпты.
UI показывает ограниченный срез архива и отдельно видимую проекцию. Полный журнал выбранного диалога можно
экспортировать в JSON. Если внешний агент не поддерживает API контекста или локальный trace, интерфейс явно
показывает недоступность; сохранённая копия не выдаётся за отправленный промпт. Частные рассуждения модели
не запрашиваются и не отображаются.

## Наблюдения и разрешения

Управляемый агент подключён к приватному loopback MCP `edgelab-observations`. Он публикует уже полученные
атласом показания и паспорта: `list_devices`, `read_property`, ресурсы `hw://inventory` и `hw://state/...`.
Все свойства только читаемые, actions пусты; никакой вызов не пересылается оборудованию. `0`, `false`,
неизвестное значение и ошибка различаются. Паспорт отмечен как снимок с исходным временем сбора.
Перед сообщением управляемый агент обновляет этот срез; источник со статусом stale не становится живым
от факта обращения модели. Модель видит только доступное рабочему пространству и может запросить опубликованное
наблюдение инструментом. Камера не отправляет изображения модели автоматически.

Автоматический инвентарь ограничен 128 KiB, значения в нём — общим бюджетом 32 KiB и 2 KiB на свойство.
Большое значение не обрезается до выдуманной величины: оно явно исключается из автоматического контекста,
а оригинал доступен через `read_property`. Покрытие и пропуски обозначены отдельно; исходный атлас не меняется.
Для плат есть компактное summary и полный passport по запросу. `list_devices` выдаёт метаданные страницами
с offset/limit; ответы MCP ограничены 4 MiB. Исходные timestamps/status сопровождают автоматический контекст,
чтобы возраст локального кэша EdgeCtx не выдавался за время измерения. Большие ресурсы состояния намеренно
не объявляются в каталоге: это предотвращает их неявное чтение хостом при каждом подключении.

## Хранение и ограничения

CLI: `--state-dir DIR`, `--agent-binary FILE`. По умолчанию состояние вне репозитория:
`$XDG_STATE_HOME/edgelab` либо `~/.local/state/edgelab`; демонстрация использует подпапку `demo`.
Каталоги приватные 0700, provider/config/trace/SQLite-файлы — 0600. Ключ не сохраняется внутри Git.
Он остаётся у небольшого credential bridge; Go получает локальный URL без ключа. Bridge добавляет
Authorization только выбранному провайдеру, отказывается от redirects и скрывает точное значение ключа,
если провайдер вернул его в ответе. Не публикуйте файлы состояния: диалоги и контекст содержат ваши данные.

Сервер UI слушает loopback, POST требуют тот же Origin и JSON; живой шлюз дополнительно требует сессию
и CSRF. В живом шлюзе управляемый запуск отключён. Лимиты: 64 диалога, 2000 сообщений, 16000 символов
сообщения и 16 MiB журнала. Переполненный архив нужно экспортировать и очистить через удаление сессий.
Автоматических повторов запроса модели нет. Если реальный EdgeCtx вернул deferred/ошибку провайдера,
управляемый процесс останавливается, чтобы не выполнить отложенный запрос позднее без действия оператора.
После обрыва UI незавершённое задание помечается interrupted, а не отправляется повторно.

API: `GET /api/assistant`, `/api/assistant/sessions/{id}`, `/api/assistant/export/{id}`;
`POST /api/assistant/provider`, `/provider/test`, `/sessions`, `/sessions/delete`, `/agent/start`,
`/agent/connect`, `/agent/stop`, `/chat`, `/memory`, `/history`. Формы и контракты проверяются локальными
тестами с настоящим Go-агентом и mock-провайдером; платные внешние LLM и физические платы не использовались.

## API памяти самого EdgeCtx

Новые маршруты доступны только с реального loopback peer/SSH-туннеля и loopback Host. POST требует JSON
с единственным объектом; чужой браузерный Origin, неизвестные поля и лишнее тело отвергаются до изменений.

- `GET /v1/context` — факты, summary, последний срез архива, видимая история и политика, профиль и число устройств.
- `POST /v1/context/facts {operation:'add'|'update'|'delete',id?,text?}` — изменить реальный профиль.
- `POST /v1/context/history/clear {confirm:true}` — удалить историю/summary, сохранить факты.
- `POST /v1/context/hardware/refresh {}` — обновить описания и наблюдения MCP без пробуждения модели.

Изменения/refresh не вклиниваются в активный ход (`409`). Удалённые ранее известные устройства и свойства
исчезают из текущего состояния при успешном refresh; историческая трасса сохраняется. Старое поведение
обычного `SetInventory` и существующих MCP-ресурсов не меняется. Для origin-less CLI старый HTTP-контракт
сохраняется; браузерные POST не могут обойти Origin-защиту, напрямую обратившись к локальному Go-каналу.

Инспекция ограничена отдельно от исходного SQLite: до 256 фактов / 256 KiB текста, 50 ходов / 384 KiB,
100 видимых сообщений / 384 KiB, профиль 128 KiB, summary 32 KiB. О пропусках говорят явные поля
`*_omitted` / `original_*_bytes`. Большая старая запись не блокирует изменение фактов и не уничтожается.

Проверка с готовыми бинарниками (все model endpoints — тестовые loopback-серверы):

```sh
EDGELAB_TEST_BINARY=/absolute/path/to/edgectx \
BOARD_TEST_HW_BIN=/absolute/path/to/hw-mcp \
python3 -m unittest discover -s neurobot/ui/tests -p 'test_*.py' -v
```

Под Python 3.8 отдельно проверены portable probe, импорт библиотек UI и создание SQLite-журнала.
Go-агент также собран с `CGO_ENABLED=0` для Linux ARM64, ARMv7 и AMD64. Сборка не является проверкой
драйверов или производительности конкретной физической платы.
