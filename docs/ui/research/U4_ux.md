- [код] — наш код или README;

## 0. Коротко

1. **Идея реализуема и адекватна, если пульт — «окно», а не «руль».**
   - По умолчанию интерфейс только наблюдает.
   - Команды — только уровня задачи и только существующими путями: исполнитель, safety_gate, пределы L3.
   - Кнопки «снять защёлку» нет.
   - Браузер работает на ноутбуке оператора, не на Jetson.
2. **Стиль — high‑performance HMI** по ISA‑101 и ASM:
   - серый фон и серые данные;
   - цвет только у тревог трёх приоритетов;
   - приоритет кодируется дважды: цветом и формой с цифрой;
   - тренды с целевыми линиями;
   - 4 уровня экранов;
   - у каждого числа видно, насколько оно свежее.
3. **Самое ценное для ВКР — экран «Тренды» и режим «Запись».**
   - «Тренды» показывают ключевую метрику во времени: вызовы и токены LLM, ₽, задержки, PSS и CPU.
   - «Запись» проигрывает JSONL прогонов. Так на защите получается «до/после» (A0 против A1), даже если живой двойник не поднимется.
4. **Стек без сборки** — ES-модули и import map (Baseline с 03.2023):
   - Preact 10.29.8 + htm 3.1.1;
   - uPlot 1.6.32 для трендов;
   - свой Canvas 2D для лидара.
   - Сторонний код ≈ 30 КБ gzip [замер 19.10]. Node и npm не нужны ни на роботе, ни для запуска.
5. **Готовые пульты (Foxglove, Lichtblick, Open MCT) берём как образцы, а не как пульт.**
   - Foxglove-приложение закрыто.
   - foxglove_bridge не поддерживает Foxy.
   - Lichtblick и Foxglove ходят в граф ROS через rosbridge или свой мост с широкими правами — это ломает инвариант «rosbridge минимально».
   - Open MCT весит ≈5 МБ.
   - Lichtblick годится как инструмент разработчика на двойнике.
6. **Главная ловушка — вечная «жёлтая» тревога.**
   - На роботе `slow` + `lidar_blind` — это обычное рабочее состояние: перед всегда в слепом секторе корпуса камеры [код].
   - Пульт должен показывать его серым, иначе оператор перестанет замечать тревоги (alarm fatigue).

## 1. Принципы HP HMI (ISA‑101, ASM) и что они значат для пульта робота

Нормы: ANSI/ISA‑101.01‑2015 — действующее издание. К ней есть технический отчёт ISA‑TR101.01‑2022 «HMI philosophy». Нового издания ISA‑101.01 в проверенных источниках не найдено [ист. ISA]. Самый свежий обзор — статья председателя совета по стандартам ISA (июль 2026) [ист. Processing]. Руководства ASM написаны для химии и нефтепереработки; второе издание 2013 г. переименовано в «Effective Console Operator HMI Design» [ист. ASM]. Текстов самих стандартов (платные) мы не читали — только вторичные источники.

| Принцип | Источник | Как применить к пульту робота |
|---|---|---|
| Светло-серый фон, статичное — оттенками серого | [ист. Processing], [ист. study guide] | фон и панели серые; линии, корпус робота, сектора лидара — серые; ни одной «декоративной» краски |
| Яркость нарастает: норма → отклонение → ненорма → критично; цвет тревог — только тревогам | [ист. Processing] | красный, оранжевый и жёлтый — только у P1–P3 (§5); синий акцент — только у интерактивных элементов; зелёного «всё хорошо» нет (с ним спорят цвета тревог [ист. Processing]) |
| Тревогу кодировать дважды (цвет + форма/текст); мигает только неквитированная | [ист. ISA‑18.2 обзор] | значок: квадрат «1» красный, треугольник «2» оранжевый, ромб «3» жёлтый; мигает ≤ 1 Гц только неквитированная P1/P2 |
| Иерархия экранов L1–L4 (обзор → участок → детали → диагностика), переходы не строго по лестнице | [ист. ControlGlobal 2018], [ист. Processing] | §3: L1 — «Обзор», L2 — Безопасность, Жесты, Агент, Система, L3 — Датчики, юнит, жест, L4 — Тренды, doctor, сырой JSON |
| L1 даёт непрерывное понимание всей зоны ответственности и подсказывает, куда идти | [ист. Processing] | на «Обзоре» всё: робот, безопасность, жесты, агент, ресурсы; у каждой плитки — переход на её L2 |
| Тренд показывает историю и куда идёт процесс | [ист. Processing] | спарклайны на L1 (15 мин), полноценные тренды на L4 с целевыми линиями (K1 0,5 с, бюджет памяти, K8 1 МиБ/ч) |
| Поток тревог: > 10 за 10 мин — «наводнение» | [ист. Processing] (ISA‑18.2) | одинаковые причины группировать (код × N, первая/последняя); счётчик «тревог за 10 мин» на строке состояния |
| Цвет не единственный носитель смысла; нетекстовый контраст ≥ 3:1 | WCAG 2.2 1.4.1, 1.4.11 [ист. W3C] | форма + цифра + текст у тревог; палитра проверена расчётом (§7.2) |
| Мигание ≤ 3 раз/с | WCAG 2.2 2.3.1 [ист. W3C] | 1 Гц; при `prefers-reduced-motion` — без мигания, толстая рамка |
| «Нет данных» — отдельный уровень, не «0» и не «ОК» | `diagnostic_msgs/DiagnosticStatus`: OK 0, WARN 1, ERROR 2, STALE 3 [ист. ROS] | у каждого значения есть возраст; старше 2 периодов — серая штриховка «устарело N с»; нет источника — «—» и STALE |

Особенность робота: состояние меняется за доли секунды, а не за минуты, как в химии. Поэтому:
- строка состояния (§3.1) видна всегда;
- переходы `safety_state` рисуются полосой во времени — как панель State Transitions у Foxglove [ист. Foxglove];
- на них не нужно «успеть посмотреть».

## 3. Иерархия экранов и навигация

### 3.1. Каркас (на всех экранах)

```
┌─ строка состояния (всегда видна, 40 px) ──────────────────────────────────────────────────────────────┐
│ NEUROBOT  ■ ЗАЩЁЛКА / SLOW lidar_blind  v 0,12/0,15 м/с  ▲2 тревоги  связь ● 0,3 с  LLM: закрыт  14:32:07 │
│ режим: НАБЛЮДЕНИЕ                                    [ СТОП движения ]   источник: робот | двойник | запись │
├─ навигация (1–7) ───────┬─ рабочая область ────────────────────────────────────────────────────────────┤
│ 1 Обзор        L1       │                                                                              │
│ 2 Безопасность L2       │                                                                              │
│ 3 Жесты        L2       │                                                                              │
│ 4 Агент        L2       │                                                                              │
│ 5 Система      L2       │                                                                              │
│ 6 Датчики      L3       │                                                                              │
│ 7 Тренды       L4       │                                                                              │
│ ─ тревоги (лента) ─     │                                                                              │
└─────────────────────────┴──────────────────────────────────────────────────────────────────────────────┘
```

- **Источник данных** (робот, двойник, запись) — крупно и всегда: числа двойника не должны сойти за числа робота (правило проекта «честность чисел»).
- **«Связь ● 0,3 с»** — возраст последнего сообщения шлюза. Больше 2 с — вся рабочая область уходит в штриховку «нет связи», значения не исчезают, но помечены как устаревшие.
- Горячие клавиши 1–7, `Esc` — назад на L1, `Space` — квитировать выбранную тревогу. СТОП с клавиатуры — только с подтверждением, чтобы не нажать случайно: `Shift+S` дважды [допущение].
- Экраны: ноутбук 1366×768 — минимум, проектор 1920×1080 — основной. Планшет у робота — L1 и «Безопасность» в одну колонку, только наблюдение.

### 3.2. Уровни

| Уровень | Экран | Вопрос оператора |
|---|---|---|
| L1 | Обзор | «Всё ли в порядке и куда смотреть?» |
| L2 | Безопасность, Жесты, Агент, Система | «Что с этой частью и почему?» |
| L3 | Датчики (лидар, камера), карточка юнита, карточка жеста, карточка хода агента | «Покажи подробности одного объекта» |
| L4 | Тренды, doctor, сырой JSON темы, запись | «Как было во времени, что сломалось» |

## 4. Экраны

Частоты — источники из README; у шлюза их можно урезать (U2 §6).

### 4.1. Обзор (L1)

- **Слева — мини-лидар** (§4.2, упрощённый): корпус, коридор, `front_m`, сектор корпуса камеры.
- **В центре — плитки 2×3. В каждой: значение, единица, возраст, спарклайн за 15 мин, цель пунктиром:**
  - «Безопасность» — `state` и первая причина;
  - «Жест → команда» — p50 и p95 за последние 20 жестов, цель K1;
  - «LLM на жест» — 0 (K4), крупно;
  - «LLM за час» — вызовы и токены; ₽ факт и ₽ оценка;
  - «Память стека» — сумма PSS против бюджета ветки ОС;
  - «Юниты» — N из M в работе и рестарты за час.
- **Справа — лента тревог** (§5) и последние 5 жестов.
- **Цвет только у плитки с активной тревогой** (рамка и значок). Остальное серое.

### 4.2. Датчики (L3): лидар и камера

**Полярный вид лидара — свой Canvas 2D.** Курс — вверх, робот — в центре.

| Слой | Данные | Вид |
|---|---|---|
| Кольца шкалы 0,5 / 1 / 2 / 4 м, диапазон 1 / 2 / 5,6 м | — | тонкие серые |
| Корпус Ø0,39 м и коридор шириной 2·(R + `lateral_margin`) = 0,49 м | `robot_radius` 0,195, `lateral_margin` 0,05 [код] | серый контур |
| Поле лидара ±119,9° (683 луча ±2,09235 рад); сзади 120° — «нет датчика» | URG‑04LX, PLAN §13.1 [код] | штриховка «нет датчика» |
| Маска корпуса D435i | `lidar_mask_deg` из `/neurobot/safety_state`; учится в −65…+8°; на роботе −60,8…+4,2° [код] | штриховка с подписью «корпус камеры: вперёд видит только глубина, ≤ 0,15 м/с» |
| Поле камеры глубины 87° | safety README [код] | тонкий контур клина |
| Точки скана | `/scan` 10 Гц → шлюз 5 Гц, минимум по 1° (≈240 значений) [оценка] | серые точки; в коридоре ближе тормозного пути — цвет P3/P2 |
| Неизвестные лучи (NaN, коды URG) | `/scan` + `warnings: lidar_unknown` | серые штрихи на краю дальности, не точки |
| `front_m` и тормозной путь `d_stop(v)` | `/neurobot/safety_state` | две поперечные линии в коридоре с подписями |

`d_stop(v) = v·t_lat + v²/(2·a_brake) + margin`. При умолчаниях (`t_lat` 0,25 с, `a_brake` 0,8 м/с², `margin` 0,05 м) [код] получается:
- 0,10 м при 0,15 м/с;
- 0,15 м при 0,25 м/с.

Это расчёт по умолчаниям, не замер тормозного пути.

Отрисовка — по приходу скана, через `requestAnimationFrame`, не чаще 10 Гц. 683 точки для Canvas 2D — пустяк [оценка].

**Камера:**
- Кадр JPEG 320×240, 1–5 кадров/с, и только пока панель открыта: камера не должна нагружать Jetson в фоне.
- Поверх кадра — рамки YOLO и след кисти.
- **Сейчас рамки не публикуются:** в `/neurobot/gesture` есть только `n_boxes` [код perception README]. Чтобы их рисовать, нужен патч perception — тема с рамками или с картинкой жеста 28×28. Это код лаборатории, Python 3.8.
- Картинка 28×28, которую классифицировала SNN, очень наглядна для комиссии: «вот что увидела сеть».
- Сколько стоит разбор и сжатие кадра на Nano, никто не мерил [код perception README] — это пункт замера (§9).
- Под кадром — строка `perception_health`: fps, `frame_age_s`, `state`, `dark`, `recoveries`.

### 4.3. Безопасность (L2)

- **Состояние крупно**: `ok`, `slow`, `blocked` или `estop`.
  - `slow` с одной причиной `lidar_blind` или `lidar_unseen` — серым, подпись «штатно: перед видит только глубина».
  - `blocked` — P3, `estop` — P1.
- **Причины** `reasons[]`: код и человеческий текст. Словарь кодов — в safety README [код]: `estop, tilt, shock, stall, foreign_writer, override, stale_*, lidar_mask, lidar_fault, motion_time, scan_foreign, scan_publishers, unarmed, obstacle, cliff, approach, lidar_nodata, lidar_blind, lidar_unseen, geofence, reverse_limit, touch`.
  - `warnings[]` — отдельным, тихим списком.
- **Цепочка скорости** — главная инженерная картинка: «запрошено → разрешено → выдано».
  - Это `req[v,w]` → `limits{v_max, v_rev, w_max}` → `out[v,w]` и флаг `cut`.
  - Рисуется горизонтальной шкалой: метка запроса, граница разрешённого, метка выхода. Срез виден сразу.
- **Тормозной путь**: полоса `front_m` против `d_stop(v)` при текущей скорости. Под ней — `min_clearance_m` и `tilt_deg`.
- **Защёлка** — карточка: `engaged`, `since` (часы и «сколько стоит»), `reasons`, и инструкция:
  > Снимается только человеком у робота: `sudo neurobot estop release` (терминал, слово `release`).
  - Рядом кнопка «копировать команду».
  - **Кнопки «Снять» нет и не будет** — инвариант. Пульт только ждёт, когда `state` станет не `estop`.
- **Полоса состояний** за 10 мин: серые `ok`/`slow` и цветные `blocked`/`estop`.

### 4.4. Жесты (L2)

**Лента за 10 мин.** Каждый жест — метка, форма метки — исход:

| Исход | Вид метки |
|---|---|
| выполнен (`task_end done`) | ● |
| не распознано | ○ |
| отменён безопасностью (`blocked`, `estop`, `safety_lost`) | ◐ |
| вытеснен агентом (`preempted`) | ◇ |

- **Подпись метки:** `name` и `conf`.
- **Карточка жеста (L3)** — по клику:
  - поля `/neurobot/gesture`: `cls, name, conf, margin, spikes, n_boxes, side, t_end, t_rec`;
  - первая команда в `/cmd_vel` (шлюз только читает тему);
  - исход из `/neurobot/events`.
- **Задержки:**
  - Δрасп = `t_rec − t_end`;
  - Δкоманда = `t_cmd − t_end`;
  - гистограмма за сессию с линиями 0,5 с (K1) и 0,6 с (цель p95 робота).
  - Считать на стороне робота, по одним часам, а не в браузере.
- **Честно про метрику.** На двойнике K1 считается от t0 — истины генератора жестов [код PLAN §3]. На роботе t0 нет, есть только `t_end` от perception. Это другая величина, и подпись должна об этом говорить.
- **Счётчики:** жестов, распознано, «не распознано», **вызовов LLM на жест 0** (K4).
- **Рефлекс:** включён или выключен, таблица «класс → манёвр». Только показ; менять — в режиме «Управление» (§6).

### 4.5. Агент (L2)

- **Чат с EdgeCtx** через шлюз → `POST /v1/user` [код agent README]. Под каждым ответом: `latency_ms`, `llm_calls`, `tool_calls`, токены и ₽.
  - **Чат — ещё один канал реплик пользователя, прав агенту он не добавляет:** инструменты и пределы те же.
- **Журнал пробуждений** из трассы JSONL: `wake.reason` (`user | gate | heartbeat | rule | deferred`). Рядом — **подавленные гейтом** `suppress.reason`.
  - Это главная мысль ВКР в одной картинке: «событий 412, пробуждений LLM 6».
- **Вызовы инструментов** (`tool_call` / `tool_result`): `drive`, `turn`, `stop` с `ok` / `denied` и причиной отказа.
- **Связь:**
  - `llm_link{state: closed|open|half_open}`;
  - `mcp{down, up}` из `GET /v1/metrics`, `GET /v1/health`.
- **₽** — два числа рядом:
  - «0,00 ₽ факт (mockllm)»;
  - «≈ X ₽ по прайсу RouterAI 06.10.2026» — [оценка] по `bench/costmodel/prices.py` [код].
- **PicoClaw** метрик по HTTP не отдаёт. Его можно показать только по журналу: «Connected to MCP server», обрывы, долгие вызовы — так же, как это делает doctor [код deploy README]. Чат с ним в пульт не встраиваем: у него свой веб-канал `pico` с токеном [код R3].

### 4.6. Система (L2)

- **Юниты:** `neurobot.target`, `driver@*`, `safety`, `executor`, `perception`, `rosbridge`, `labworker@*`, `mcp`, `picoclaw`, `watchdog` [код deploy README].
  - По каждому: состояние, с какого времени, `NRestarts`, последний `Result`.
  - Цвет — только у упавшего юнита или юнита в цикле рестартов.
- **doctor:**
  - запускается кнопкой «Проверить» — это `neurobot doctor --json`, коды 0, 1, 2, 3;
  - показывается последний результат и время проверки.
  - Не по таймеру: doctor снимает граф DDS, а это дорого [код]. Даже кнопка — действие, поэтому только в режиме «Управление» или по правам шлюза.
- **Память:** PSS по компонентам горизонтальными полосами и сумма против MemoryMax ветки ОС.
  - Бюджет ветки: GNOME 2406, LXDE 3056, headless 3336 МиБ [код budget README].
  - Подпись «модель бюджета — [допущение] до замера на Nano».
- **CPU** по компонентам, температура, запись на флеш, трафик — из sysmon JSONL [код sysmon README].

### 4.7. Тренды (L4) — ключевая метрика ВКР

- **Окна:** 15 мин, 1 ч, 8 ч, весь прогон.
- **Курсоры** всех графиков синхронизированы (cursor sync в uPlot [ист. uPlot]). Сглаживания нет: uPlot его не советует [ист. uPlot].

| График | Ряды | Целевая линия |
|---|---|---|
| LLM | вызовы/ч, токены/ч (вход, кэш, выход), подавлено гейтом/ч | — |
| Деньги | ₽ накопительно: факт и оценка по прайсу | — |
| Задержки | жест → команда p50/p95 (скользящее, 20 жестов); реплика → ответ агента | K1 0,5 с; цель p95 0,6 с |
| Память | PSS сумма и по компонентам; наклон Сена МиБ/ч в легенде | бюджет ветки; K8 ≤ 1 МиБ/ч на процесс |
| CPU, °C | CPU % по компонентам, температура | — |
| Непрерывность | рестарты, отказы и их TTR, полоса `safety_state` | — |

- Это то же, что считают `bench/metrics` и sysmon. **Пульт числа ВКР не производит:** результат — только прогон по протоколу (§10).

## 5. Тревоги: приоритеты (предложение, утвердить)

По ISA‑18.2 приоритеты задаёт «философия тревог» объекта, а не общая палитра [ист. ISA‑18.2 обзор]. Ниже — проект такой философии для робота [допущение].

| Приоритет | Знак | Что сюда |
|---|---|---|
| P1 критично | красный квадрат «1» | `estop` и защёлка по `tilt`, `shock`, `stall`, `foreign_writer`; `lidar_fault`; упал safety_gate или нет `/neurobot/safety_state` > 1 с (пульт не знает, безопасно ли) |
| P2 высокий | оранжевый треугольник «2» | `stale_scan`, `stale_odom`, `stale_imu`, `stale_accel`, `stale_depth`; `scan_foreign`, `scan_publishers`; `motion_time`; юнит в цикле рестартов; `rosbridge_down`, `executor_offline`; `camera_lost` > 30 с; MCP down |
| P3 внимание | жёлтый ромб «3» | `blocked` по `obstacle`, `cliff`, `approach`, `lidar_nodata`; `geofence`, `reverse_limit`; предупреждения `override` (геймпад), `mask_outside`; `slow_detector`; perception `recovering`; LLM `open` |
| норма (без цвета) | серый текст | `slow` с `lidar_blind` / `lidar_unseen`; `unarmed`; `starting`; `paused` у perception в движении |

- Квитирование гасит мигание, но не саму тревогу: тревога висит, пока условие есть.
- Повтор одной причины не создаёт новую строку, только счётчик.
- **«Затенение» тревог (shelving) — не делаем**: робот маленький, тревог мало, а скрытая тревога безопасности опаснее шума.

## 6. Управление из пульта: границы

| Действие | Как | Почему так |
|---|---|---|
| Наблюдение (по умолчанию) | ни одной кнопки движения | ошибка оператора невозможна |
| Взять управление | «сдвинь, чтобы подтвердить» (как Arm у Cockpit [ист. Cockpit код]); видно на строке состояния; владелец один; сам возврат в наблюдение через 5 мин бездействия [допущение] | случайный клик не поедет; двое не управляют сразу |
| СТОП движения | кнопка видна всегда, в любом режиме; путь — как у стопа агента (`/neurobot/stop_now`: ноль сразу, без защёлки [код]) или отдельный узел шлюза — решает архитектура | действие только к безопасности; **подпись «Стоп», не «Аварийный стоп»:** сенсорный экран не может быть e-stop, он лишь дополняет аппаратный [ист. ControlDesign 2024]; аппаратная кнопка L0 — рекомендация лаборатории [код safety README] |
| Поставить защёлку | кнопка с подтверждением (ставят все [код]) | безопасно по направлению |
| Снять защёлку | **нет кнопки**, только инструкция `sudo neurobot estop release` у робота | инвариант: снимает только человек с root |
| Задача: `drive` ≤ 1 м, `turn`, `maneuver`, `reflex` вкл/выкл/таблица | только в «Управлении», «сдвинь, чтобы подтвердить»; до подтверждения — прогноз (м, ≤ 0,15 м/с, eta); после — `task_end` | те же пределы L3 и тот же путь через исполнитель и safety_gate, что у агента; пульт не публикует скорости |
| Джойстик, телеуправление Twist | **не делаем** | второй писатель скоростей; веб-задержки; у Foxglove Teleop — прямой Twist [ист. Foxglove panels] |
| Параметры safety_gate | только показ | `params_glob [none]` [код]; безопасность не настраивается из браузера |

Доступ: шлюз слушает 127.0.0.1. Ноутбук ходит к нему через SSH-туннель — подробности за U-архитектурой. Агент при этом не получает ни одной новой темы и ни одного нового права; глобы rosbridge не меняются.

## 7. Визуальный язык

### 7.1. Правила

- **Плоско:** панели с рамкой 1 px, без теней, градиентов и анимаций. uPlot принципиально без анимаций [ист. uPlot].
- **Числа:**
  - моноширинный шрифт, `font-variant-numeric: tabular-nums` — Baseline с 01.2020 [ист. MDN];
  - русская запись: `Intl.NumberFormat('ru-RU')`, запятая в дробях, тонкий пробел в разрядах;
  - единица — после значения, приглушённым цветом;
  - «—» вместо отсутствующего значения, никогда «0».
- **Точность по величинам:**

  | Величина | Формат |
  |---|---|
  | путь | м, 2 знака |
  | скорость | м/с, 2 знака |
  | угол | °, 0 знаков |
  | задержка рефлекса | с, 2 знака |
  | стоп | мс, 0 знаков |
  | память | МиБ, 0 знаков |
  | токены | целые |
  | ₽ | 2 знака |

- **Возраст значения** — маленькая цифра справа сверху у плитки («0,2 с»). Устаревшее — штриховка.
- **Шрифты:**
  - системный стек `ui-monospace, "JetBrains Mono", "IBM Plex Mono", Menlo, Consolas, monospace`;
  - для одинакового вида — свои woff2 рядом с пультом (в лаборатории может не быть интернета).
  - JetBrains Mono (OFL‑1.1, v2.304 — 2023, свежее в проверенных источниках не найдено): латиница 400 — 21 КБ, кириллица 400 — 5 КБ.
  - IBM Plex Mono (OFL‑1.1): латиница 400 — 15 КБ, кириллица 400 — 8 КБ.
  - Размеры по файлам `@fontsource` 5.x [замер 19.10].
- **Размеры:** подписи 12–13 px, значения 14 px, KPI 28–32 px, сетка 8 px.

## 9. Нагрузка и бюджет 4 ГБ

- **Отрисовка — в браузере ноутбука.** Браузер на Jetson с GNOME съел бы запас: он и так 539 МиБ [код OVERVIEW]. Лаборатории уже рекомендован headless.
- **На роботе — только шлюз.** Его вес и CPU входят в бюджет и мерятся тем же sysmon.
- **Частоты в браузер:**
  - `safety_state` 5 Гц;
  - `motion_state` 2 Гц;
  - здоровье 1 Гц;
  - скан 5 Гц, свёрнутый до ≈240 значений;
  - метрики 1 Гц;
  - sysmon — 1 раз в 5 с;
  - кадр камеры — только при открытой панели.
- **Обязательный замер:** прогон двойника «пульт выключен / пульт открыт» в `jetson.slice`. Смотреть на PSS шлюза, CPU, K1 и K6. Если пульт заметно меняет метрики, на прогонах ВКР по протоколу он выключен — или это отдельное условие эксперимента.

## 10. Как пульт поможет на защите

1. **Живой двойник** — ВМ sim на Mac, пульт в браузере, источник «двойник».
   - Сценарий на 5–7 мин:
     1. жест → в ленте «Жесты» появилась метка и Δ;
     2. ящик на пути → «Безопасность»: `blocked`, причина, `front_m` против тормозного пути;
     3. `kill -9` perception → «Система»: рестарт и TTR (на стенде 3,1–3,2 с [код PLAN §13.5]);
     4. реплика агенту «проедь 0,5 м» → «Агент»: 2 вызова LLM, токены, 0 ₽ факт и ₽ по прайсу;
     5. `robot_stop` → ноль через единицы миллисекунд (K6 p50 1,9 мс на стенде);
     6. защёлка → карточка «снимается только `sudo` у робота».
   - Числа на экране подписаны «двойник».
2. **«До/после» в режиме «Запись».** Два прогона рядом по одной оси времени, с ускорением ×30:
   - стек лаборатории A0 и наш A1 — по 34 мин;
   - задержка жест → команда: p50 1,81 против 0,67 с;
   - касаний 23 против 0;
   - LLM на жест 0 [код OVERVIEW §4, двойник].
   - Запись работает без ВМ и без сети: это запасной план, если живой стенд в аудитории не поднимется. Плюс видео прогона.
3. **Тренды за 1 ч и 8 ч** — та самая метрика «работа во времени»:
   - PSS ровный или растёт;
   - LLM будится редко;
   - ₽ стоит на месте.
4. **Рисунки для ПЗ** — скриншоты экранов: архитектура «окно, а не руль», иерархия L1–L4, палитра тревог. Это прикладная часть: HMI для граничного агента.
5. **Честность.** На экране всегда видно, откуда данные. Результатом ВКР остаётся прогон по протоколу на плате с реальной LLM, а не картинка пульта.

## 12. Риски

- **Пульт превращается в «руль».**
  - Появляется второй писатель скоростей или обход L3 — нарушение инварианта.
  - Мера: в коде пульта нет публикации Twist; команды идут только существующими путями; проверка писателей doctor'ом в приёмке U‑6.
- **Новая поверхность атаки.**
  - Если шлюз открыт в сеть лаборатории, любой в сети видит робота, а в «Управлении» — может им командовать.
  - Мера: 127.0.0.1 + SSH-туннель, только наблюдение по умолчанию, никакого снятия защёлки.
- **Пульт искажает ключевую метрику:** CPU и память шлюза, сжатие JPEG на Nano. Мера: замер U‑7; на прогонах ВКР пульт выключен или это отдельное условие.
- **Усталость от тревог:** вечный `slow` / `lidar_blind` жёлтым. Мера: философия тревог §5, норма — серым.
- **Путаница источников:** числа двойника на слайде как числа робота. Мера: метка источника на каждом экране и в каждом скриншоте.
- **Задержка робота «жест → команда» — не K1 двойника** (нет t0). Мера: разные подписи.
- **Рамки YOLO и 28×28 требуют патча perception** — это код лаборатории, Python 3.8, и цена на Nano неизвестна. Мера: камера в последнюю очередь, без рамок; рамки — по согласию лаборатории.
- **Объём работ против сроков ПЗ** (глава 1 — к 15.01.2027). Мера: U‑0…U‑4 на записях — уже ценный результат; управление — опция.
- **Свежие версии библиотек:** Preact 11 вышел 30.09.2026. Мера: Preact 10.29.8, версии и SHA‑256 зафиксированы в `vendor/`.
