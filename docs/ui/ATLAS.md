# Edge Atlas — оборудование и сигналы

20.10.2026. Реализовано в ветке `codex/neurochip-interface` по запросу расширить интерфейс с робота NeuroChip на оборудование и все доступные сигналы. Это инструмент наблюдения и демонстрации ВКР; новая научная гипотеза здесь не заявляется.

## Запуск

Без ROS, записи, модели и платы:

```sh
python3 -m neurobot.ui catalog
# http://127.0.0.1:18126/
```

«+ Источник» подключает локальный MCP Streamable HTTP сервер. Можно передать адреса при запуске:

```sh
python3 -m neurobot.ui catalog --source http://127.0.0.1:18090/mcp

# Живая демонстрация: модели датчиков меняют sysfs, hw-mcp читает его тем же кодом
python3 scripts/ui/atlas_demo.py
# http://127.0.0.1:18127/?demo=1#/equipment · только симулятор
```

Для удалённого оборудования сначала поднимите SSH-туннель на его MCP-порт. Каталог допускает только явные локальные адреса, не сканирует сеть, не использует внешние CDN. Подключения хранятся в памяти серверного процесса; для постоянной конфигурации передавайте `--source` при запуске.

Запись и существующий живой шлюз робота тоже получили экран «Атлас сигналов», клавиша `4`. Прежние экраны, проигрыватель, СТОП, защёлка и диагностика сохранены.

## Работа с данными

- Каталог слева показывает обнаруженные источники. Поиск находит устройство, канал или вложенное поле; `/` переводит фокус в поиск. Отдельно видны датчики, движение, система, события и внешние MCP-устройства.
- Карта в центре показывает принадлежность каналов общему потоку наблюдения. Это не автоматически восстановленная схема ROS и не электрическая схема. Выбор из каталога и карты синхронен.
- Инспектор справа раскрывает поля любого полученного объекта, включая неизвестные вложенные словари, массивы, `null`, `false` и `0`. Ключи с точками и косыми чертами не теряются. Есть поиск по полям, полный JSON, описания возможностей и экспорт снимка JSON.
- Числовые сигналы и булевы состояния имеют историю. Пропуски образуют разрывы; булевы значения показываются ступенчато. До четырёх сигналов из разных источников можно закрепить; выбор сохраняется в браузере.
- История ограничена в памяти. MCP хранит последние 180 полученных обновлений на устройство; для временного скана — до 600 наблюдений за последние 5 минут. История отключённого источника освобождается. Общая запись робота продолжает использовать существующий 15-минутный буфер.
- В записи действует её время; MCP-источники живут по собственным часам независимо от проигрывателя. Последнее успешное наблюдение не обновляется при сетевой ошибке. Описание устройства без значений не выдаётся за живые измерения.

## Подключение оборудования

Новые имена устройств не требуют изменения фронтенда. Адаптер читает `initialize`, `resources/list`, `resources/read`, `tools/list`; для совместимости с известным контрактом поддержан `list_devices`. Описания устройств, состояний и неизвестных полей преобразуются в общий каталог. Подтверждена связка с настоящим процессом `hw-mcp` на копии синтетического sysfs.

Это универсальность на уровне опубликованных данных MCP. Неизвестному USB-прибору без драйвера, назначения каналов или MCP-адаптера интерфейс не может приписать физический смысл. Пассивный инвентарь, отсутствие показаний, неподдержанный ресурс и ошибка сервера видны явно. Поток робота предоставляет те поля, которые действительно публикует шлюз; отсутствующие кадры камеры или скан из записи не генерируются.

Каталог читает оборудование. Возможность записи и действия из MCP показываются как описания, но не исполняются автоматически. В роботном пульте по-прежнему ровно две команды — СТОП движения и постановка защёлки с подтверждением. Снятие защёлки выполняет человек у робота.

## Визуальный принцип

Приборный стол с тремя постоянными областями: каталог, рабочая плоскость, инспектор. Графитовые поверхности, цвет выбранного сигнала, моноширинные значения и сдержанная сетка вместо декоративной витрины. Светлая тема также поддержана; на малых экранах области перестраиваются последовательно.

Импульс возникает при приходе нового сообщения и завершается; остановленная запись не изображает поток. Переключение выбора и раскрытие интерфейса короткие, значения меняются сразу. Анимацию можно выключить, системный Reduce Motion соблюдается.

Использованные принципы и первоисточники:

- [Rerun — viewer navigation](https://rerun.io/docs/getting-started/configure-the-viewer/navigating-the-viewer): единая выбранная сущность и временная позиция.
- [Foxglove — topic discovery](https://foxglove.dev/blog/improved-topic-discovery-and-visualization-in-foxglove): поиск каналов и полей.
- [Foxglove — topic graph](https://docs.foxglove.dev/docs/visualization/panels/topic-graph): реальный граф соединений требует publisher/subscriber данных; здесь они не подменяются догадками.
- [Teenage Engineering — OP-1](https://teenage.engineering/products/op-1/original/overview): приборная идентичность и связь визуального отклика с параметром.
- [Linear — calmer interface](https://linear.app/now/behind-the-latest-design-refresh): приглушённая оболочка и внимание к рабочей области.
- [Apple HIG — motion](https://developer.apple.com/design/human-interface-guidelines/motion): краткая осмысленная анимация и возможность её отключить.

## Проверки

```sh
python3 -m pytest neurobot/ui/tests -q
python3 neurobot/ui/tests/e2e_design.py --bundle neurobot/ui/samples/demo_hall.json.gz --out /tmp/atlas-robot-qa
python3 neurobot/ui/tests/e2e_equipment.py --out /tmp/atlas-equipment-qa
```

Браузерным проверкам нужны Playwright и Chromium только в окружении разработки; приложению они не нужны. `e2e_equipment.py --hw-mcp /абсолютный/путь/hw-mcp` дополнительно проверяет настоящий MCP-процесс на копии фикстуры: обнаружение и изменение показания до браузера. Проверки не касаются физического оборудования и не подтверждают результаты ВКР на плате.

Зафиксированные проверки 20.10: 142 теста серверной части и модели интерфейса, 31 subtest; 10 ожидаемых пропусков без ROS и приватных записей. Браузерная матрица — запись, живой шлюз и автономный каталог; отдельно проверены настоящий процесс hw-mcp и изменение тестового sysfs до браузера.
