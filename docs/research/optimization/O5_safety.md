## 0. Вывод в пяти строках

1. Логика правил адекватна литературе и стандартам: тормозной путь `v·t_lat + v²/(2a) + margin` — та же структура, что
   S = K·T + C (ISO 13855), защитная дистанция SSM (ISO/TS 15066; Marvel, Norcross 2017) и «допустимые скорости» DWA
   (Fox и др. 1997). По сути это одномерный backup-CBF с политикой «тормози» (Chen и др. 2021) и «пассивная
   безопасность» при ограниченном поле зрения (Bouraine и др. 2012). Переходить на CBF-QP смысла нет (§4).
2. Главная прошлая перестраховка (`blocked` 73–79 %, ложный `lidar_nodata`) снята правильно. Сейчас `blocked` 2 % в
   `lab_v5` и 15 % в `long_v5`. Мой разбор `long_v5` по истине: 449 из 455 с `obstacle` — при истинном зазоре
   0,10–0,20 м. Значит, блок по замыслу, а не ложный. Остаток консервативности — это сумма запасов для клеток глубины:
   0,05 + 0,04 + 0,035 = 0,125 м (§6.5).
3. Главный риск — не правила, а перенос с двойника на робота. Двойник идеален там, где робот — нет:
   - поза и высота камеры на мачте: ошибка наклона 1° даёт 2–4 см «высоты пола» и превращает весь пол в препятствие (§6.3);
   - шум глубины на 424×240;
   - тормоза L1: в Foxy `has_acceleration_limits` по умолчанию `false`, поэтому мгновенный ноль — жёсткое торможение;
   - реальная задержка и `a_brake`.
4. Дыры, которые дёшево закрыть:
   - застывший скан или кадр (одинаковые данные, `stamp` не растёт);
   - свежесть по времени прихода, а не по `header.stamp`;
   - геймпад в twist_mux обходит защёлку: закрывается lock'ом twist_mux, механизм есть в Foxy;
   - пробуксовка на повороте (гироскоп против одометрии).
5. В тексте ВКР нужна точная терминология:
   - защёлка L2 — программный «защитный останов» категории 2 по IEC 60204-1, а не «аварийный останов» ISO 13850.
     Аварийный останов возможен только в L0: аппаратная кнопка, категория 0 или 1;
   - «0 касаний» указывать вместе с n и верхней границей по правилу трёх (§5).

## 1. Что уже есть (кратко)

- [есть] Тормозной путь от края корпуса. Скорость падает плавно (`allowed_speed`). Блок ниже `min_speed`, у снятия
  блока гистерезис `release_hyst`/`release_s`.
- [есть] Коридор шириной корпуса, а не сектор.
- [есть] «Нет данных» лидара по REP 117. Провал запрещает, только если на дальнем конце поместится предмет шире
  `max_gap_m`. Свободное по свежей глубине — разрешено. Вне поля глубины действует `nodata_unseen=slow`.
  Весь скан пустой — `lidar_fault`.
- [есть] Маска корпуса камеры учится только в секторе, только сужается.
- [есть] Глубина без PCL: препятствие, пол и обрыв по плоскости z = 0 базы. Память клеток хранится в одометрии.
  Покрытие коридора — по полосам. Поправка `depth_err_m`.
- [есть] Поворот на месте с `turn_margin`. Задний ход только по своему следу. Выход из тупика у исполнителя.
- [есть] IMU: наклон (с установкой фильтра после перерыва), удар. Упор по одометрии.
- [есть] Защёлка: ставит кто угодно, снимает только root. После снятия — `unarmed`, нужен нулевой запрос.
  Стоп агента — ноль сразу, без защёлки.
- [есть] Устаревшие входы — полный стоп. Чужой писатель `/cmd_vel` — защёлка. Проверяются издатели `/scan`.

## 2. Адекватность правил и порогов

| Правило / порог | Вердикт | Почему (и источник) |
|---|---|---|
| `d_stop = v·t_lat + v²/(2a) + margin` от края корпуса | адекватно | Структура S = K·T + C (ISO 13855) и S_p = S_h + S_r + S_s + C + Z (ISO/TS 15066, Marvel и Norcross 2017). Решение «наибольшая v, с которой успеем встать» — допустимые скорости DWA (Fox и др. 1997) с поправкой на задержку. Но `t_lat` 0,25 с и `a_brake` 0,8 м/с² — [допущение]. ISO 3691-4 требует, чтобы торможение укладывалось в зону обнаружения при худших трении, уклоне и нагрузке (по обзору ANSI). Значит, нужен замер худшего случая на роботе (H2) |
| Неопределённость лидара | частично | URG-04LX: ±30 мм на 60–1000 мм, ±3 % дальше (паспорт Hokuyo). В SSM это отдельный член Z. У нас он неявно сидит в `margin` 0,05: на «после остановки» остаётся ≈2 см. Безопасно, но в ПЗ лучше записать явно (L4) |
| Прямой коридор при движении по дуге (v и w вместе) | адекватно | [расчёт] За время остановки с 0,15 м/с путь 0,052 м. При w = 0,8 рад/с дуга отходит от хорды на 0,7 см, при 0,25 м/с — на 1,7 см. Это меньше `lateral_margin` 5 см. Жесты демо — чистые повороты или прямые (`predict_live.py`) |
| NaN = «неизвестно», запрет только по ширине провала в коридоре | адекватно | Совпадает с практикой ROS: в costmap_2d `inf_is_valid` по умолчанию false, max-range не очищает. Nav2 Collision Monitor NaN не считает препятствием вообще — у нас строже. [код чужого] urg_node2 (main, v1.0.0, `urg_node2.cpp`, строки 571–581): NaN — только для сырого кода 0; коды ошибок URG (< 20 мм) идут конечными значениями ниже `range_min`, их ловит наше правило; +inf драйвер не выдаёт никогда. Какой сырой код URG-04LX даёт на «нет отражения», по спецификации SCIP не проверил |
| `nodata_unseen=slow` (решение 2а) | адекватно | Это паттерн «скорость ограничена там, где обзора нет» (Chung и др. 2009; Bouraine и др. 2012: при ограниченном поле зрения гарантируема только пассивная безопасность). [расчёт] Удар при 0,15 м/с: E ≈ 0,042 Дж (приведённая масса 3,76 кг). Квазистатический предел для голени по таблице ISO/TS 15066 (130 Н, 60 Н/мм) — 0,14 Дж: запас ≈3×; предел достигается при ≈0,27 м/с. Это аналогия с PFL коботов, не требование для мобильных роботов. Стекло и имущество не покрыты — цена записана в README |
| `blind_speed` 0,15 = предел L3 | адекватно | Та же оценка энергии. `slow` 83–95 % времени — свойство робота (RS3), а не стоимость фильтра |
| Маска корпуса только в секторе, только сужается | адекватно | Аналог exclusion zones Nav2 Collision Monitor, но учится сама и не «запоминает обстановку» |
| `lidar_fault` (< 10 попаданий 3 скана) | адекватно | Правдоподобие входа. Не ловит застывший скан — см. H3 |
| Свежесть по времени прихода (`time.monotonic()` в колбэке) | спорно | Nav2 ведёт свежесть по штампу (`source_timeout`) и сдвигает данные на движение базы (`base_shift_correction`). Очередь в однопоточном `spin_once` (глубина и скан в одном потоке) на Jetson может съесть бюджет `t_lat`. На ВМ «ноль после скана» 0,3/0,7 мс — это x86, не A57 |
| Плоскость пола z = 0 из `/tf_static`, пороги +0,02 / −0,04 | спорно для робота | [расчёт, §6.3] Ошибка наклона камеры 1° — +2,1 см на 1,2 м и +4,4 см на 2,5 м: весь видимый пол становится препятствием. Ошибка высоты мачты −2 см — то же. На двойнике поза точная, поэтому прогоны этого не видят. Прецедент — `depth_sensor_pose` (RANSAC высоты и наклона, Drwięga и Jakubiak 2017) |
| 424×240, `depth_max_m` 2,5 | спорно | [расчёт по формуле Intel] σz на 2,5 м — 4,5 см при 424 px и 2,2 см при 848 px. σ высоты пола — 1,2 см против порога 2 см (1,7σ). Intel: 848×480 оптимально, вместо снижения разрешения — прореживать (decimation); пресет High Accuracy рекомендован для обхода препятствий. В `neurobot.env.example` профиль и пресет не заданы |
| Прореживание карты глубины выборкой каждого ≈5-го пикселя | спорно | Тонкий предмет (ножка 2,5 см) на ≥1,2 м попадает в 0–1 выборочных пикселей и мерцает. Клетку «очищает соседний пол» — это и есть причина инцидента 17.10 (`safety_tune/safety.md` §3.2). Консервативная альтернатива — ближайшая глубина в блоке, как «closest radius» в `depthimage_to_laserscan` |
| Память опасностей очищается только видимым полом | адекватно для безопасности, есть [гипотеза] о цене | Клетка в 0,1–1,2 м перед роботом не очищается (пол виден с 1,2 м). Человек вошёл и вышел — клетки могут остаться «призраками». В наборах нет сценария «человек ушёл». Это надо измерить до правки (L2) |
| Память в одометрии без роста допуска | спорно | Ошибка клетки = шум глубины + дрейф одометрии с момента наблюдения (рыскание при повороте на месте с проскальзыванием). `depth_err_m` 0,04 — одна константа на всё. Классика: gyrodometry (Borenstein и Feng 1996) |
| Сумма запасов для клеток глубины (0,05 + 0,04 + 0,035) | адекватно | Сумма неопределённостей — так и в SSM (Z_d + Z_r). Уменьшать её надо устранением причин (M1, M2), не порогом |
| `turn_margin` 3 см, поворот на месте | адекватно | По замеру ухода центра 3 см |
| Задний ход ≤ 0,05 м/с, ≤ 0,2 м по следу | адекватно | E ≈ 0,005 Дж [расчёт]. Сзади датчиков нет |
| Тупики и отъезд назад | адекватно | Тупик — известное свойство фильтров безопасности: устойчивые «нежелательные равновесия» CBF-QP (Reis, Aguiar, Tabuada 2020/21). Лечится внешним манёвром — как у нас (5 тупиков за 2,7 ч, все вышли) |
| `tilt_max_deg` 10° | адекватно | Статическое опрокидывание вперёд — при ≈7 м/с² по оценке двойника (ЦМ 0,21 м, ролик 0,15 м), то есть ≈35°. Запас большой; пандус 12° — защёлка по замыслу |
| `shock_mps2` 6 на мачтовом `/camera/imu` | спорно | Свои остановки на двойнике — p95 3,72, max 4,14 (запас 1,45×). Однажды было 6,1. На роботе не мерено. Простой порог даёт ложные срабатывания на стыках пола. Помогает учёт команды: Becker и Ebner 2019 — ускорение против направления движения вместе с командами моторов, 13 из 14 ударов без ложных |
| Упор по одометрии | частично | Пробуксовка с вращающимися колёсами не ловится. Поворот ловится дёшево: гироскоп D435i против `w` одометрии (M4) |
| Защёлка: снятие только человеком, после снятия `unarmed` | адекватно | Принцип ISO 13850: снятие аварийного останова не перезапускает машину (вторичный источник, текст стандарта не читал). Но геймпад `/cmd_vel_joy` (приоритет 100 в twist_mux) обходит защёлку — у аварийного останова такого быть не должно (M3) |
| Стоп агента — ноль сразу (1а) | адекватно на двойнике, спорно на роботе | На двойнике L1 ограничивает торможение (−1,0 м/с²). В Foxy `has_acceleration_limits` по умолчанию `false` (twin README §2.4), лимиты на роботе не сняты. Тогда «ноль сразу» = ПИД тормозит как может. Предел — трение ≈ μg; опрокидывание по оценке ≈7 м/с². Это стоп категории 2 (IEC 60204-1: управляемый, питание остаётся). Управляемость даёт только L1 (H2) |
| Термин «аварийная защёлка» | спорно (текст) | По ISO 13850 и IEC 60204-1 аварийный останов — категория 0 или 1, аппаратная реализация. Программная защёлка L2 — защитный останов. Nav2 о своём аналоге прямо пишет: «does not provide hard real-time safety certifications». URG-04LX и D435i — не safety-rated датчики |

## 3. Рекомендации

Эффект — на метрику ВКР «работа во времени»: доля `blocked`, оборванные манёвры, вмешательства человека (K3), CPU и
задержка на Jetson. Токены LLM safety_gate не трогает.

### Высокий приоритет

**H1. Калибровка позы камеры и плоскости пола** — [нет]
- Что:
  1. На HIL записать облако пола в покое и на ходу (разгон и стоп 0,15 м/с), 5–10 мин.
  2. Гистограмма высоты точек пола по дальности.
  3. При старте (робот стоит на ровном полу) оценивать наклон, крен и высоту камеры МНК-плоскостью по точкам пола
     1,2–2,5 м. Принять, если поправка ≤ ±3° и ±3 см, иначе `stale_depth` с причиной.
  4. Вариант на ходу: поворачивать точки по ориентации `/imu/data` — это IMU самой камеры, оно видит наклон мачты.
- Почему: двойник этого не воспроизводит.
- Прецедент: `depth_sensor_pose` в `depth_nav_tools` (RANSAC высоты и наклона).
- Эффект: снимает самый вероятный на роботе отказ — ложные препятствия по всему полу или ложные обрывы, то есть
  `blocked` до 100 %. Заодно устраняет пропуск низких предметов при наклоне камеры вверх.
- Трудоёмкость: 0,5–1 дня кода; 15 мин записи у лаборатории.
- CPU [оценка]: МНК (одно SVD на ≤2000 точек) — доли мс на M4, единицы мс на A57; только на старте или раз в секунду.
  RANSAC на 50 итераций — 2,5 мс на M4 [замер], ≈25–50 мс на A57 [оценка], то есть только на старте.
- Применимость: numpy, Python 3.8, Foxy — да.

**H2. Тормоза и задержка — замер худшего случая; торможение при безопасном стопе** — [частично]
- Формула есть, числа — допущения; L1 двойника задан, у робота — нет.
- Что:
  1. HIL: по 5 остановок с 0,10 и 0,15 м/с на полу лаборатории. По двум скоростям разделить `t_lat` и `a_brake`.
     Брать худшее, не среднее — практика ISO 3691-4.
  2. Снять параметры `/diff_cont` (в `LAB_HANDOUT` пункт уже есть). Если `has_acceleration_limits` = false —
     предложить лаборатории `min_acceleration` (у нас уже готов `twin/config/controllers.yaml`).
  3. Если лаборатория откажет — в L2 безопасный стоп с ограниченным замедлением: = `a_brake` (на нём считается
     `d_stop`), а когда путь короче тормозного — сразу.
     Начало торможения остаётся в первом тике, поэтому K6 «торможение ≤ 100 мс» выполняется. Если читать K6
     буквально как «ноль ≤ 100 мс», это пересмотр решения 1а — решает студент.
- Эффект: правильный `d_stop` (касания). Нет удара по мачте и ложных `shock`, а значит меньше вмешательств человека
  (K3). Нет риска опрокидывания.
- Трудоёмкость: 1 ч HIL; 2–3 ч кода и теста.
- Применимость: Foxy — да; параметры `min_acceleration` в Foxy вместо `max_deceleration`.

**H3. Свежесть по штампу, бюджет задержки на Jetson, застывшие данные** — [нет]
- Что:
  1. Логировать возраст `/scan` и глубины: `now_ros − header.stamp`, p50/p95/max.
  2. Логировать длительность колбэков на Jetson.
  3. Если p99 возраста плюс обработка выходит за `t_lat` — поднять `t_lat` или вынести глубину в отдельный поток или
     процесс.
  4. Застывший вход — `stale_*` с причиной `frozen`: `stamp` не растёт, или N = 3 подряд побайтно одинаковых
     `ranges` (у URG шум, совпадение невозможно) или кадров глубины.
- Аналог: `diagnostic_updater::TimeStampStatus` (Foxy, C++) — проверяет задержку штампов.
- Закрывает: строку README «застывший скан не ловится».
- Трудоёмкость: 2–4 ч. CPU — хеш массива 683 float, микросекунды.
- Применимость: да.

### Средний приоритет

**M1. Консервативное прореживание глубины: ближайшее в блоке** — [нет]
- Что: вместо `image[rows, cols]` брать минимум ненулевой глубины в блоке stride×stride. От «летящих» пикселей —
  второй минимум или не меньше 2 годных в блоке.
- Прецедент: `depthimage_to_laserscan` берёт ближайший радиус по строкам.
- После правки повторить `chair_turn` и решить, можно ли уменьшить `depth_err_m`.
- Эффект: тонкие предметы не мерцают в памяти. Меньше ложной очистки клеток соседним полом. Потенциально −2…4 см
  запаса, то есть меньше `touch` и тупиков.
- Трудоёмкость: 2–4 ч плюс регрессия на двойнике.
- CPU [замер на M4]: 0,27 мс на кадр 424×240 (выборка — 0,002 мс); на A57 [оценка] 3–5 мс при 10 Гц ≈ 3–5 % ядра.
- Применимость: Python 3.8 и numpy 1.24 — да.

**M2. Рыскание для памяти по гироскопу и рост допуска клетки** — [нет]
- Что:
  - интегрировать ω_z гироскопа D435i (есть в `/camera/imu`, `unite_imu_method:=2`) вместо рыскания одометрии для
    переноса клеток — gyrodometry (Borenstein и Feng 1996);
  - хранить у клетки путь и поворот с момента наблюдения и прибавлять k·путь + дальность·σψ.
- Перед правкой замерить на HIL ошибку рыскания одометрии при повороте на месте (360° 3 раза).
- Эффект: ошибка зазора у предметов, видимых только глубиной, устойчива к проскальзыванию на реальном полу.
- Трудоёмкость: 0,5 дня.
- Применимость: да (robot_localization на Foxy тоже есть, но лишний процесс и CPU).

**M3. Защёлка перекрывает геймпад: lock twist_mux** — [нет]
- [код чужого] twist_mux foxy-devel: `LockTopicHandle` (`std_msgs/Bool`) маскирует входы с приоритетом ниже своего
  (`isMasked: priority < lock_priority`). Lock с `timeout` > 0 срабатывает и при молчании издателя.
- Что: safety_gate публикует `true` в lock с приоритетом 255 на время защёлки. Тогда геймпад (100) тоже не проходит.
- Оговорка: twist_mux сам ноль не шлёт, базу остановит `cmd_vel_timeout` 0,5 с.
- Нужно согласие лаборатории: это их yaml twist_mux. Цена — под защёлкой геймпадом робота не отвести, сначала
  `sudo neurobot estop release` (так и задумано у ISO 13850).
- Эффект: закрывает обход P4 приёмки 17.10 (0,20 м мимо L2).
- Трудоёмкость: 1–2 ч плюс процессный тест.
- Применимость: Foxy — да.

**M4. Пробуксовка поворота** — [нет]
- Что: команда поворота дошла, `w` одометрии ≥ порога, а |ω_z гироскопа| < 0,2·|w| дольше 1 с — `stall`.
- Основа: гироскоп проскальзыванию колёс не подвержен (идея yaw slip ratio — патент US 12157233).
- Линейная пробуксовка останется непокрытой — записать.
- Трудоёмкость: 1–2 ч.
- Применимость: да.

**M5. Профиль и пресет глубины под безопасность** — [частично]
- README рекомендует 424×240 при 15 к/с, но в `neurobot.env.example` профиль не задан.
- Что: на HIL сравнить 424×240@15 и 848×480@15 + decimation, по пресету Default и High Accuracy. Мерить:
  - шум высоты пола на 1,2–2,5 м;
  - покрытие `depth_min_valid` на полу лаборатории;
  - CPU десериализации.
- Intel: прореживать лучше, чем снижать разрешение; High Accuracy — для обхода препятствий, ценой заполнения.
- Эффект: меньше ложных клеток и ложных `stale_depth`.
- Трудоёмкость: 1 ч HIL.
- Применимость: параметры realsense-ros 4.x на Foxy [допущение о версии на роботе].

**M6. Метрики консервативности и доверительные границы в ВКР** — [частично]
- Что: к доле `blocked` добавить:
  - частоту вмешательств (доля тиков с `cut`, как intervention frequency у Gameplay Filters, Nguyen и др. 2024);
  - точность вмешательств по истине двойника: вмешательство ложное, если истинный путь вперёд > `d_stop(v_req)` +
    `margin` (как мой разбор в §6.5, но по пути вперёд, а не по зазору);
  - распределение зазора при стопе.
- «0 касаний» давать с n и верхней 95 %-границей ≈ 3/n (Hanley и Lippman-Hand 1983).
- Трудоёмкость: 2–3 ч в `neurobot/sim/suites/reasons.py` и `metrics.py`.

### Низкий приоритет

**L1. Порог удара с учётом команды** — [нет]
- Только после записи `/camera/imu` на роботе (`LAB_HANDOUT` п. 7б).
- Варианты:
  - остаток «измерено − ожидаемо по команде и одометрии»;
  - окно 0,5 с после своей резкой остановки с порогом выше.
- Источник: Becker и Ebner 2019.
- Эффект: меньше ложных `shock`, то есть меньше K3.

**L2. «Призраки» в памяти глубины** — [нет, гипотеза]
- Сначала сценарий двойника `person_leaves`: человек встал в 0,7 м и ушёл. Мерить время `blocked` до движения вперёд.
- Если подтвердится: снимать клетку, когда лучи свежего кадра проходят сквозь неё на высотах, где опасность была
  видна. Низ клетки останется «как до человека» — риск не новый.
- Аналог — очистка лучом в OctoMap (Hornung и др. 2013) и в costmap_2d.

**L3. Терминология в ПЗ** — [нет]
- Как назвать:
  - L2 — «защитный останов» (protective stop) с защёлкой, категория 2 по IEC 60204-1;
  - аварийный останов (ISO 13850) — только L0, кнопка-грибок с принудительным размыканием и механической
    фиксацией (IEC 60947-5-5) в цепи питания моторов, категория 0 или 1.
- Сюда же — STM32 с таймаутом связи (вопрос №1 лаборатории).
- Трудоёмкость: 0,5 ч.

**L4. Явный член неопределённости датчика в `d_stop`** — [частично]
- Как: `margin` = запас + Z_датчика (лидар 0,03 по паспорту; глубина — по замеру H1/M5).
- Поведение не меняется. Пороги станут объяснимыми по SSM.

## 4. Что сознательно НЕ советую

- **CBF-QP с изменением руления** (OGM-CBF, Raja и др. 2024; LiDAR-CBF, Keyumarsi и др. RA-L 2024):
  - манёвры жестов — чистые повороты и прямые, и изменение руления исказило бы смысл жеста;
  - при фильтре только по v QP сводится к нашей замкнутой формуле;
  - решатель на Python 3.8 и A57 — лишний CPU.
  Идея памяти невидимых препятствий из OGM-CBF у нас уже есть.
- **Nav2 Collision Monitor** — пакет с Humble, на Foxy его нет. NaN он не считает препятствием, то есть слабее
  нашего. Полезен только как референс параметров: `source_timeout`, `base_shift_correction`, `min_points`,
  дебаунс.
- **Обученные и HJ-фильтры** (Gameplay Filters, UNISafe) — GPU и модели мира. Для Nano и нашей задачи избыточны.
- **Детекция стекла по интенсивности** (TOPGN, arXiv 2408.05608) — нужна интенсивность. Выдаёт ли её
  URG-04LX-UG01 через urg_node2 — не проверял. Остаточный риск стекла уже записан как цена 2а.
- **Член S_h скорости человека из SSM** — человек, идущий на робота, обгоняет любой стоп при 0,15 м/с. Достижима
  только пассивная безопасность (Bouraine 2012): робот стоит в момент контакта. `person_steps_in` это проверяет.

## 5. Как писать результаты (адекватность заявлений)

- Касаний 0 за 2,7 ч прогонов (4 прогона) — верхняя 95 %-граница частоты ≈ 3/2,7 ≈ 1,1 касания в час (Пуассон,
  ноль событий). «0 в 11 сценариях регрессии» — до ≈27 % на сценарий. Так и писать: это ориентир стенда.
- `blocked` разделять на «по замыслу» (истинный зазор у порога, §6.5) и «ложный» (M6).
- Числа L2 на двойнике (0,3/0,7 мс до нуля) — x86 ВМ; на A57 перемерить (H3).

## 6. Расчёты

1. **Дуга против коридора.** Путь до остановки s = v·t_lat + v²/(2a): при 0,15 м/с — 0,052 м, при 0,25 — 0,102 м.
   Радиус ρ = v/w при w = 0,8: 0,1875 и 0,3125 м. Отход дуги s²/(2ρ): 0,007 и 0,017 м — меньше 0,05.
2. **Энергия удара (аналогия PFL).** m_робота 3,96 кг (twin README), m_голени 75 кг, μ = 3,76 кг.
   - E(0,15) = 0,042 Дж; E(0,25) = 0,118 Дж; E(0,05) = 0,005 Дж.
   - Предел голени F²/(2k) = 130²/(2·60 Н/мм) = 0,141 Дж (квазистатически). Для переходного контакта TS берёт
     бо́льшую силу: у Benzi и др. для груди — 1,6 Дж. Значит, оценка консервативна.
   - Значения ступни и пальцев не проверял.
3. **Наклон и высота камеры.** Ошибка высоты точки пола Δh ≈ d·δ.
   - δ = 0,5°: 1,0 см на 1,2 м; 2,2 см на 2,5 м.
   - δ = 1°: 2,1 и 4,4 см.
   - Камера наклонена вниз больше, чем в TF: пол «поднимается», и при d·δ > 0,02 всё становится препятствием.
     При 1° это с 1,15 м, то есть весь видимый пол.
   - Вверх: ложный обрыв при d·δ > 0,04 (с 2,3 м).
   - Ошибка высоты мачты: ниже TF на > 2 см — весь пол «препятствие»; выше на > 4 см — «обрыв».
4. **Шум глубины D435** (формула Intel: RMS = z²·s/(f·B); B = 50 мм, s = 0,08, HFOV 87°).
   - f = 223 px (424) и 447 px (848).
   - σz(2,5 м) = 4,5 / 2,2 см; σz(1,5 м) = 1,6 / 0,8 см.
   - Высота пола σh ≈ σz·0,66/z: 1,2 см (424, 2,5 м); 0,7 см (424, 1,5 м); 0,6 см (848, 2,5 м).
5. **Почему остаток `obstacle` — по замыслу.**
   - Запас от клетки глубины: угол клетки 0,035 + `depth_err_m` 0,04 = 0,075 м.
   - Блок при `d_stop(0,03)` = 0,058 м, то есть центр клетки ≲ 0,13 м.
   - Снятие при 0,108 м, то есть центр ≳ 0,18 м.
   - `long_v5`: `obstacle` 455 с, из них 449 с при истинном зазоре 0,10–0,20 м и 5,5 с при ≤ 0,10 м.
     `budget_v5b`: 21,7 с, все при ≤ 0,20 м.
   - Метод: `safety.jsonl` против `truth.jsonl`, ближайший по `m`. Зазор истины — в любую сторону, не путь вперёд,
     поэтому это нижняя оценка «правильности».
6. **Удар своей остановкой.** p95 3,72, max 4,14 м/с² против порога 6 — запас 1,45×.
