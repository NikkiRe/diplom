## 1. Этап «Windows» [следующее, если работа идёт на Windows]

Цель — тот же стенд на Windows через WSL2 (Ubuntu 24.04, systemd), без потери проверок.

1. Окружение по `docs/WINDOWS.md`:
   - WSL2 + Ubuntu 24.04 с systemd;
   - Go 1.27, uv + Python 3.12, ROS 2 Jazzy, Gazebo Harmonic, нужные пакеты ros-jazzy-*.
2. Слой запуска «ВМ». Сейчас около 35 скриптов зовут `limactl shell sbc|sim -- …`. Ввести одну точку, например `scripts/vmexec`:
   - бэкенд `lima` (Mac) оставить без изменений;
   - бэкенд `native` — для WSL: команда выполняется прямо в текущем Linux.
   Скрипты переводить на неё по одному, с тестом.
3. Архитектура: на Windows-ПК стенд x86_64, поэтому бинарники стенда — `linux/amd64`. Для Jetson остаются `linux/arm64`. Суффиксы `-linux-arm64` в скриптах заменить на `$(go env GOARCH)` или параметр.
4. Возможности ядра WSL:
   - проверить cgroup v2 (memory, cpu, io), `tc netem`, `ifb`, `gpio-sim`;
   - чего нет — честно отключать соответствующие проверки, а не подделывать;
   - при необходимости — своё ядро WSL (инструкция Microsoft).
5. **Готово, когда:**
   - зелёные `go test ./...` во всех модулях и pytest;
   - `bench.sensors` проходит;
   - двойник поднимается (`neurobot/sim/twin/twin.sh up`) и проходит `check.sh`;
   - различия Mac и Windows записаны в `docs/WINDOWS.md`.

`experiments/results/neurobot_20261018_acceptfix2/compare.md` (столбцы A0, A1 16.10, A1 18.10, A1 итог; локально, в
репозиторий не входит), статус по критериям K1–K9 — `docs/neurobot/PLAN.md` §13.5. Ход: прогоны 16.10 → приёмка
17.10 (принято частично) → доработки 18.10 → повторная приёмка 18.10 → доводка 19.10 (независимо не перепринята).

1. **Бюджет 4 ГБ** (`neurobot/sim/budget`, `neurobot/sim/runs`) — по памяти сделано: весь A1 в cgroup «jetson»
   (MemoryMax 2406 МиБ, ветка GNOME) — OOM 0, уникальная память 1866,6 МиБ, запас GNOME 539 МиБ. По CPU — открыто:
   вывод о квоте CPU не воспроизводится, калибровка зависит от нагрузки ВМ; её не исправляли, числа по CPU помечены
   ненадёжными до замера `cpubench` на Nano. Наклон памяти за 8 ч не измерен.
2. **A0 против A1** — сделано, одно расписание жестов и отказов, по 34 мин; у A1 ещё отказы драйверов (kill -9 узлов
   лидара, камеры и базы; SIGSTOP 30 с узлов лидара и камеры). Итоговый A1 снят в комнате `lab` 5 × 5 м, A0 — в зале
   9 × 9 м, поэтому сравнение — ориентир:
   - K1 p50 / p95 без ранних жестов: A0 1,81 / 2,11 с, A1 0,67 / 0,95 с; 0 вызовов LLM на жест у обоих;
   - касания: A0 — 23, A1 — 0 во всех трёх итоговых прогонах; «едет без свежей команды»: A0 — 5, A1 — 0;
   - верная реакция на жест: A0 28 из 80, A1 38 из 80 (в основном ошибки класса SNN);
   - вмешательства человека: A0 — 8, A1 — 2, оба после смерти базы двойника (мир заново, защёлка от удара IMU).
3. **start_test** — сделано: 101 из 101 холодного старта, «ОК» doctor не позже 20,55 с при T = 26 с; doctor назвал
   поломку в 5 из 5 сломанных сценариев.
4. **Прогон в бюджете 4 ГБ** — сделано по памяти (п. 1).
5. **1 час непрерывной работы** — сделано (сокращено с 2 ч решением студента 16.10): касаний 0, 31 отказ — компоненты
   поднялись сами; видимых перезапусков 3 — смерти базы двойника.
6. **Независимая приёмка** — две: 17.10 (принято частично) и 18.10 (пять новых замечаний, исправлены 19.10; доводку

   safety_gate на ходу, NaN-скан, лишний геймпад, снятие защёлки, смерть драйвера внутри `ros2 launch`, тупик у стула.
   По их замечаниям сделаны: плавная штатная остановка, поправка глубины у тонких ножек, `nodata_unseen=slow`,
   `lidar_fault`, отъезд из тупика, защёлка только через root, перезапуск юнитов `ros2 launch` (обёртка и сторож),
   честный ответ агента (`blocked`/`estop`/`unconfirmed`), пересобранная сводка.
